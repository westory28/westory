# 역사사전 요청 출처와 보상 출처 분리

직접 등록한 A에 보상을 지급한 뒤 교사가 이름을 B로 바꾸고 학생이 B를 요청하면, 요청의 원래 단어는 B이고 보상의 원래 단어는 A입니다. PATCH14는 두 출처를 한 필드로 증명할 수 없어 추가 이름 변경을 막았습니다. 이번 변경은 서버가 `requestOriginTermId`를 별도로 보존하여 B를 C로 바꾼 뒤에도 요청 B와 보상 A를 각각 확인하도록 합니다.

## 저장과 검증 계약

- 학생 요청은 현재 요청의 canonical 단어 ID를 출처로 저장합니다. 호출자가 보낸 출처는 사용하지 않습니다.
- 공식 풀이 저장과 직접 등록은 요청 연결을 해제하므로 `requestId`와 `requestOriginTermId`를 함께 빈 값으로 저장합니다. 기존 보상 처리 정책은 유지합니다.
- 교사 저장·승인은 실제로 연결을 검증한 요청의 단어 ID를 저장합니다. 허용된 legacy ID도 실제 요청 참조에 따라 보존합니다. 기존·누락 요청 fallback의 명시 출처가 모순되면 전역 단어 쓰기 전에 거절합니다.
- 교사 수정은 원본 단어와 실제 요청의 학생·학기·상태·단어 연결을 transaction 안에서 검증하고 확인한 요청 출처를 보존합니다. 이름 변경 뒤에는 교사 검토자와 시각, 명시된 요청 ID도 필요합니다. 보상 출처는 별도로 유지합니다.
- 교사 삭제는 요청 출처로 원래 요청을 확인하고 기존 보상 출처로 회수 원장을 검사합니다. 모순된 명시 요청 출처를 보상 출처로 대체하지 않습니다.
- 진행 중인 요청에 다른 단어를 가리키는 승인 참조가 있으면 재요청을 쓰기 전에 거절합니다. 반려 등 종료된 요청을 다시 열 때는 현재 단어 기준으로 승인 참조를 초기화하고 저장된 새 상태를 반환합니다. 이미 해결된 요청은 기존처럼 쓰기 없이 반환합니다.

## 기존 자료

출처 필드가 없거나 빈 문자열인 자료는 기존의 현재 단어 연결 또는 검증된 교사 수정 기록과 보상 ID를 통한 연결을 사용합니다. 수정에 성공하면 검증된 요청 출처가 저장됩니다. 요청과 보상 출처가 이미 갈라졌지만 연결을 증명할 수 없는 legacy 자료는 자동 추정하지 않습니다.

명시 출처의 타입·경로·길이 또는 실제 요청 연결이 잘못되면 거절합니다. 요청이 없는 직접 저장 자료의 유효한 잔여 출처는 요청 권한으로 쓰지 않으며 다음 교사 수정에서 비웁니다. UID·학기·보상 증거가 없는 legacy 자료에 호출자의 학기를 새 출처로 부여하지 않는 기존 보호도 유지합니다. 학생의 직접 Firestore 단어 쓰기는 기존 Rules로 차단되어 있습니다.

## 검증과 배포 범위

기존 서버에서 정상 흐름의 추가 이름 변경 차단을 실제 Auth/Functions/Firestore 에뮬레이터로 먼저 재현합니다. 순수 helper 검사와 실제 callable 검사는 모든 변경 writer의 설정·해제·승인·재요청, 반복 수정·삭제, 보상 지급·회수, legacy와 위조 출처, 거절 시 업무 데이터 무변경을 확인합니다.

전용 Staging 배포 순서는 삭제 reader → 요청·공식 저장·직접 저장·교사 저장·승인 writer 다섯 개 → 교사 수정입니다. 같은 검증된 소스로 일곱 함수를 반영합니다. 프런트·Rules·의존성과 Hosting은 변경하지 않습니다. 실제 실행 결과, 소스 hash, 배포 ACTIVE 및 합성 계정 HTTPS 검증 기록은 외부 PATCH15 인수인계와 receipt에 남깁니다.

Staging HTTPS는 실제 Auth SDK·AppCheck·세션을 거쳐 교사 수정·삭제를 검사합니다. 새 요청 함수는 실제 관리자 전체에게 알림을 보내므로 합성 계정 live 호출에 포함하지 않습니다. 나머지 writer 연쇄 및 실제 보상 원장 지급·회수는 에뮬레이터 근거입니다. 합성 자료 seed가 과거 writer의 실제 실행을 증명하지 않습니다.

## 후속 작업

이번 패치는 요청 출처를 분리합니다. 원래 보상의 지급 학기·원장 ID를 모든 writer에서 별도로 보존하는 migration은 남아 있습니다. 현재 단어의 학기나 `rewardTransactionId` 하나로 과거 지급 학기를 증명하지 않습니다. 기존 삭제 회수는 여전히 현재 호출 학기를 사용합니다.

서버 revision/CAS·Gateway 결과 복구, 전역 단어와 요청 fanout의 분리 transaction, 알림 전달 복구, 실제 Google 계정의 전체 앱 수용과 운영 전환은 별도입니다.
