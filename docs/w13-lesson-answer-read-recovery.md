# 학생 답안 초기 조회 실패 복구

첫 답안 조회가 실패하면 저장 기준 revision이 null로 남아 화면을 다시 열어야 했습니다. 이제 입력을 유지한 채 `저장된 답안 다시 확인`으로 서버 조회를 재시도할 수 있습니다.

- 초기 조회와 수동 재시도는 `getDocFromServer`를 사용합니다. 실패하거나 유효하지 않은 revision을 받으면 저장을 열지 않습니다. 서버에서 확인한 기존 문서의 revision 누락 또는 새 문서는 기존 규약대로 0을 사용합니다.
- loading/error/ready 표시와 재시도는 답안 문맥과 분리합니다. 재시도 횟수는 답안 초기화 조건에 포함하지 않습니다.
- 동기 요청 잠금으로 중복 클릭을 막고, 취소된 effect와 바뀐 계정·학기·단원 세션의 늦은 응답은 버립니다.
- 본문·PDF 빈칸에서 수정한 값과 재시도 중 새로 찾은 핵심포인트를 유지합니다. 읽기만 다시 수행하며 답안 저장이나 보상 명령을 대신 실행하지 않습니다.
- 빈칸·본문·핵심포인트가 없는 수업에는 답안 조회 중이라는 표시를 남기지 않습니다.
- 기존 같은 문맥 수업 재조회는 `getDoc` 복원 경로를 유지합니다. 이미 사용 중인 revision을 수동 재시도로 다시 읽는 기능은 추가하지 않습니다.

## 검증

`scripts/verify-lesson-core-point-recovery.mjs`는 실제 LessonContent와 학습지 컴포넌트를 묶고 Firebase와 저장 I/O만 제어합니다. localhost 외의 요청은 차단합니다.

기존 핵심포인트·보상 100개에 다음 답안 검증을 추가했습니다.

- 320/390/768/1280/1440px에서 초기·반복 실패, 키보드 재시도, 한 이벤트 내 중복 클릭, 재시도 중 본문·PDF 입력 보존
- 수정하지 않은 답안 복원, 새 핵심포인트 보존, 복구된 revision과 답안 전체 저장 payload
- 잘못된 revision 거절, 0 revision 복구, 계정·단원 변경과 로그아웃 후 늦은 성공·실패 무시
- 실제 수업 조회 분기에서 초기 오류 복구와 config 객체 재조회 후 기존 답안 복원
- 저장하지 않는 미리보기와 답안이 없는 PDF 수업

이 검증은 실제 Google 로그인, SDK 초기화 전체 또는 Staging 학생의 서버 저장 검증을 대체하지 않습니다. 배포 결과와 실행 횟수는 별도 작업 기록에 남깁니다.

## 남은 범위

결과를 확인하지 못한 저장 A 뒤에 새 답안 B를 입력했을 때, A의 명령 ID와 payload를 유지하면서 결과를 먼저 복구하는 작업은 남아 있습니다. 서버 CAS를 완화해서 해결하지 않습니다.

같은 문맥에서 수업 메타데이터가 다시 조회될 때 기존 코드가 초안을 초기화하는 문제도 별도 작업이 필요합니다. 이번 변경은 해당 기존 경로를 확대하지 않으며, 그 문제까지 해결했다고 보고하지 않습니다. Functions, Rules, 공용 저장 Gateway, 의존성은 변경하지 않습니다.
