## 구현 전 검토

1. 답안 복구 실패는 앱 저장 결함이 아닌 검사 환경 결함이다. 앱 저장 로직을 바꾸지 않고 실제 모듈을 검사에 연결한다.
2. 생각모아는 현재 서버의 학기·권한 경계를 유지한다. 공통 캐시를 무효화하거나 조회마다 임의 값을 넣지 않는다. 조회 종료 후 다음 작업을 예약하고 기존 쓰기 요청 식별·재시도 흐름을 유지한다.
3. 알림 전체 확인은 삭제 기능으로 바꾸지 않는다. 확인 상태가 바뀌어도 공지가 남는 현재 동작과 문구를 일치시킨다.
4. 성적 자료를 이동·변환하지 않는다. 두 기존 화면의 탐색만 보완한다.
5. 백업 설정은 메타데이터 변경이다. 사전 설정과 API 계약을 확인한 뒤 적용하고 결과를 다시 조회한다. PITR는 활성화 이후 이력이 쌓이며 과거 전체 기간이 즉시 복구 가능해지는 것은 아니다.
6. 배포 기준을 정리하기 위해 오래된 main을 강제로 합치거나 작업 폴더의 dist를 바로 배포하지 않는다. 검증된 커밋에서 만든 후보를 확인하고 실제 운영 파일과 대조한다.

- 각 변경의 회귀 검사 → 코드 독립 검토 → TypeScript/format/build → 필요한 실제 브라우저 확인 순서로 진행한다.
- 화면 변경은 390·768·1280px 폭에서 확인한다.
