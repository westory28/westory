# 수행평가 점수 확인 서명 정책

학생은 현재 등록된 점수를 확인하고 서명한다. 이후 평가가 등록되거나 기존 점수가 바뀌면 해당 점수를 다시 확인하고 서명한다. 기존에 유효하게 확인한 평가의 서명은 보존한다.

## 학적 변동과 수행평가 일람표

교사는 **학생 명단 → 학적 상태 변경**에서 전출 또는 정원외 학적관리를 선택하고 실제 변동일을 입력한다. 서버는 해당 학기의 수행평가 기준일(`years/{year}/semesters/{semester}/assessment_config/enrollment_movement.startDate`)이 있으면 이를 사용하고, 없으면 학기 원장의 시작일을 사용한다. 2026학년도 2학기의 수행평가 기준일은 교사가 확인한 **2026-08-14**다. 이 기준일은 접속·출결 등 다른 기능의 학기 기간을 변경하지 않는다.

| 변동 시점 | 수행평가 응시자 명단과 일람표 | 성적 집계와 서명 |
| --- | --- | --- |
| 학기 시작 전 | 학생 행을 표시하지 않음 | 인원·평균·서명 대상에서 제외 |
| 시작일 당일 또는 학기 중 | 학생 행과 실제 응시한 평가의 점수를 유지. 미응시 평가에만 `전출` 또는 `정원외` 표시. 합계는 실제 점수의 합, 비고는 공란 | 응시한 평가의 인원·총점·평균에 포함. 전체 평균의 분자·분모와 서명 대상에서는 제외 |

학적 표시는 점수나 서명 이미지에 덮어쓰지 않는다. 전출·정원외 학생을 포함하여 실제 응시한 0점은 집계하고 미응시와 구분한다. 평가별 평균은 해당 평가의 실제 점수가 있는 인원으로 나눈다. **전체 평균에서는 전출·정원외 학생의 점수와 인원을 모두 제외**한다. 전체 총점은 실제 응시한 모든 점수의 합이므로 전체 평균의 분자와 다를 수 있다. 예를 들어 첫 평가 뒤 전출한 학생은 1차 32명·2차 31명의 서로 다른 집계에 반영하되, 전체 평균은 해당 학생을 제외한 31명으로 계산한다. 이는 사용자 최종 정정 지시(2026-11-09)다. 보관 학기에는 그 학기의 점수표에 남긴 분류와 실제 점수를 사용한다. 날짜 경계는 `scripts/verify-student-roster-browser.mjs`, 재조회·서명 제외·실제 내려받은 XLSX의 인원과 평균은 `scripts/verify-score-workflow-browser.mjs`로 확인한다.

2026학년도 2학기 일회성 보정은 `functions/scripts/backfill-performance-movement-2026-2.cjs --input <비공개 JSON 경로>`로 미리 확인한다. 입력은 저장소 밖에 보관한다. 적용하려면 동일한 명령에 `--apply --expect <미리 확인한 fingerprint>`를 붙인다. 적용 직전 활성 학기와 대상 문서 버전을 다시 검사하며, 이미 반영된 자료는 다시 쓰지 않는다. 출력한 로컬 백업 경로는 복구용으로 보관하고 Git에 추가하지 않는다.

## 확인 대상과 완료 기준

- 같은 학생·학기의 해당 수행평가를 대상으로 판단한다. 학생 화면은 현재 표시하는 수행평가 전체, 교사 일람표는 선택하여 출력하는 평가를 대상으로 한다.
- `enteredScoreCount: 0`인 미등록 평가는 서명 대상과 완료 분모에서 제외한다. 실제로 입력한 0점은 등록된 점수이므로 서명이 필요하다. 과거 문서의 입력 여부는 `hasEnteredPerformanceScore`의 기존 형식 호환 기준을 따른다.
- 학생은 수행평가 점수 화면에 들어올 때마다 점수가 등록된 모든 평가의 상세 탭을 직접 열어야 새 서명을 시작할 수 있다. 이미 서명한 평가도 함께 확인하되 유효한 서명은 보존한다. `i`로 평가명을 읽는 동작은 상세 확인에 포함하지 않는다. 확인 여부는 해당 학생·학기·화면의 메모리에만 두며, 변경된 점수 버전에는 이전 확인을 적용하지 않는다.
- 수행평가 서명 제출 직전에 등록된 평가 목록과 각 점수 버전을 서버에서 다시 비교한다. 추가·변경·미등록 전환이 확인되면 제출을 중단하고 최신 상세를 표시한다. 저장 대상은 기존 confirmation 문서이며 Firestore가 각 문서의 소유자·점수 버전·서명 조건을 검사한다.
- 현재 등록된 대상 평가마다 유효한 서명 이미지와 이름이 모두 있어야 최종 완료다. 대상 평가가 하나도 없으면 완료로 처리하지 않는다.
- 완료 여부는 조회 시점 기준이며, 서명 저장 뒤 전체 점수와 서명을 서버에서 다시 조회한다. 후속 조회가 실패하면 완료 표시를 막고 서버 재조회를 통해 다시 확인한다.
- 새 평가가 등록되었으나 아직 서명하지 않았다면 이전 서명만으로 최종 완료 처리하거나 일람표 비고란에 최종 서명을 출력하지 않는다.
- 점수 변경으로 서명 버전이 맞지 않거나 교사가 서명을 반려한 경우 해당 평가를 다시 서명해야 한다. 다른 평가의 유효 서명을 임의로 삭제하거나 덮어쓰지 않는다.

## 최종 서명 선택

모든 대상 평가의 유효 서명을 확인한 뒤 가장 최근에 제출한 서명 하나를 최종 서명으로 사용한다. 평가 차수, 목록 순서, 업로드 순서로 선택하지 않는다.

| 상태 | 최종 완료 | 일람표 비고란 |
| --- | --- | --- |
| 1차 서명 완료, 2차 점수 미등록 | 완료 | 1차 서명 |
| 1차 서명 완료, 2차 점수 등록·미서명 | 미완료 | 서명 없음 |
| 1차 서명 후 2차 서명 완료 | 완료 | 더 최근인 2차 서명 |
| 2차 서명 후 1차 점수 수정 | 미완료 | 서명 없음 |
| 수정된 1차 점수를 다시 서명하고 두 평가 모두 유효 | 완료 | 더 최근인 1차 서명 |
| 어느 한 평가의 서명을 반려 | 미완료 | 서명 없음 |

제출 시각은 유효한 confirmation의 `confirmedAt`을 우선하고, 해당 값이 없으면 기존 `signedAt`을 사용한다. Firestore의 초와 나노초를 모두 비교한다. 과거 자료의 제출 시각이 없으면 알려진 시각보다 앞선 것으로 취급한다. 시각이 정확히 같으면 평가 ID 문자열 순서로 결정하여 입력 배열 순서에 따라 결과가 바뀌지 않게 한다. 같은 일괄 제출로 저장된 서명은 시각과 이미지가 같다.

## 구현과 검증 경계

- 평가별 서명은 기존 `users/{uid}/performance_scores/{scoreId}/confirmations/{uid}`에 저장한다. 별도의 최종 서명 문서를 만들거나 과거 서명을 전역 덮어쓰지 않는다.
- `applyPerformanceScoreConfirmation`으로 학생 UID, 평가 ID, 현재 점수 버전을 확인한다. `getLatestPerformanceScoreSignatureRecord`는 등록된 평가 전체의 서명이 유효한지 확인한 뒤 최근 서명을 선택한다.
- 교사 일람표의 필수 평가 자료가 누락되거나 서명 조회가 실패하면 기존 차단 동작을 유지한다. 점수 또는 서명 조회 실패를 미등록 상태로 간주하지 않는다.
- Firestore 배포 전 `npm run test:score-request-rules`는 점검 예외 계정이 20개인 설정에서도 학생 본인의 유효한 서명이 저장되는지 검사한다. 점검 중 일반 학생, 타인 서명, 잘못된 점수 버전은 계속 차단해야 한다.
- 검증에는 1차만 완료, 2차 추가 후 미완료, 2차 서명 완료, 1차 수정·재서명, 반려, 버전 불일치, 실제 0점, 미등록 제외, 제출 시각 역전·동률을 포함한다. 최종 XLSX의 서명 이미지와 기존 `hair` 테두리도 함께 확인한다.
