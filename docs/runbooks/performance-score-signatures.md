# 수행평가 점수 확인 서명 정책

학생은 현재 등록된 점수를 확인하고 서명한다. 이후 평가가 등록되거나 기존 점수가 바뀌면 해당 점수를 다시 확인하고 서명한다. 기존에 유효하게 확인한 평가의 서명은 보존한다.

## 확인 대상과 완료 기준

- 같은 학생·학기의 해당 수행평가를 대상으로 판단한다. 학생 화면은 현재 표시하는 수행평가 전체, 교사 일람표는 선택하여 출력하는 평가를 대상으로 한다.
- `enteredScoreCount: 0`인 미등록 평가는 서명 대상과 완료 분모에서 제외한다. 실제로 입력한 0점은 등록된 점수이므로 서명이 필요하다. 과거 문서의 입력 여부는 `hasEnteredPerformanceScore`의 기존 형식 호환 기준을 따른다.
- 현재 등록된 대상 평가마다 유효한 서명 이미지와 이름이 모두 있어야 최종 완료다. 대상 평가가 하나도 없으면 완료로 처리하지 않는다.
- 완료 여부는 조회 시점 기준이며, 서명 저장 뒤 전체 점수와 서명을 서버에서 다시 조회한다. 후속 조회가 실패하면 완료 표시를 막고 서버 재조회를 통해 다시 확인한다.
- 새 평가가 등록되었으나 아직 서명하지 않았다면 이전 서명만으로 최종 완료 처리하거나 일람표 비고란에 최종 서명을 출력하지 않는다.
- 점수 변경으로 서명 버전이 맞지 않거나 교사가 서명을 반려한 경우 해당 평가를 다시 서명해야 한다. 다른 평가의 유효 서명을 임의로 삭제하거나 덮어쓰지 않는다.

## 최종 서명 선택

모든 대상 평가의 유효 서명을 확인한 뒤 가장 최근에 제출한 서명 하나를 최종 서명으로 사용한다. 평가 차수, 목록 순서, 업로드 순서로 선택하지 않는다.

| 상태 | 최종 완료 | 일람표 비고란 |
| --- | --- | --- |
| 1차 서명 완료, 2차 점수 미등록 | 완료 | 1차 서명 |
| 1차 서명 완료, 2차 점수 등록·미서명 | 미완료 | 서명 없음 |
| 1차 서명 후 2차 서명 완료 | 완료 | 더 최근인 2차 서명 |
| 2차 서명 후 1차 점수 수정 | 미완료 | 서명 없음 |
| 수정된 1차 점수를 다시 서명하고 두 평가 모두 유효 | 완료 | 더 최근인 1차 서명 |
| 어느 한 평가의 서명을 반려 | 미완료 | 서명 없음 |

제출 시각은 유효한 confirmation의 `confirmedAt`을 우선하고, 해당 값이 없으면 기존 `signedAt`을 사용한다. Firestore의 초와 나노초를 모두 비교한다. 과거 자료의 제출 시각이 없으면 알려진 시각보다 앞선 것으로 취급한다. 시각이 정확히 같으면 평가 ID 문자열 순서로 결정하여 입력 배열 순서에 따라 결과가 바뀌지 않게 한다. 같은 일괄 제출로 저장된 서명은 시각과 이미지가 같다.

## 구현과 검증 경계

- 평가별 서명은 기존 `users/{uid}/performance_scores/{scoreId}/confirmations/{uid}`에 저장한다. 별도의 최종 서명 문서를 만들거나 과거 서명을 전역 덮어쓰지 않는다.
- `applyPerformanceScoreConfirmation`으로 학생 UID, 평가 ID, 현재 점수 버전을 확인한다. `getLatestPerformanceScoreSignatureRecord`는 등록된 평가 전체의 서명이 유효한지 확인한 뒤 최근 서명을 선택한다.
- 교사 일람표의 필수 평가 자료가 누락되거나 서명 조회가 실패하면 기존 차단 동작을 유지한다. 점수 또는 서명 조회 실패를 미등록 상태로 간주하지 않는다.
- 검증에는 1차만 완료, 2차 추가 후 미완료, 2차 서명 완료, 1차 수정·재서명, 반려, 버전 불일치, 실제 0점, 미등록 제외, 제출 시각 역전·동률을 포함한다. 최종 XLSX의 서명 이미지와 기존 `hair` 테두리도 함께 확인한다.
