# 답안 저장 결과 재확인과 새 입력 보존

저장 요청 A의 응답을 받지 못한 뒤 학생이 B를 입력하면, 종전에는 최신 입력과 학기 포인터로 새 요청을 만들어 A의 결과를 확인할 수 없었습니다. 서버에서 A가 이미 저장되었다면 불필요한 답안 충돌이 생길 수 있었습니다.

## 변경 동작

- 답안 세션은 첫 요청의 사용자, 학기, 단원, 자료·답안 revision, 답안 사본을 별도 작업으로 보관합니다. 처음 서버에서 확인한 활성 학기 revision도 작업에 고정합니다.
- 결과를 알 수 없는 요청은 `저장 결과 다시 확인`으로 재시도합니다. Gateway의 원래 payload key와 command ID를 유지하므로 기존 receipt를 재생할 수 있습니다. 재시도 때문에 새 답안을 전송하거나 활성 학기 revision을 바꾸지 않습니다.
- A가 성공하면 A의 answerRevision을 채택합니다. 그동안 B를 입력했다면 본문·PDF 값과 미저장 표시를 유지하고 A의 판정 효과를 B에 적용하지 않습니다. 다음 저장에서 B와 확인된 revision을 보냅니다.
- 다른 화면의 저장으로 서버가 `LESSON_ANSWER_CONFLICT`를 확정하면 현재 초안을 유지하고 추가 저장을 잠급니다. 학생이 작성한 값만 TXT로 내려받은 뒤 자료를 다시 열도록 안내합니다. 자료 메타데이터 재조회로 이 충돌을 해제하거나 새 답안 revision을 자동 채택하지 않습니다.
- 교사 메모를 포함한 공용 Gateway의 실행·결과 조회는 캡처한 사용자 UID를 callable factory까지 전달합니다. 비동기 준비나 응답 대기 중 계정이 바뀌면 다른 계정으로 명령을 보내거나 이전 결과를 적용하지 않습니다. 기존 미확정 handle은 원래 사용자 범위에 남습니다.

## 확정 실패의 경계

서버 transaction은 사용자·명령 종류·ID에 해당하는 receipt를 먼저 확인합니다. 같은 명령에 receipt가 있으면 답안 CAS 전에 재생합니다. receipt가 없는 경우에만 기존 answerRevision을 검사하며, 성공한 답안 쓰기와 receipt 저장은 같은 transaction에서 처리합니다. 따라서 saveLessonAnswers의 정확한 `LESSON_ANSWER_CONFLICT`만 확정 실패로 추가합니다.

세션·권한 거절은 receipt 조회 전에 일어날 수 있으므로 이전 요청이 실패했다는 증거가 아닙니다. 기존 미확정 ID를 계속 유지합니다. 자료 충돌, 빈칸 정의 변경, 상태 조회의 NOT_FOUND도 이번 확정 실패 분류에 추가하지 않습니다.

## 검증과 한계

실제 helper·Gateway·callable factory를 제어된 I/O와 함께 실행하는 검증과, 실제 LessonContent·WorksheetStage의 격리 브라우저 검증을 구분합니다. UI에서는 A 전송 중 B 입력, 응답 유실, 동일 자료 재조회, A 재확인, B 저장 revision, 충돌 잠금·다운로드를 확인합니다. 기존 초기 답안 복원·자료 재조회·핵심포인트·보상 검사도 유지합니다.

명시적 실행 함수로 버튼부터 Gateway까지의 호출 경로를 정적 검사합니다. 기존 허용 목록에서 답안 실행 함수의 위치와 공용 Gateway의 호출 그래프 해시 두 항목만 갱신합니다. 전체 136개 경계, 답안 저장의 USER_EVENT 조건, 금지·미분류 호출 검사는 유지합니다.

작업 객체는 현재 답안 세션의 메모리에 있습니다. 새 plaintext 답안 저장소는 만들지 않습니다. 새로고침·단원 이동·브라우저 종료 이후 초안 복구까지 지원한다는 뜻은 아닙니다. 실제 Google 로그인과 최신 Staging의 학생 저장·보상 수용은 별도 검증이 필요합니다. 실행 건수와 정확한 배포 소스는 외부 작업 기록에 남깁니다.

추가 조사에서 기존 worksheetScreenOpen을 true로 바꾸는 진입 동작이 없어 중첩 전체 화면은 현재 도달할 수 없는 코드임을 확인했습니다. 이전 기록의 전체 화면 초안 문제는 실제 활성 경로로 재현된 결함이 아니므로 신규 화면을 만들거나 해당 경로를 이번에 재설계하지 않습니다. 교사의 학생 미리보기와 기존 빈칸·각주·링크·핵심포인트 효과는 유지합니다.

Functions, Rules, 의존성과 Production은 변경하지 않습니다.
