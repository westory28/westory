# 위스 주식 교사 준비 기능 (2026-11-14)

## 범위와 접근

- 역사 종목의 이름·시대/주제·배경·기준가·가격 상하한·변동폭·기본 변화율·변동 간격을 등록하고 수정한다. 기준가는 등록 후 고정한다. 종목 삭제와 학생 매매는 이번 범위에 포함하지 않는다.
- 모든 서버 응답과 저장 문서의 `studentOpen`은 `false`다. 입력으로 공개 필드를 보낼 수 없으며 학생 매매 API, 학생 메뉴, 학생용 읽기 경로는 만들지 않는다.
- 서버는 기존 애플리케이션 세션을 검증하고, 현재 사용자 문서에서 위스 읽기/관리 권한을 다시 검사한다. 기존 `isAdminUser` 계약에 맞춰 `teacher` 역할은 별도 포털 플래그나 staff 권한 없이 읽기·관리를 허용하고, staff는 기존 위스 읽기/관리 권한을 구분한다. `student` 역할은 교사 포털 플래그와 `point_manage` 권한이 있더라도 거부한다. 기존 지정 관리자 예외는 유지한다. 비활성·삭제 계정은 역할과 무관하게 거부하며 저장은 기존 high-risk·recent-auth 검사를 적용한다.
- 현재 학기 설정, 활성 학기 포인터, `ACTIVE` manifest를 같은 transaction에서 확인한다. 다른 학기·종료 학기에는 쓰지 않는다. 신규 자료는 `years/{year}/semesters/{semester}` 아래에만 저장하며 레거시 주식 자료 fallback은 없다.
- 외부 AI 호출·외부 시세 서비스·학생 개인정보 전송·학생 공개 확대는 없다. 가격 변동은 내부 모의 시장의 서버 계산이며 실제 금융 시세를 나타내지 않는다. 보안성 검토 승인·면제를 새로 판단한 기록은 아니다.

## 저장과 자동 가격

- 시장: `years/{year}/semesters/{semester}/wis_stock_markets/current` 한 문서. 학기당 최대 40종목은 등록 시 강제하는 운영 상한이며, 목록을 잘라 보여 주는 조회 limit가 아니다. 각 종목은 최근 가격 변화 120건을 보관한다.
- 영수증: 같은 학기 `wis_stock_receipts/{sha256(uid + requestId)}`. 요청 hash, 수행자, 대상 종목, 이전/새 설정, 반영 revision, 처리 시각을 저장한다. 가격 이력 전체를 영수증에 복제하지 않는다.
- 저장의 expected revision을 비교하고, 시장 변경과 영수증을 원자적으로 저장한다. 같은 요청 ID의 재시도는 현재 시장 상태와 기존 대상 ID를 반환하며 이중 등록하지 않는다. 요청 ID가 같고 내용이 달라지면 거부한다. 변경 없는 저장은 쓰지 않는다.
- 클라이언트는 같은 요청의 ID를 메모리와 sessionStorage의 해시 키에 보관하여 응답 유실 후 같은 입력의 재시도에 재사용한다. 서버 권한 검사를 캐시로 대체하지 않는다.
- 자동 변동은 기본 꺼짐이다. 교사가 켜면 서버가 시간당 한 번 현재 학기를 확인하고 1/6/24시간 간격이 된 종목만 처리한다. 종목 ID·학기·시간 구간으로 정한 결정론적 변동을 적용하며, 가격은 정수와 상하한을 지킨다. 지연된 예약 작업의 과거 구간을 한꺼번에 소급 재생하지 않는다.
- 시장 transaction과 종목별 다음 처리 시각으로 같은 구간의 이중 반영을 막는다. 정지·아직 도래하지 않은 구간·변동 후 값이 같은 경우에는 쓰지 않는다. 가격이 실제로 바뀔 때만 이력을 추가한다.
- 이 단계는 지갑 잔액·원장·순위를 변경하지 않는다. 이후 매매 추가 시 서버의 확정 가격/잔액/보유량/영수증을 같은 transaction에서 처리하고 공개 차단을 함께 검증해야 한다.

## 읽기·쓰기 예산

- 관리 조회: 사용자 권한 1 + 학기 설정/포인터/manifest 3 + 시장 1 = transaction 안에서 5문서 읽기, 쓰기 0. 세션·점검 검증의 기존 읽기는 별도다.
- 저장: 위 5 + 해당 요청 영수증 1 = transaction 안에서 6문서 읽기. 실제 변경은 시장 1 + 영수증 1 = 2문서 쓰기. 중복·no-op·거부에서는 쓰기 0. 경합 시 Firestore transaction 재시도 비용은 추가될 수 있다.
- 예약 작업: 학기 설정/포인터/manifest/시장 4문서 읽기. 변경된 종목이 하나 이상이면 시장 1문서 쓰기, 아니면 쓰기 0. 별도 종목별 쿼리나 학생 지갑 조회는 없다.
- UI는 실제 탭이 마운트되고 문서가 보일 때만 최초 조회한다. 주기적 폴링·실시간 listener·숨김 탭 조회는 없고 명시적인 새로고침만 제공한다. 저장 응답으로 화면을 갱신하여 후속 전체 재조회를 생략한다.
- client 조회는 계정·인증 시점·학기별 진행 중인 요청만 공유하고 완료된 결과를 권한 캐시로 재사용하지 않는다. 계정/학기 변경이나 unmount 후 도착한 화면 응답은 폐기한다.

## UI

- `education-web-design-system`, 기존 `DESIGN.md` 토큰·`InfoHelp`·`useAppToast`를 사용한다. 제목·운영 상태·액션은 투명한 페이지 배경 위에 놓고 실제 편집 폼만 표면으로 구분한다.
- `animejs` 4.5.0으로 선택한 종목의 가격 선을 300ms opacity/translate 전환한다. 줄어든 동작 설정에서는 정지 차트를 유지하며 scope cleanup으로 언마운트 시 정리한다. 애니메이션에 서버 요청을 연결하지 않는다.
- 가격 선의 가로 위치는 배열 순번 대신 실제 `atMs` 간격을 따른다. 변동 없는 시점의 생략으로 시간 간격이 왜곡되지 않으며, 단일 점이나 모든 시각이 같은 경우에도 유한 좌표를 유지한다.
- 공식 참고: [Anime.js React 사용](https://animejs.com/documentation/getting-started/using-with-react), [Scope mediaQueries](https://animejs.com/documentation/scope/scope-parameters/mediaqueries).
