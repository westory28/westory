# 조회·자동저장 통신 점검 (2026-11-10)

## 운영 기준과 원인

- Firestore는 `nam5`이며 기존 평가 함수는 서울이다. 여러 순차 서버 조회에는 리전 간 왕복이 포함된다. 기존 함수의 리전·대기 인스턴스·시간 제한을 일괄 변경하지 않는다.
- 11월 10일 21:00~23:19 KST의 실제 POST 요청 로그에서 `getAssessmentState` 성공 13건의 중앙값은 2,707ms, `saveAssessmentProgress` 성공 221건은 1,904ms였다. `executeCommand` 성공 35건의 95백분위는 10,743ms였다. 이 함수에는 여러 종류의 명령이 포함되어 있어 모의고사 시작만의 수치로 해석하지 않는다. 해당 표본에 5xx는 없었다. 소량 표본과 사용자 네트워크 시간을 제외한 서버 지표라는 한계가 있다.
- 수업자료는 표시와 관계없는 편집용 학기 포인터 조회를 기다리고 있었다. 평가/수업자료 간 동일 목차 조회, 명단 동일 경로 이동, 겹치는 모의고사 상태/저장 요청에는 중복 통신이 있었다.
- 기존 명단은 사용자 문서 전체를 브라우저로 전송했다. 자동저장도 이미지·지문을 포함하는 동결 시험지 전체를 다시 읽었다.
