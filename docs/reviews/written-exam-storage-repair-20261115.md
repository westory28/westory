# 정기시험 원안지 Storage 권한 오류 복구

## 원인

운영 Storage 규칙과 작업 기준 규칙이 동일한 것을 확인했다. 기존 원안지 경로는 세션·점검 설정·교사 프로필·현재 학기·등록 revision을 조회했다. Firebase Storage의 교차 서비스 규칙은 평가 한 번에 Firestore 문서 두 개까지만 접근하므로 이 경로는 운영에서 실패한다. [Firebase 공식 문서](https://firebase.google.com/docs/storage/security/rules-conditions)

앞선 XLSX/PDF 가져오기 검사의 에뮬레이터 성공은 이 운영 한도를 보장하지 않았다. 이번 검사는 파일 인식과 운영 저장 권한을 구분한다.

## 변경

- `manageWrittenExamAsset` 전용 서버 함수로 업로드·읽기·실패 정리를 처리한다. 기존 로그인 세션 증명, 가입 승인, 점검, 교사/관리자, 현재 학기 및 본인 등록 revision 검사를 유지한다. 학생·staff·외부 계정 접근은 거부한다.
- 4MiB 단위 전송으로 JSON/base64 크기 제한을 피하고 PDF 30MiB, PNG/WebP 12MiB 제한을 유지한다. 서버는 실제 크기·형식·해시를 검사하고 생성 전용 저장 조건으로 같은 내용의 응답 유실 재시도를 처리한다. 한 조각 파일은 최종 객체만 한 번 저장한다.
- 파일은 공개 다운로드 토큰 없이 `private, no-store`로 저장한다. 완료된 현재 manifest에 있는 파일만 인증된 서버 응답으로 읽는다. Storage 직접 접근은 완성 파일과 임시 조각 모두 차단한다.
- 정리를 시작하면 서버가 먼저 `cleanup` 상태를 확정하고 파일을 지운다. 그 뒤 늦게 도착한 게시·업로드는 거부한다. Firestore 규칙은 본인 `cleanup` 자료와 학급 복사본의 삭제만 허용하며, 클라이언트의 상태 변경·새 자료 쓰기·게시 권한은 추가하지 않는다. 정리 실패 시 비공개 상태를 보존하고 재시도한다.
- 이전 학기 읽기는 기존 세션 문서의 증명을 사용하고 세션을 개설하거나 갱신하지 않는다. 공통 Firebase 연결을 재사용해 로컬 에뮬레이터 설정을 보존하며, 해당 읽기 함수의 서버 이름과 `read` 동작을 고정한다. 기존 쓰기 차단은 유지한다.

학생 점수·서명·이의 상태와 학생 화면은 변경하지 않는다. 새 AI 호출·외부 처리 업체·개인정보 항목·학생 공개 범위를 추가하지 않는 기존 평가 관리의 저장 경로 유지보수다.

## 검증과 운영

- 서버 합성 검사 46개: 크기·해시·형식, 역할/세션/학기/소유권, 공개 전 읽기 차단, 응답 유실, 임시 조각 정리, cleanup 확정 실패·삭제 실패·늦은 게시 차단. 여러 파일이 같은 revision의 정리를 요청하면 Firestore 상태 확정만 재시도하고, GCS 작업을 트랜잭션 재실행에 포함하지 않는다.
- 클라이언트 18개·점수 원장 연결 46개 검사 통과: 분할 전송과 응답 크기·해시, 계정/인증 시점 변경, 이전 학기 읽기 및 쓰기 차단. 기본 빌드에 연결한다.
- 실제 Firestore/Storage 에뮬레이터 59개 통과: 실제 클라이언트와 서버 handler를 연결해 등록·게시·읽기·정리 및 직접 Storage 차단을 검증했다. 4MiB를 넘는 PDF를 두 조각으로 전송·재조회하고 원본 바이트와 해시를 대조했다. 기본 빌드·전체 포맷·Functions 검사·기존 점수 요청 규칙 검사도 통과했다.
- `prepare-written-exam-assets-release.mjs`는 운영 세션 함수의 보안 helper 4개를 그대로 보존한 신규 함수 단독 패키지를 만든다. 저장소와의 차이는 관리자 최근 인증 예외뿐이며 이 함수의 기본 세션 검사에는 적용되지 않는다. 기존 Functions는 재배포하지 않는다. `verify-written-exam-assets-release.mjs`로 운영 ACTIVE·자원 제한·전체 소스 해시·익명 거부를 대조한다.
- 운영 현재 학기는 `2026-2`, revision 1, ACTIVE이며 Firestore 동시성 모드는 PESSIMISTIC이다. 실제 시험 정보와 검증 화면은 로컬 증거 경로에만 저장한다.

검증 로그: `C:/evidence/written-exam-storage-repair`, `C:/evidence/written-exam-asset-recovery-20261115`. 실제 파일과 학생 정보는 커밋하지 않는다.
