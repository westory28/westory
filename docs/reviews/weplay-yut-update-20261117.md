# 윷놀이 진행 속도와 게임 전체화면

기준은 `c30f889740350cb683f6530a185c16b388c1a782`이며 기존 `C:\westory`의 미커밋 작업을 보존하기 위해 `C:\westory-weplay-update`에서 변경했다.

## 동작

- 윷놀이의 기존 native/회전/fallback 전체화면 버튼을 PC에서도 표시한다. 이순신은 공통 게임 프레임에서 시작·대기·경기·결과 화면을 같은 전체화면에 유지한다. 브라우저가 native API를 거절하면 고정 화면을 사용하며 Escape, 키보드 초점 순환과 원래 초점·페이지 스크롤 복원을 제공한다. 해전 버튼은 별도 44px 행을 사용해 점수·입력란과 겹치지 않는다.
- 윷 던지기 준비 중에는 지난 사건 문구를 숨기고, 요청·투척 연출 중에는 하단 상태 문구를 숨긴다. 기존 예약 공간은 유지하므로 윷판 위치가 흔들리지 않는다.
- 서버의 연출 유예는 시작 1,200ms, 던지기 2,400ms, 이동 1,100ms, 새 업기 1,500ms, 잡기 1,900ms다. 기존 던지기·말 선택 제한 시간은 그대로다. 실제 이동은 칸당 160ms/최대740ms, 잡기 반응900ms, 업기450ms, 일반 착지180ms이며 결과 강조는750ms다. 말마다 실제 착지·효과를 유지하고 봇의 추가 대기를350/450ms로 줄인다.
- 약/중/강 세기의 도·개·걸·윷·모 확률은 각각 `33/35/24/6/2`, `25/34/31/7/3`, `20/31/35/10/4`%다. 세기 사이에서는 선형 보간한다. **같은 참가자의 직전 결과가 윷 또는 모이면 다음 투척의 윷·모 확률을 각각 절반으로 줄이고, 빠진 확률은 도·개·걸에 비례 분배한다.** 도·개·걸이 나온 뒤에는 기본 확률로 복귀한다. 온라인·싱글·봇은 같은 코어를 사용하며 진행 중인 구형 V1방의 균등 윷면 규칙은 보존한다.
- 온라인에서는 트랜잭션 밖에서 난수4개를 고정하고 트랜잭션 안의 실제 직전 결과에 적용한다. 재시도는 난수를 다시 뽑지 않으며 명령 영수증의 결과를 복구한다. 클라이언트가 보낸 이전 결과는 사용하지 않는다.

## 통신과 권한

참가자의 화면은 기존 한 방의 실시간 구독과 한 동작당 한 명령 호출을 유지한다. 투척 프레임·전체화면·로컬 효과에 서버 호출을 추가하지 않는다. 서버에서는 **단일 트랜잭션 내부**의 중복 문서 읽기만 합친다. 시작 시 같은 학생·학급을 반복 읽는 비용을 줄이며 다음 요청·트랜잭션 재시도·계정·학기 사이에 캐시를 공유하지 않는다. 공개 차단, 세션, 현재 학적, 교사 관전 신호, 보상·명령 영수증을 유지한다.

실제 Firestore 에뮬레이터에서 4인 비밀방 시작은23읽기/6쓰기, 같은 시작 영수증 재시도는10읽기/0쓰기, 오래된 revision 거부는10읽기/0쓰기였다. 각 경로에 공통 세션 guard의3읽기가 별도로 있다. 이는 해당 정상 시나리오의 문서 접근 계측이며 충돌 재시도의 과금 상한이 아니다. 필드 projection 감소를 읽기 건수 감소로 계산하지 않았다.
