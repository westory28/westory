# 시험 입장과 서버 장애 복구 점검

기준 커밋은 `f28249071969440779cebfb4239e162762610937`다. 갤럭시탭에서 응시에 실패해 새로고침·재로그인·앱 재설치가 필요했다는 보고를 조사했다.

## 확인한 원인

- 목록의 `응시`는 주소만 이동하고, 풀이 화면이 다시 시작 버튼을 요구했다.
- 2026-11-09 09:08–09:15 KST에 운영 `executeCommand`의 256 MiB 메모리 초과가 세 번 발생했다. 같은 시간대 네 시험 함수에서 503·504·500 응답을 확인했고, 504는 약 60초에 끝났다. 요청 건수는 영향받은 학생 수와 같지 않다.
- 당시 네 함수는 CPU 1, 메모리 256 MiB, 인스턴스당 동시 요청 80이었다. 모니터링 표본에서는 CPU가 낮은 상태로 한 인스턴스에 요청이 쌓였다. `getAssessmentState`에는 Firestore 트랜잭션 경합, 자동 저장에는 만료된 트랜잭션 오류도 있었다.
- 상태 조회가 쓰기 트랜잭션을 사용하여 진행 상태 저장과 잠금 경합을 일으킬 수 있었다. 현재 프론트엔드에는 서비스 워커 캐시가 없다. 앱 재설치를 서버 장애의 해결 방법으로 안내하지 않는다.
- 서버 응답을 받은 뒤 로그인 상태 검사에서 거절되면 클라이언트가 영수증 ID를 지웠다. 다시 시도할 때 같은 영수증을 유지해야 하는 경계가 빠져 있었다.

운영 로그는 제한된 시간의 오류·리비전·런타임 지표만 읽었다. 학생 이름·UID·토큰·답안·요청 본문은 이 문서에 보관하지 않는다.

## 변경

목록에서 누른 시작 의도를 한 번 소비하고, 서버 상태 확인과 자료 준비가 끝나면 기존 START로 바로 입장한다. 직접 링크는 시작 확인을 유지한다. 새로고침·응답 유실 때에는 기존 응시와 서버 마감 시각을 사용한다. 초기화의 오래된 응답은 무효화하며, 결과 표시용 교육과정 라벨 조회가 느리거나 실패해도 시험 입장을 막지 않는다. 시작 오류는 현재 화면에서 사유와 재시도 버튼을 제공한다.

서울 `executeCommand`, `getCommandStatus`, `getAssessmentState`, `saveAssessmentProgress`만 메모리 512 MiB, CPU 1, 동시 요청 8, 최대 인스턴스 20, 최소 인스턴스 0으로 설정한다. 시간 제한은 60초를 유지한다. 처리 중 자원 비용은 달라질 수 있으며 상시 대기 인스턴스는 추가하지 않는다. [Firebase 런타임 설정](https://firebase.google.com/docs/functions/manage-functions)의 메모리·동시성 설정을 사용한다.

상태·영수증 조회는 Firestore의 일관된 읽기 전용 스냅샷을 사용한다. START·SAVE·SUBMIT은 기존 쓰기 트랜잭션과 영수증을 유지하고 현재 권한·학기·공개 범위·선행 회차를 재검사한다. 응답 이후 로그인 변경이 감지되면 결과 수락은 차단하면서 원래 소유자의 명시적 재시도를 위한 영수증은 보존한다. 자동 쓰기 재시도·폴링은 추가하지 않는다.

## 검증 및 운영 범위

- `node scripts/verify-assessment-command-recovery.mjs`: 실제 클라이언트 모듈의 응답 유실·로그인 변경·계정 격리·새로고침·동시 요청·저장소 차단.
- `node scripts/verify-mock-exam-runner-browser.mjs`: 한 번 클릭 입장, StrictMode, 자료 준비 실패, 오래된 초기화, 보조 조회 실패·무응답, 기존 풀이·자동저장·제출·결과.
- `node scripts/verify-student-quiz-entry-browser.mjs`, `node scripts/verify-assessment-attempt-safety.mjs`: 목록 연결·회차 제한·서버 시간 유지.
- `functions/productionGateway/scripts/verify-quiz-release-integration.cjs`: 로컬 demo Firestore에서 10개 반의 합성 학생 30명의 요청을 인스턴스당 동시성 8로 처리하고, 중복 영수증, 상태 조회와 자동저장 병행, 응답 유실 뒤 같은 응시·답안 복구를 검사한다. 실제 SDK의 읽기 전용/쓰기 트랜잭션 분리를 함께 검사한다.
- `npm run build`, `npm run format:check`, `npm --prefix functions run check`.

30개의 START를 제한 없이 동시에 실행한 에뮬레이터 실험에서는 `ABORTED: Transaction lock timeout`이 발생했다. 이 결과를 통과로 취급하지 않는다. [Firestore 에뮬레이터의 공식 제한](https://firebase.google.com/docs/emulator-suite/connect_firestore)에 따르면 운영의 모든 트랜잭션 동작을 재현하지 않으며 동시 쓰기 잠금 해제에 최대 30초가 걸릴 수 있다. 인스턴스당 동시성 검사와 영수증 복구 검사는 운영 다중 인스턴스 부하 보증이 아니다.

390·768·1280·1366px 브라우저 검사는 합성 계정으로 수행한다. 실제 갤럭시탭 기기나 학생 계정의 운영 응시를 대신한 검증으로 표현하지 않는다. 실제 학생의 응시·답안·점수·공개 상태를 시험 목적으로 변경하지 않는다.

기존 학교 서비스의 시험 안정화이며 새 학교·권한·개인정보 항목·외부 AI 호출·외부 전송은 추가하지 않는다. Functions 소스는 기존 운영 원본과 대조했다. Firebase의 위 네 함수와 Vercel main 배포만 반영하며 rules·공개 설정·다른 리전은 변경하지 않는다.
