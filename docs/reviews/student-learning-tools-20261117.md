# 학생 플로팅 학습 도구와 신문고 접속 복구

기준: `c30f889740350cb683f6530a185c16b388c1a782` (운영 도메인의 배포 소스와 일치), 2026-11-17.

## 동작과 원인

- 학생 신문고는 사이드 메뉴에 등록하지 않는 경로인데 공통 학생 메뉴 검사가 `not-visible`로 거부했다. `/student/gongsinmoongo` 정확한 경로만 메뉴 포함 여부 검사에서 분리한다. 로그인·승인·학적·학기·신문고 실시간 공개·서버 본인 검사는 유지하며 유사 경로는 계속 거부한다.
- 플로팅 버튼을 body 포털로 고정하고 일반 버튼 겹침에 의한 학생 버튼 숨김을 제거한다. 모달·전체화면·스크롤 잠금의 기존 경계와 교사 버튼 동작은 유지한다. 첨부와 동일한 기존 `westory-mark.webp`를 재사용하고 닫힘은 회색, 펼침은 원색이다.
- `+` 팝업에서 학습 자료·역사 지도·위스피·아바타 상점·위플레이·캘린더만 추가·삭제·순서 저장한다. 손잡이 마우스/터치 드래그와 키보드 이동을 지원한다. 등록한 메뉴도 현재 학생 메뉴 공개 검사를 통과해야 표시한다. 사전·신문고는 사용자 저장 목록에 넣지 않는다.

## 통신과 저장 경계

- 학생 신문고 `bootstrap`은 상태와 본인 최신 질문 첫 페이지를 한 read-only transaction으로 반환한다. 초기 두 callable을 하나로 합쳐 실제 에뮬레이터 기준 43→33문서 읽기, 0쓰기(질문 20개·다음 페이지 판정 포함)다. 빈 질문함은 13읽기다. 별도 공개 문서 구독과 그 rules 종속 읽기는 이 수치에 포함하지 않는다. 질문 과거 페이지는 cursor로 계속 열며 전체 자료를 임의로 잘라 집계하지 않는다. 교사와 구 클라이언트 `state/questions`는 유지한다.
- 공개 문서는 계정·로그인 세대·학기별 하나의 listener를 공유하며 마지막 구독자가 떠나면 폐기한다. 오류에서는 닫고 명시적 재시도를 제공한다. 같은 UID의 새 로그인도 재연결한다.
- 바로가기는 서버 전용 `users/{uid}/preferences/studentLearningTools` 한 문서다. 허용된 6개 ID의 순서와 revision만 사용한다. 계정의 다음 학기에도 설정을 유지하지만 요청마다 현재 학기·학생 세션·승인·canonical 학적·학급을 검증한다. 직접 Firestore read/write는 기존 rules가 거부한다.
- 바로가기 조회는 첫 메뉴 펼침과 60초 지난 뒤 다시 펼침에만 수행한다. 계정·로그인 세대·학기별 메모리 캐시, 진행 중 요청 공유, 마지막 소비자 해제 시 폐기를 사용한다. 폴링·자동 쓰기 재시도·새 최소 인스턴스는 없다. 오류는 재사용하지 않는다.
- 실제 세션 포함 조회 10읽기/0쓰기, 변경 저장 10읽기/1쓰기다. 클라이언트 동일값 저장은 호출 0회, 서버 동일값/응답 유실 재요청은 쓰기 0회다. revision 충돌에서는 초안을 보존하고 명시적으로 다시 불러온다. 학생 삭제는 기존 수집에 해당 설정 ref 하나만 추가하며 추가 목록 조회는 없다.

## 검증과 배포

- 실제 신문고 Firestore 통합 26그룹, 바로가기 6그룹 및 기존 점수요청 rules 검사 통과. 본인/타인/교사, 현재/이전 학기, 세션 변경, 공개 차단, cursor, 변경 없는 쓰기, 동시 기기 충돌, 응답 유실 재시도를 포함한다.
- `verify-auth-route-gates.mjs`, `verify-floating-launchers-browser.mjs`, `verify-gongsinmoongo-browser.mjs` 및 `--entry-only`, `verify-student-learning-shortcuts-client.mjs`, `verify-student-shortcuts-browser.mjs`로 실제 컴포넌트/훅과 합성 서비스의 회귀를 확인한다. 학생/교사 플로팅 320/390/768/1280/1440px, 편집창 390/768/1280px, 최상단/중간/끝 고정과 회색/원색, 접근성·초점·드래그·취소·저장·기기간 유지·오류 복구를 확인한다.
- 운영 원본은 `output/gongsin-access-20261117/production`, 격리 배포본은 같은 evidence의 `release`에 보존한다. `getGongsinmoongo`는 운영 원본의 `gongsinmoongo.js`만 교체하고 동일 의존성으로 26개 통합 검사를 통과했다. `deleteStudentData`는 운영 원본 index의 정확한 ref 추가 2줄만 이식하며 기존 조회 4회·기존 파일·런타임을 보존했다. 새 `manageStudentLearningShortcuts`는 선택 배포한다. 다른 함수·rules·공개 설정을 배포하지 않는다.
- 병행 중인 위스 메뉴/주식 UI 패치를 섞지 않도록 별도 checkout에서 앱 빌드와 커밋 범위를 검증한다. 프론트는 최종 검증 커밋의 Vercel main 배포가 Ready인 것을 확인하고 운영 도메인으로 승격한다. 실제 학생 계정의 질문·점수·보상·설정 쓰기는 운영 검증에 사용하지 않는다.

기존 학생 기능의 유지보수와 개인 화면 설정이다. 외부 AI/에이전트 호출, 새 외부 서비스·처리 위치·학생 공개 범위 확대는 없다. 서버 권한을 완화하지 않으며 보안성 검토 승인이나 면제를 새로 주장하지 않는다.
