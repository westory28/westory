# 시험 조회·제출 및 교사 응시 기록 성능 개선

기준: `7a9da91f6ac380a1f5d54dafa52d620a3767971a` (2026-11-09). 같은 작업 공간에서 진행하는 모의고사 A–E 분석 개선과 파일·커밋·배포 순서를 조율했다. 분석 변경은 별도 검토 기록을 따르며, 이 문서는 조회량과 로딩 변경을 다룬다.

## 학생 시험

- 모의고사 최초 상태 조회에 자료 준비를 합쳐 정상 신규 응시의 순차 callable을 상태·준비·시작 3회에서 상태/준비·시작 2회로 줄인다. 준비 자료는 계정·평가·초기화 세대에 묶어 한 번만 사용한다. 실패 후 수동 재시도와 출제 자료 변경은 다시 확인한다.
- 기존 진행 중 응시의 복구는 유지한다. 자료 준비가 허용되지 않는 상태에서는 준비 없는 상태 조회로 기존 복구 가능 여부를 확인한다. 이 응답을 새 응시의 준비 승인으로 사용하지 않는다.
- 모의고사 결과에서 쓰지 않는 교육과정 라벨과 점수 비교 기록 조회를 제거한다. 단원 평가의 비교 기능은 유지한다.
- 상태 조회는 현재 학기 검증에서 읽은 포인터·학기 문서를 재사용한다. 모의고사 과거 응시 목록은 상태·횟수·제출 시각 등 메타데이터만 읽고, 반환·복구에 필요한 응시의 원문을 따로 읽는다. 과거 응시 문서 수 자체를 줄이는 변경은 아니며 전송량과 메모리를 줄인다.
- 시작·제출이 600ms 이상 걸리면 공통 로딩 오버레이를 표시한다. 제출 중 종이를 유지하고 중복 키보드 동작을 막는다. 진행 중 자동 저장이 완료되면 최신 revision으로 제출하며, 실패하면 답안을 유지하고 명시적 재시도를 허용한다.
- 최종 제출의 보상 준비에서 학적·학급·정책의 독립적인 읽기 세 단계를 병렬로 수행한다. 읽는 문서 수와 보상·점수·영수증의 원자적 저장은 동일하다. 검증과 오류의 우선순위는 기존 순서를 유지하고, 구형 식별자는 기존 순차 경로를 사용한다.

## 교사 결과·응시 기록

- 학생별 기록 목록은 선택하지 않은 응시의 문항을 미리 읽지 않는다. 선택한 응시의 문항만 10개씩 최대 두 묶음으로 읽고 같은 화면 범위에서 재사용한다. 저장된 문항 스냅샷이 있으면 현재 문제은행을 읽지 않는다.
- 학생·로그인 세대·학기·현재/이전 자료·상위 필터가 바뀌면 메모리 캐시와 진행 중 응답의 표시 범위를 초기화한다. 목록과 문항 조회 실패에는 별도 재조회 버튼을 제공한다.
- 학급 분석의 구형 학적 조회는 문자열·숫자 반 값을 합쳐 네 쿼리에서 두 쿼리로 줄인다. 현재 학적 조회와 병렬로 수행하고, 중복 학생의 학기 소유권 문서는 한 번만 읽는다. 이동·제외·이전 학기의 학생을 잘못 포함하지 않는 검사는 유지한다.
- 고정 모의고사 문항은 선택한 회차만 조회한다. 선택한 회차가 없으면 작은 메타데이터로 구형 은행 여부를 확인한다. 회차가 있는 은행에서 다른 회차나 무회차 자료를 빌려오지 않는다.
- 무회차 구형 은행은 호환성 확인을 위한 조회 단계가 늘어난다. 현재 고정 시험지의 본문 전송 감소와 구분하며, 모든 과거 데이터 경로가 같은 비율로 빨라진다고 해석하지 않는다.
- 평가 목록·요약·상세·응시 기록 조회에 기존 공통 로딩을 표시한다. 대화상자 안에서는 인라인 로딩을 사용한다.

## 검증 범위

- `functions/scripts/verify-quiz-class-analysis.cjs`: 쿼리 수·필드 범위·다른 회차 원문 미조회·구형 은행·빈 회차·학급 이동·캐시·권한 회귀.
- `functions/productionGateway/scripts/verify-assessment-lifecycle.cjs`: 모의고사 메타데이터 조회·필요 응시 복원·재응시 제한·대기·초기화·선행 회차·단원 평가 유지.
- `functions/productionGateway/scripts/verify-assessment-wis-reward.cjs`: 독립 읽기의 병렬 시작·오류 우선순위·보상 금액·전체 제출 롤백·중복 지급 차단.
- `scripts/verify-mock-exam-runner-browser.mjs`: 단일 입장·지연 조회·저장 대기·지연 제출·실패 복구·회차/자료 변경·390/768/1280/1366px.
- `scripts/verify-student-history-loading-browser.mjs`: 합성 500문항 중 첫 응시 20문항만 조회, 재선택·보관 스냅샷 추가 조회 없음, 오류·늦은 응답·390/768/1280px.
- `scripts/verify-quiz-class-browser.mjs --loading-only`: 조회·상세 로딩, 390/768/1280px, 대기 중 초기화, 상세 창 갱신·닫기 및 늦은 응답 차단.
- 합쳐진 최종 소스의 `npm run build`, `npm run format:check`, TypeScript 검사, `npm --prefix functions run check`를 통과했다. 공통 class browser 전체 검사와 구형 클라이언트의 명시적 갱신 안내를 포함한 실제 Firestore 에뮬레이터 통합 검사도 통과했다. 운영 배포는 서울 `executeCommand,getCommandStatus,getAssessmentState,getQuizClassAnalysis`와 Vercel 최신 main을 한 번에 조율하며, 실제 운영 도메인 확인까지를 완료 기준으로 삼는다.
- 합성 지연/쿼리 수 검사를 실제 학생 기기의 응답 시간 측정으로 취급하지 않는다.

학생 답안·점수·응시 제한·공개 범위·위스 지급 규칙을 QA 목적으로 변경하지 않는다. 새로운 외부 AI 호출·개인정보 전송·권한·영구 학생 캐시를 추가하지 않는 기존 서비스 유지보수다.
