## 적용 범위

1. **HTML 실행 차단:** 약관·개발자 일지·공지 이미지·편집기·수업본문·각주의 표시 경계에 DOMPurify를 적용한다. 스크립트·이벤트·위험 URL·폼·문서 삽입을 제거하고 표·목록·한글·서식·이미지와 수업 빈칸을 유지한다. 저장된 원문은 다시 쓰지 않는다. 일반 학생의 권한 상승 공격을 재현한 결과가 아니라 관리자 작성·붙여넣기·레거시 콘텐츠의 방어 공백 보완이다.
2. **이미지 파서 진입 차단:** sharp의 SVG 처리 취약점에 대응해 이미지 실제 헤더를 native parser 호출 전에 검사한다. MIME 문자열만 믿거나 `metadata()` 뒤에 확인하는 순서를 보완한다. PNG/JPEG/WebP와 사료실의 기존 GIF/AVIF/TIFF/HEIF 계약을 유지한다. sharp 자체의 버전 수정이 아닌 해당 SVG 입력 경로의 완화 조치다.
3. **브라우저·개발 설정:** MIME 추측 방지와 referrer 정책을 적용한다. 앱 문서에 같은 출처 프레임 정책, `base-uri`, `object-src`를 적용한다. Firebase 인증 프록시에는 프레임 정책을 추가하지 않는다. 통신·PDF worker·외부 지도·로그인 팝업을 막는 광범위 CSP는 도입하지 않는다. 사용되지 않는 GEMINI 비밀키의 프런트엔드 define 설정을 없애고 개발 서버 기본 바인딩을 loopback으로 제한한다. 필요할 때 `--host`를 명시할 수 있다.
4. **의존성:** 기존 호환 범위 안에서 루트 lock을 갱신하고 보안 설정·공급망 IOC 검사를 빌드에 연결한다. [의존성 상세 기록](security-dependencies-20261110.md)에 버전·공식 공지·잔여 경고를 구분했다.
5. **알림 이동 경계:** 설정에 있는 기존 23개 목적지는 모두 학생·교사 내부 화면이다. 최종 이동값을 해당 내부 경로로 제한하고 외부 스킴·호스트·역슬래시·제어문자를 거부한다. 쿼리·해시·인코딩한 제목과 ID, 읽음 처리는 보존한다. 현재 HashRouter에서 외부 이동 공격을 재현한 것은 아니며 관리자가 저장한 값의 방어 경계를 명확히 한 조치다.

## 안정성과 비용

- HTML 정화는 브라우저에서 수행하며 저장 원문·인증·학기 경로·서버 호출을 변경하지 않는다. 수업본문은 입력마다 반복 정화하지 않도록 메모이제이션한다.
- 이미지 검사는 파일 앞부분의 고정 길이 바이트만 비교한다. 정상 요청의 Firestore 조회·쓰기·Storage 통신은 추가하지 않는다.
- 위장 SVG 거부 검사: 지도·사료·배너의 native 파서 호출 0회, 파일 저장 0회, lease/receipt 쓰기 0회. 기존 지도/사료의 대상·티켓 읽기 2회, 배너 0회다. 학습지 이벤트의 기존 실패 상태 기록 1회는 보존한다.
- 캐시 헤더·인증 프록시·평가 영수증·실시간 공개 검사·권한 정책은 보존한다. 의존성 36개 제거를 실제 브라우저 전송량이나 운영 지연 개선 수치로 보고하지 않는다.
- 전체 서비스의 무장애·성능 향상을 보증하는 부하 시험은 아니다. 운영 자료에 대한 공격·부하 시험은 하지 않았다.

## 운영 반영 방식

운영 함수별 보관 소스를 내려받아 비교했다. 수업자료 업로드는 저장소보다 발전한 `lessonAssetVerification.js`를 사용하고 지도 소스에도 기존 차이가 있다. 루트 Functions 일괄 배포는 하지 않는다.

`scripts/prepare-security-image-release.mjs`가 각 함수의 운영 원본에 검사 호출과 공통 helper만 추가한다. 기존 exports·의존성·권한·런타임 파일을 SHA-256으로 대조한다. 준비본·원본 zip 해시·변경 diff는 로컬 `output/security-release/<함수>/`에 둔다. 운영 원본이나 임시 배포 폴더는 Git에 넣지 않는다.

선택 배포 대상은 서울의 `uploadMapAssetContent`, `uploadSourceArchiveAsset`, `registerSchoolBanner`, `processSourceArchiveIncomingUpload`, `processLessonAssetUpload`, `uploadLessonAssetContent`다. 각 배포는 `--only functions:<해당 함수>`를 반드시 지정한다. rules·다른 함수·최소 인스턴스·공개 상태를 변경하지 않는다.

프런트엔드는 최신 main을 통합·검증한 커밋을 Vercel에 배포하고 운영 도메인 연결을 확인한다. 운영 화면 확인에는 Chrome `방재석` 프로필을 사용한다. 최종 배포 ID·커밋·검증 결과는 작업 완료 기록에 남긴다.

점검 중 원격에 추가된 아바타 변경 `ef28593d8fcc43b4e3097b6cfa3efd70535a7854`를 fast-forward로 통합하고 최종 앱 빌드를 다시 수행한다. 원래 작업 폴더의 다른 미커밋 UI 변경을 이 패치에 포함하지 않는다.

## 남은 범위와 판단

- 루트 audit 경고는 19→7개(critical 1→0개)다. Functions lock의 18개 경고는 그대로다. 해당 조건·실행 가능성·차단과 라이브러리 자체 패치를 구분한다. 상세 잔여 항목은 의존성 기록을 따른다.
- React2Shell/RSC·Next.js 관련 최근 취약점은 현재 React 18 SPA/HashRouter 구성에 해당하지 않는다. 현재 사용하는 PDF.js 5.4.296은 알려진 2024 JavaScript 실행 취약점 수정 버전 이상이다. 미사용 CDN PDF.js 3.11.174 모듈은 활성 경로로 계산하지 않았다.
- Tailwind CDN과 Quill CDN의 자체 호스팅·무결성 고정, 전체 Functions 의존성 갱신은 별도 호환·운영 소스 통합 검증이 남는다. npm audit만으로 CDN이나 클라우드 IAM·백업 복구 설정을 모두 점검한 것은 아니다.
- 로컬 기본 Node 24.13.1 대신 이번 Functions와 통합 검증에는 보안 수정된 22.23.4를 사용한다. 확인한 운영 업로드 함수는 Node 22 자동 런타임 업데이트 정책이다. 선언된 주 버전만으로 관리형 서버의 정확한 패치 버전을 확정하지 않는다.
- AI 런타임 호출·외부 AI 전송·개인정보 항목·학생 공개 범위·사용자 권한 확대가 없는 기존 서비스 보안 유지보수다. 기관의 기존 보안성 검토 이력은 여전히 별도 확인 사항이며 이번 검사를 승인·인증으로 표현하지 않는다.
