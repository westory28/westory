# 컨테이너 로딩과 배포 파일 복구 (2026-11-10)

사용자는 이전 전체 화면 로딩 때문에 다른 작업을 할 수 없다고 지적했고, 해당 컨테이너의 블러와 로고만 요청했다. 또한 배포 직후 이전 CSS 파일의 `Unable to preload CSS` 오류가 초기 오류 화면으로 표시되는 문제를 함께 제보했다.

## 로딩 범위

- PageLoading·InlineLoading은 해당 콘텐츠 슬롯에 표시한다. LoadingOverlay는 직접 부모의 기존 DOM·입력값을 유지하고 그 영역의 콘텐츠만 잠근다. 다른 메뉴·섹션·스크롤·팝업 닫기는 사용할 수 있다.
- `scope="screen"`은 로그인/세션/공개 설정 준비, 최외곽 부트스트랩, 배포 파일 복구에만 명시한다. 라우트의 콘텐츠 준비와 일반 목록·폼·팝업은 지역 범위를 기본으로 한다.
- 같은 부모의 여러 요청은 합치고 다른 컨테이너는 독립적으로 완료한다. 숨긴 탭·닫힌 팝업은 표시하지 않는다. StrictMode와 연속 요청에서도 부모 위치 지정·inert·aria-busy·포커스를 복원한다.
- 지역 완료 효과도 같은 부모 안에 남겨 로고와 블러를 함께 제거한다. 스크롤·리사이즈·페이지 숨김 때는 잔상을 즉시 정리한다. 긴 컨테이너와 가로로 스크롤하는 표에서는 보이는 부분의 중앙에 로고를 둔다.
- fragment나 body portal 아래에 있던 메모·시험·서명/이의·개발일지 로딩을 실제 작업 영역으로 옮겼다. 학급 분석의 상세 로딩 중복을 없애고, 표 오른쪽 셀에 가려지던 로고를 해당 표 영역으로 옮겼다. 데이터 조회·저장·채점·권한·학기 경로는 변경하지 않는다.

## 배포 파일 복구

기존 오류 판별은 JavaScript chunk 실패만 포함해 CSS preload 실패를 놓쳤다. 새 공통 복구는 CSS/JS 파일 실패 때만 같은 origin의 HTML을 최대 1회 확인한다(5초 제한). 현재 문서와 새 문서의 module entry가 다르고 온라인이며 입력 중이던 내용이 없을 때 새로고침한다. 같은 대상 재시도와 60초 안의 연속 복구는 sessionStorage로 차단한다. 저장소 접근이 불가능해도 새로고침을 반복하지 않는다.

복구 확인·이동 중에는 로고를 표시한다. 같은 버전의 일시 오류·오프라인·사용자 입력 감지·재시도 한도·탐색 취소는 영구 로딩으로 숨기지 않으며 간결한 복구 문구와 수동 버튼을 제공한다. 기술 진단은 접힌 오류 정보 안에 둔다. lazyWithRetry의 별도 새로고침과 영구 pending Promise를 제거해 복구를 한 곳에서 처리한다.

입력 감지는 boolean만 보관하며 입력값·학생 정보는 수집/전송/추가 저장하지 않는다. 기존 최외곽 ErrorBoundary가 이미 언마운트한 임시 React 상태까지 보존한다고 보장하지 않으며, 화면별 기존 임시 저장·답안 복구 경계를 유지한다.

애니메이션에는 추가 서버 조회·쓰기·폴링이 없다. 배포 파일 복구의 정적 HTML 확인은 오류가 발생했을 때만 수행하며 정상 사용 시 요청하지 않는다. 외부 AI·서버 권한·Firebase Functions/rules·개인정보 항목은 변경하지 않는다.
