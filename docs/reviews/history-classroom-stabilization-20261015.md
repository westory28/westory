# 역사교실 안정화 검증 (2026-10-15)

## 작업 기준과 확인한 원인

- 회사 PC `C:\westory`, `main`의 깨끗한 checkout을 최신 `origin/main`으로 fast-forward했다. 수정 기준은 `3adc0de6a55a3f8c815fa606f1712d749a926f6b`이며 당시 `www.westory.kr`의 Vercel 운영 커밋과 일치했다.
- 운영 교사 화면의 면제권 호출은 종료된 `grantHistoryClassroomExemptions` callable을 사용했다. 현재 canonical 명령 gateway의 기존 학습 면제 기능은 재사용 면제권과 다른 계약이므로 그대로 대체할 수 없었다.
- 면제권 조회 rules는 학생 접속 검사를 중복 실행했다. 실제 Firestore emulator에서 1,000개 표현식 평가 한도 초과로 교사 목록 조회 실패를 재현했다.
- 응시 저장 응답 유실, 제출 직후 재접속, 오프라인 화면 이탈, 교사 리셋의 로컬 표식 동기화에 복구 누락이 있었다. 기존 결과의 통과 여부도 현재 과제의 기준점수에 영향을 받았다.
- 수업자료 문서가 중복된 경우 자료 편집기와 역사교실이 서로 다른 원본을 선택할 수 있었고, 응시 중 원본 교체 및 실패한 저장의 공개 상태 보존을 보강해야 했다.

## 변경 범위

- 면제권 부여·회수·학생 신청·교사 승인/거절을 `executeCommand`의 receipt 기반 명령으로 연결했다. 활성 학기·재학/학급·실제 선택 학생·소유권을 서버에서 검증하고 일괄 부여는 원자적으로 처리한다. 승인 결과는 canonical과 학기별 호환 기록에 같은 ID로 저장하며 보상이나 가짜 응시를 생성하지 않는다.
- 신규 명령의 응답 유실을 복구하도록 `getCommandStatus`도 현재 운영 원본과 대조해 루트 export에 연결했다. 폐기된 callable은 다시 활성화하지 않았다.
- rules는 기존 교사/관리자/본인 조회 범위를 유지하면서 중복 접속 검사를 제거했다. 클라이언트 직접 쓰기는 계속 차단한다.
- 학생 단어 목록을 기본 접힘 아코디언으로 옮겼다. 타이머·제출·페이지/확대 조작을 고정 도구막대에 유지하고, 키보드로 화면 높이가 줄어도 입력 중 문서 확대율을 보존한다. 결과 창은 작은 화면에서 내부 스크롤과 포커스 복귀를 지원한다.
- 서버 마감 시간은 오프라인에도 계속 적용한다. 답안·미확인 저장 revision·제출 대기를 보존하고 연결 복구 후 동일 요청을 재확인한다. 단순 blur나 네트워크 손실로 잠그지 않으며, 3초 이상 document hidden 또는 실제 경로 이탈은 서버 잠금으로 처리한다. 목록에서 다시 접속해도 미전송 잠금을 반영한다.
- 교사 리셋은 서버 응시와 학생별 과제 표식을 함께 갱신한다. 새 과제 저장이 오래된 클라이언트 표식으로 이를 덮어쓰지 않는다. 통과 기준과 판정은 새 응시/결과에 고정하고 이전 결과 fallback은 유지한다.
- 수업자료 선택을 편집기와 일치시키고 `최신 수업자료 반영`을 명시적 초안 동작으로 제공한다. 빈칸 ID·소수점 좌표·페이지·정답·inkClip을 유지한다. 진행 중 응시나 제출 기록이 있는 과제의 빈칸 구조 변경은 차단한다. 검증 실패 시 기존 공개 상태를 유지하고, 성공한 소스 변경과 일시정지를 한 트랜잭션으로 처리한다.

## 운영 반영 대상과 확인 기준

Functions는 운영 원본을 대조한 서울 `executeCommand`, `getCommandStatus` 두 개만 배포한다. Firestore rules는 별도 배포 후 현재 운영 release의 본문과 로컬 해시를 비교한다. 프론트엔드는 검증 커밋을 main에 push하고 Vercel Ready 및 필요 시 Promote를 확인한다. `www.westory.kr`의 연결 커밋·실제 제공 asset과 로그인된 교사 면제권/자료 화면을 확인해야 완료다. 실제 학생에게 시험용 면제권을 지급하거나 운영 응시·성적을 생성하는 검증은 하지 않는다.

## 남은 기기 제약

Galaxy Tab S7에 대응하는 화면 크기와 키보드 축소 상태를 브라우저에서 검증했으며 실제 기기에서의 삼성 키보드 동작은 별도 확인 대상이다. 웹페이지가 계속 보이는 분할 화면은 브라우저에서 확실하게 식별할 수 없다. 키보드·시스템 UI에 의한 단순 blur를 부정행위로 처리하지 않으므로, 분할 화면까지 강제 차단하려면 기기 관리/시험 모드가 필요하다.
