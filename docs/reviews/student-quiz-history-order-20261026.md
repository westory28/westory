# 학생 풀이·마이페이지 문항 순서 연결 수정

## 원인과 운영 확인

기준 커밋은 `c5dfa433be16975cf493d0d9b52c8f4b7ad056b3`이다. 작업 전 운영 도메인의 Vercel 배포 `dpl_5pnV2ppTNCn1gnAQ8FoUx2YfM82A`도 같은 커밋이었다. 기준 checkout의 공지 이미지 관련 미완료 변경은 유지하고 별도 worktree에서 수정했다.

서버는 응시 시작 때 선택 문항의 `questionIds`, 채점·원문 스냅샷을 같은 순서로 저장한다. 이전 `QuizRunner.startQuiz`는 받은 문항 전체를 다시 `selectQuestions`에 넘겨 등록순·단원순·무작위순으로 재정렬했다. 마이페이지는 저장된 `answerChecks` 순서를 사용하므로 풀이 화면의 1번과 기록의 1번이 달랐다. 재접속도 서버 순서를 사용해 최초 풀이와 달라질 수 있었다.

운영 최신 결과 50건 중 퀴즈 32건(진단 18, 형성 14)을 읽기 전용으로 대조했다. 모두 단원순 설정이며, 기존 프론트 정렬 재현 결과 32건 모두 기록 순서와 달랐다. 다른 번호 위치에 표시된 문항은 합계 611개였다. 응시와 결과의 학생·학기·문제 ID 집합·답안·원문 불일치, 원문 누락, ID 중복·숫자 변환 충돌은 없었다. 학생 식별자와 문제 원문은 검증 문서에 보관하지 않았다.

## 변경

- 문항 선택 집합과 학습 우선순위는 유지한 채 서버가 출제 설정의 최종 표시 순서를 한 번 확정한다.
- 등록순은 숫자 ID 순, 단원순은 교육과정 트리 순, 무작위는 기존 응시별 결정적 섞기 순서를 사용한다. 단원순만 교육과정 트리 1문서를 추가로 읽는다.
- 프론트는 최초 시작과 이어 풀기에서 서버 문항 순서를 그대로 사용한다. 순서형·연결형 보기 섞기는 유지한다.
- 기존 진행 중 응시는 저장된 문항 순서로 재개한다. 신규 순서 확정은 새 응시에만 적용한다.
- 기존 마이페이지의 본인·학기 검사, 저장 원문·답안의 ID 연결, legacy 기록 조회, 점수·보상 정책은 그대로다. 문제은행의 현재 원문으로 과거 기록을 대체하지 않는다.

과거 클라이언트가 최종 표시 순서를 서버에 저장하지 않았고 당시 교육과정 순서도 보관하지 않았다. 특히 무작위 출제의 과거 번호는 정확히 복원할 수 없다. 기존 기록의 원문·답안·점수를 추정하여 다시 쓰지 않는다.

## 검증

- `node scripts/verify-quiz-history-identity.mjs`: 실제 runner의 시작·답안 입력·복원·제출 함수를 실행하고 서버 상세 변환 및 마이페이지 복습 변환과 연결한다. 일반 평가/모의고사 × 출제 순서 3종 × 난수 3종, 18개 흐름에서 ID·본문·답안·이미지 보기·재개 위치를 비교한다.
- `functions/productionGateway/scripts/verify-assessment-learning.cjs`: 무작위·등록순·단원순·기존 randomOrder=false에 대해 시작→저장→재개→제출→마이페이지의 순서·원문·답안을 검사한다. 진행 중 설정·교육과정·문제은행 변경 및 제출 응답 재전송도 검사한다.
- 실제 `QuizRunner`와 `MyQuizHistory`를 합성 서버 경계로 실행한 Chrome 검증: 서버 ID 순서 31→12→24로 시작, 2번 답변 후 새로고침·이어하기, 제출 67점, 마이페이지 동일 1·2·3번과 오답·내 답 연결 확인. 운영 응시나 점수를 생성하지 않았다.
- 기본 검증은 `npm run build`, `npm --prefix functions run check`, 기존 평가 안전성·복습·마이페이지 검증을 수행한다.

전체 Functions 검사에서 기존 지도 transport 테스트 VM이 최근 추가된 `brandWatermark` import를 등록하지 않아 실패했다. 기준 checkout에서도 동일하게 재현했다. 테스트 fixture에 해당 의존성만 등록하고, PDF 검사 중 이미지 워터마크가 호출되면 실패하도록 보완했다. 실제 지도·워터마크 코드는 변경하지 않았다. 동시 작업으로 추가된 `71a5643d` 공지 표지 변경을 fast-forward로 보존하고 통합 타입 검사를 다시 수행했다.

## 배포 범위

운영 `executeCommand`의 gateway JS/JSON 56개가 기준 커밋과 동일함을 LF 정규화 해시로 확인했다. `getMyQuizHistory`도 동일하며, 운영 `getAssessmentState`의 차이는 별도 역사교실 명령 부분으로 퀴즈 조회·직렬화는 동일하다.

변경 실행 경로는 서울 `executeCommand`의 신규 응시 시작뿐이다. `getAssessmentState`, `getMyQuizHistory`, `getCommandStatus`, rules는 변경하거나 재배포하지 않는다. Functions 검사 후 `executeCommand`를 선택 배포하고, 검증한 프론트 커밋의 Vercel 배포를 운영 도메인에 승격한다. 운영 배포 ID 및 실제 확인 결과는 최종 응답으로 기록한다.
