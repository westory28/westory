# 역사교실 결과·알림 연결 복구 (2026-10-21)

## 확인한 원인

- 학생 제출은 canonical `semester_assessment_results`에 저장됐지만 교사 화면은 학기별 `history_classroom_results`만 조회했다. 운영의 서로 다른 두 학생에서 93%, 97% 통과 원본과 교사 조회 자료 누락을 확인했다. 개인 이름·UID·답안은 이 기록에 포함하지 않는다.
- canonical 제출·응시 잠금·면제권 명령에 과거 callable의 알림 생성 경로가 연결되지 않았다. 교사 알림함 자체가 없는 사례를 확인했다.
- 알림 목록을 연 상태에서는 새 inbox 갱신을 반영하지 않았고, 읽음·삭제는 운영에서 이미 종료된 callable을 사용했다.
- 교사 저장·공개 전환·직접 면제 성공을 공통 토스트로 알리는 경로가 누락됐다.

## 변경

- 현재 학기의 배정 과제 ID로 한정한 canonical 결과 구독과 기존 결과의 병합을 추가했다. 같은 결과 ID는 중복 집계하지 않으며 실패 후 통과, 면제 완료, 조회 실패를 구별한다. 제출 답안은 자료 확인 때만 읽는다.
- 제출·잠금·면제권·공개 배정의 교사용 조회 자료와 알림을 해당 canonical 명령 트랜잭션에 함께 기록한다. 기존 알림 설정·템플릿·삭제 기준시각과 결정적인 항목 ID를 유지한다. 비활성 교사 포털의 잔여 staff 권한은 수신 권한이 아니다.
- 통과 여부는 저장된 판정을 우선한다. 구 기록의 판정 값이 없을 때는 저장 당시 결과·응시의 통과 기준만 사용하며 확인할 수 없으면 복구 대상에서 제외해 `unknownOutcomes`로 보고한다. 점수·원본 답안·보상은 변경하지 않는다.
- `manageNotificationInbox`는 세션·현재 학기·본인 알림함을 검증하는 별도 API다. 실제 표시한 개인 알림 ID와 방송 알림 시각만 읽음 처리하고 동시 도착·오래된 요청·페이지 단위 삭제에도 새 알림 수와 기준시각을 보존한다. 폐기된 callable은 다시 연결하지 않는다.
- 공통 토스트를 사용해 저장·공개/비공개·면제권 사용 결과를 알리고, 알림의 과제 링크로 해당 응시 현황을 연다.

## 검증과 운영 절차

- 루트 빌드, 최종 타입·포맷 검사, Functions 검사와 운영 소스 해시 검사를 수행한다. 루트 빌드의 XLSX `hair` 구분선 검사는 유지한다.
- 교사 실제 컴포넌트 브라우저: 390/768/1024/1280/1366px, 실시간 통과, 실패 후 통과, 중복 면제, 제출 자료, 알림 링크, 토스트, 실패 시 상태 보존.
- 학생 실제 컴포넌트: 목록 복구 52개, 응시 복구 30개. 최신 공통 CSS를 검증용 번들에도 포함하도록 이전 fixture를 보완했다.
- 알림 목록 갱신·동시 도착·읽음 요청·학기 전환, 본인 inbox API의 권한·세션·동시 처리·삭제 기준시각을 검사했다.
- 격리된 Firestore 에뮬레이터에서 실제 exported callable, 공개 배정, 제출·잠금·면제권·알림, 응답 유실·재전송·롤백과 복구의 반복 실행을 검증했다. 보상 회귀 37개를 유지한다.
- 수정 전 서울 `executeCommand` 운영 소스를 대조했다. lifecycle·exemption·productionSource·notification helper는 기준 checkout과 일치했고 gateway의 차이는 앞서 검토한 순위 조회의 선택적 읽기 최적화뿐이었다.
- Firebase 배포 대상은 서울 `executeCommand`, 새 `manageNotificationInbox` 두 개다. 명령 종류와 상태 조회 allowlist는 바꾸지 않으며 Functions·rules를 일괄 배포하지 않는다. Vercel은 검증한 커밋을 운영 도메인으로 승격한다.
- 기존 자료 복구는 `repair-history-classroom-sync.cjs`의 명시한 과제·현재 학기와 알림 기준시각으로 한정한다. dry-run → 배포 → apply → 재검사 순서로 진행하며 초기화되거나 새 통과로 대체된 잠금, 이미 삭제한 알림을 되살리지 않는다.
- 상세 합성 브라우저 증거와 개인정보를 포함한 운영 대조·복구 보고서는 Git에서 제외한 `.superloopy/sessions/history-integration-20261021/evidence/`에 둔다.
