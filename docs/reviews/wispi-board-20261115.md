# 위스 마을 사이드 메뉴·학생 투자 현황

## 범위

- 기준: `bd6687a51ac692e537011ce9868650625ac01014`와 당시 운영 `www.westory.kr`.
- 기존 `C:\westory`의 성적·아바타 미커밋 변경을 보존하고 별도 worktree에서 작업했다.
- 교사 위스 마을에만 128px 사이드 메뉴를 적용한다. 767px 이하에서는 64px로 줄인다. 기존 위쪽 메뉴 한 줄을 제거하고 제목을 본문 위에 직접 놓는다. 학생 메뉴와 일반 위스 관리 화면은 유지한다.
- 위스피의 네 번째 탭은 `학생 투자 현황`이다. 학급·번호, 이름, 주식 계좌 현금, 매수 예약금, 보유 종목 수, 주식 평가액, 총자산, 실현손익, 평가손익을 표시한다. 전체 화면 진입 시 이름을 먼저 숨기며 교사가 다시 표시할 수 있다.

## 실제 서비스 경계

현재 운영에는 학생 주식 계좌·체결 원장이 없다. 운영 컬렉션 메타데이터만 확인했으며 학생 명부·지갑을 수집하거나 예시 계좌를 실제 투자자로 표시하지 않았다. 따라서 현재 운영 화면의 올바른 상태는 `투자 자료 연결 전`, 금액은 `—`다. 실제로 연결된 빈 원장만 0명·0위스로 표시한다. 학생 매매·입출금과 공개 상태는 이번 패치로 활성화하지 않는다.

후속 실매매 서버는 `buildWisStockInvestmentBoard` 계약에 따라 같은 계좌 원장·가격 revision에서 완전한 전체/학급 projection을 원자적으로 갱신해야 한다. 이번 변경에는 해당 원장 작성기나 거래 RPC가 없다. 누락된 계좌·가격을 0으로 치환하면 안 되며, 900KiB 예산을 초과하면 부분 목록 대신 실패하도록 했다.

## 회계와 접근 경계

- 주식 계좌 현금에는 매수 예약금이 포함된다. 총자산은 `계좌 현금 + 체결된 보유 주식 평가액`이며 예약금을 다시 더하지 않는다.
- 평가손익은 `보유 평가액 − 매수 수수료를 포함한 보유 원가`다. 실현손익과 분리하며 일반 위스 지갑·누적 위스는 포함하지 않는다.
- 정확한 정수와 BigInt 합계 대조, 중복 학생/학급번호, 학기·학급, 원장 출처, revision, 완전성, 스키마를 검사한다. 불일치는 숫자를 표시하지 않고 재연결 오류로 처리한다.
- Firestore는 현재 학기·준비도·로그인 세션·유효 교사/위스 권한을 검사한 뒤 선택한 projection 한 문서의 get만 허용한다. 학생·다른 역할·list·클라이언트 쓰기·비공개 가격 seed·계좌/원장 직접 조회는 허용하지 않는다.
- 권한/학기 변경은 기존 AuthContext의 본인 프로필·설정 구독과 페이지 경계를 재사용한다. 별도로 본인 UID와 현재 auth_time이 일치하는 로그인 세션 문서만 관찰하여, 투자 자료가 그대로여도 세션 폐쇄 즉시 전광판을 비운다. 본인에게 로그인 RPC가 이미 제공하는 세션 메타데이터만 허용하고 알 수 없는 필드가 추가되면 차단한다. 타인의 세션·과거 세션·목록·쓰기는 불가하다.
- ENFORCE 만료는 단발 타이머로 종료하며 기존 OBSERVE_ONLY/DISABLED 정책은 보존한다. 학생 개인정보의 외부 AI 전송이나 새로운 AI 호출은 없다. 기존 교사 권한 안에서 조회 화면을 추가하는 유지보수다.

## 조회 비용·복구

탭 진입 시 현재 본인 세션 1개를 확인한 뒤 선택한 전체 또는 학급 projection 1개를 구독한다. 계정·학기·권한 경계와 분리된 로컬 저장 캐시는 사용하지 않는다. 학급 변경은 이전 두 구독을 해제하고 새 범위의 두 구독을 연다. 정렬·페이지 이동·이름 숨김·전체 화면·효과는 추가 조회 0회, 쓰기 0회다.

이 수치는 SDK의 구독 대상 수이며 청구되는 Firestore 읽기 수와 같다는 뜻이 아니다. 권한 규칙의 의존 문서 읽기, 실제 변경 전달, 재연결 읽기는 별도다. 정해진 간격의 폴링이나 변경 없는 재조회는 없다. 탭 이탈·브라우저 숨김·오프라인 때 구독과 타이머를 해제한다. 캐시 응답은 현재 자료로 표시하지 않고 서버 확인을 기다린다. 연결 실패 시 기존 숫자를 숨기고 사용자의 `다시 연결`로만 재시도한다.

## 검증과 배포

- `npm run verify:wis-investments`: 원장 합계/범위/용량/세션 검사와 실제 클라이언트 번들에 주입한 SDK로 구독 수·변경 전달·숨김·오프라인·캐시 장애·재시도·계정/auth_time 교체·타이머·늦은 콜백을 검증한다.
- `verify-wis-stock-investment-board-rules.mjs`: 실제 Firestore 에뮬레이터에서 현재 교사/위스 권한, 학생 차단, 세션·학기 폐쇄, 정확한 문서 조회, list/write 차단, 미연결→연결 전달, 세션 회수 listener를 검사한다.
- `verify-wis-stock-investment-board-browser.mjs`: 합성 50명으로 320/390/768/1280/1440px, 학급 조회, 정렬/20행 페이지, 연결 전/진짜 빈 원장/오류, 전체 화면·이름 숨김, reduced motion, 계정/학기 초기화를 검사한다.
- `verify-wis-village-navigation.mjs`: 실제 교사 페이지와 본문을 결합하여 5개 폭에서 메뉴/제목/권한/조회/학생 화면 유지 여부를 검사한다. 기존 stock/wallet/avatar 브라우저 회귀도 실행한다.
- 기본 앱 빌드, Functions 검사, `npm run test:score-request-rules`를 수행한다. 운영 rules 원본은 기준 커밋과 일치하는지 대조한 뒤 rules만 배포한다. 실행 Functions·학생 원장·시장 설정은 변경하지 않는다.
- 근거 산출물: 로컬 `output/wispi-board-20261115/`. 테스트용 합성 개인정보만 사용하며 운영 학생 정보는 포함하지 않는다. Vercel main의 검증 커밋을 승격한 뒤 운영 도메인과 교사 화면에서 별도로 확인한다.
