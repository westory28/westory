# 개발자 일지 좋아요 학생 명단 (2026-11-17)

## 범위

교사와 개발자는 글의 좋아요 수를 눌러 해당 글에 좋아요를 누른 학생의 이름·학년·반·번호를 확인한다. 학생의 좋아요 처리와 메타데이터 한 행 배치는 유지한다. 명단은 열 때만 읽고, 더 보기를 통해 나머지 학생을 확인한다. 이름·학적을 URL, 로컬 저장소, 분석 이벤트에 기록하지 않는다.

새 `getDeveloperLogLikeStudents` 서버 함수는 기존 로그인 세션·등록·점검 검사를 사용하고 최신 교사 역할을 검사한다. 학생 보조교사와 일반 staff에는 권한을 부여하지 않는다. Firestore/Storage rules, 좋아요 쓰기, 지갑, 학기 데이터에는 변경이 없다. 기존 교사 명단 접근 범위에서 해당 게시글 반응을 확인하는 유지보수이며, 새 개인정보 항목·외부 제공·런타임 AI 호출을 추가하지 않는다.

## 조회 경계

- 정식 게시글 경로는 `site_settings/developer_logs/items/{postId}`이다. 기존 화면이 사용하지 않는 루트 legacy 경로로 조회 범위를 확대하지 않는다.
- 해당 글의 likes만 문서 ID 순서와 커서로 조회한다. 기본 40명, 최대 100명씩 조회하며 추가 한 문서로 다음 페이지 유무를 확인한다. 전체 학생 명단을 가져와 대조하지 않는다.
- 현재 페이지의 좋아요 계정만 필드 선택으로 조회하여 이름·학적을 반환한다. 필드 선택은 전송량을 줄이며, 문서 읽기 요금 자체가 줄어드는 것으로 계산하지 않는다.
- 닫힌 명단과 학생 화면은 새 API를 호출하지 않는다. 로그인 계정·역할·게시글 변경과 창 닫기 뒤의 늦은 응답은 무시한다. 다시 열면 새로 조회하고 실패한 페이지는 재시도할 수 있다.
- 명단 조회 자체는 읽기 전용이다. 공통 세션 권한 검사의 기존 활동 기록은 그대로 유지한다.

## 검증 결과

- 서버 단위 검사 41개 그룹: 83명/3페이지, 유효성·권한·오류·커서·필드 선택과 페이지별 읽기 수를 검증했다.
- 실제 Firestore 에뮬레이터: 85명/3페이지와 학생 조회 문서 수 `[40, 40, 5]`, 실제 세션·등록·점검 모듈, 미승인·삭제·비활성·학생·직원 및 취소된 세션 차단을 확인했다. 정식 배포 준비본의 동일 검사도 통과했다. 명단 기능의 쓰기는 0회다.
- 클라이언트: 같은 계정·글·페이지의 동시 호출 1회, 완료 뒤 다시 열기 재조회, 페이지 분리, 전송 전 계정 변경 시 요청 0회, 지연 응답 폐기와 실패 재시도를 확인했다.
- 실제 컴포넌트를 사용하는 합성 브라우저: 320/390/768/1280/1440px에서 학생·교사·개발자·학생 보조교사, 40명 초과 명단, 빈 목록·실패·재시도, 권한 거부 시 기존 이름 제거, Escape·닫기·포커스 복귀·가로 넘침과 기존 좋아요를 포함한 72개 시나리오를 통과했다. 실제 학생 자료나 사용자 데스크톱 촬영을 사용하지 않았다.
- 독립 읽기 전용 코드 검토에서 추가 차단 이슈를 찾지 못했다. 서버 단위 검사는 리뷰에서도 별도 실행했다.
- 최신 원격 main의 위스피 변경을 fast-forward로 보존한 상태에서 `npm run build`, `npm --prefix functions run check`, 변경 화면의 Prettier 및 `git diff --check`를 통과했다. 기존 대형 번들 경고는 유지된다.

## 운영 반영

`scripts/prepare-developer-log-like-students-release.mjs`가 현재 서울 `uploadDeveloperLogImageContent`의 운영 소스를 보존하고 그 안의 세션·등록·점검 모듈을 그대로 사용한다. 최소 진입점에서 새 조회 함수 하나만 내보내며 기존 이미지 함수를 배포하지 않는다. Functions 기본 검사와 신규 서버·화면 검증 후 준비한 디렉터리에서 아래 함수만 배포한다.

```powershell
$env:FUNCTIONS_DISCOVERY_TIMEOUT='60'
firebase deploy --only functions:getDeveloperLogLikeStudents --project history-quiz-yongsin --config firebase.json
```

배포 후 `--verify`로 전체 소스 SHA, ACTIVE, Node 22, 256MiB, 30초, 최소 0/최대 5개 인스턴스, 동시성 40 및 기존 이미지 함수 원본의 보존을 확인한다. 프론트엔드는 검증한 main 커밋의 Vercel READY 배포를 운영 도메인에 연결한다. 운영 화면 촬영·컴퓨터 직접 조작은 사용자의 중단 요청에 따라 수행하지 않으며, 실제 운영 자산과 함수 응답·배포 상태를 확인한다.

검증 결과와 합성 화면 자료, 배포 기록은 Git 제외 경로 `output/developer-log-like-students-20261117/`에 보관한다. 실제 학생의 이름이나 명단은 검증 산출물에 남기지 않는다.
