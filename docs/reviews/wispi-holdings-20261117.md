# 학생 투자 목록 더보기와 보유 종목 (2026-11-17)

## 변경 범위

기준 저장소 `C:\westory`와 운영 도메인은 시작 시 main `328029eb6d32c5ed72c25cd1ae11d2b005602760`으로 일치했다. 작업 브랜치는 `codex/wispi-student-load-more-20261117`이다. 기존 교육 웹 디자인 기준과 투명 제목·필터·세로 목록 계약을 유지한다.

- 내부 스크롤 목록에 처음 20명을 표시하고 `더보기`마다 20명씩 누적한다. 전부 표시하면 버튼을 숨기며, 학급·학기·정렬 변경은 20명으로 초기화한다. 목록 높이와 스크롤 위치는 추가 표시 때 유지한다.
- 학생 선택 시 그래프와 회계 상세 아래에 종목명·보유 수량을 표시한다. 보유 0주는 제외하고 체결 전 매도 예약 주수는 보유 수량에 포함한다. 시장에서 종목 정보가 사라진 경우 `종목 정보 없음`으로 표시한다.

## 조회·권한·복구

기존 `getWisStockInvestmentHistory`가 동일 read-only transaction에서 읽는 계좌 positions와 시장 자료를 재사용해 각 이력에 `holdings: [{stockId,name,quantity}]`만 추가한다. 원장과 현재 보유 대조 후 반환하며 UID·계좌 ID·예약/원금 필드를 추가 노출하지 않는다. 1~5명·학급·활성 학기·세션·기존 교사/점수 조회 직원 권한 검사는 그대로다. 기존 개인 API 입력도 지원한다.

추가 Firestore 조회는 0회다. 기존 fixture의 5명은 23문서/10쿼리, 1명은 11문서를 유지한다. 더보기·기간 전환·가격만 갱신될 때도 추가 이력 조회가 없다. 보드 projection/학생 포털/거래·정산/공개 상태/rules/인증/AI 호출·외부 전송은 변경하지 않는다.

클라이언트는 종목 ID·이름·양의 정수 주수·중복을 검사하고 실패와 빈 보유를 구분한다. 보유 목록은 기존 화면의 학기·학급·보드 sourceRevision·새로고침 scope와 일치할 때만 표시한다. 개인 account revision과 전체 board revision은 다른 값이므로 직접 비교하지 않는다. 학생 선택·거래 갱신 중 이전 목록은 숨기고, 늦은 응답·비연결·계정 변경은 기존 차단을 적용한다.

## 검증

- 기존 브라우저 검사 6개 검증군: 320/390/768/1280/1440px, 20→40→50 누적·추가 조회 0·목록 높이/스크롤 보존·학급/정렬 초기화·키보드·44px 버튼·긴 종목명·각 주수·미보유·이전 학생/거래 revision 보유 수량 폐기·가격 전용 갱신 및 기존 그래프/전광판 회귀 통과.
- 클라이언트 응답·계정/세션·오류 재시도 검사 통과. 잘못된/누락/중복 holdings와 0·음수·소수·안전 범위 초과 주수를 거부하고 빈 목록은 허용한다.
- 서버 batch 검사 20개 검증 및 실제 배포 준비본의 batch·시계열 검사 통과. 다중 종목·0주·매도 예약·전량 매도·삭제 종목·원장 불일치·권한 거부·원본 식별자 미노출·동일 조회 예산을 확인했다. 전체 `npm --prefix functions run check` 통과.
- `npm run build`, 변경 TS/TSX Prettier, `git diff --check` 통과. 독립 읽기 전용 검토에서도 추가 결함이 없었다. UI 증거는 `output/wispi-charts-20261117/investment`, 빌드·서버 검증·배포 증거는 `output/wispi-holdings-20261117`에 보관한다. 실제 학생 자료는 검증 fixture로 사용하지 않는다.

## 배포

`prepare-wispi-holdings-release.mjs`로 현재 `getWisStockInvestmentHistory` 운영 ZIP을 보존하고 260파일 중 `wisStockInvestmentHistory.js` 하나만 바꾼다. 나머지 259파일·런타임·자원·환경 설정 및 학생 이력 함수는 보존한다. 준비본 자체 검증 후 이 함수만 먼저 배포하고 `verify-wispi-holdings-release.mjs --after`로 실제 코드·자원 보존과 익명 접근 차단을 검사한다. 기존 프런트는 새 필드를 무시하므로 서버 선배포와 호환된다.

프런트는 검증한 main 커밋의 Vercel 배포를 운영 도메인으로 승격하고 `방재석` Chrome 프로필에서 더보기와 선택 학생의 보유 목록을 읽기 전용으로 확인한다. 학생 계좌·위스·주문·성적·공개 상태를 시험 목적으로 변경하지 않는다.

서버 선택 배포와 배포 후 검증은 통과했다. 대상 함수 ACTIVE, 전체 260파일 SHA 일치, 기존 런타임·자원·환경 설정 및 학생 이력 함수 보존, 익명 접근 HTTP 401 차단을 확인했다. 프런트엔드 최종 SHA·운영 확인은 `output/wispi-holdings-20261117/release/frontend.json`에 기록한다.
