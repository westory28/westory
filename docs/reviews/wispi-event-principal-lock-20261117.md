# 위스피 이벤트 지원금 원금 출금 제한

## 범위와 승인

- 캠페인 `wispi-deposit-500-v1`의 학생당 500위스는 위스피 매수에만 사용한다. 지원금 투자 손실은 이후 지원금 수익으로 먼저 만회하고, 이를 넘는 수익은 출금할 수 있다.
- 사용자는 정책 적용 전 완료된 출금은 유지하도록 확인했다. 해당 출금과 일반 위스 지갑을 되돌리지 않는다.
- 기존 본인 입금액, 매수 한도·입금 대기 시간, 학기·계정 권한, 종목 졸업의 마지막 가격 정산은 유지한다.
- 런타임 AI 호출·외부 전송·학생 공개 범위 변경은 없다. 회계 검증에는 합성 자료를 사용하고 사용자 데스크톱·브라우저 조작이나 화면 캡처를 하지 않는다.

## 회계 계약

- 출금 가능액은 `현금 - 매수 예약 - 제한 현금 + 제한 현금 중 매수 예약`이다. 주식에 투자된 지원금 때문에 본인 현금이 잠기지 않는다.
- 매수에는 제한 현금을 먼저 배정한다. 지원금으로 온전히 산 주식과, 필요한 경우 최대 1주의 혼합 자금 주식을 별도 원장에 기록한다. 매수 수수료도 취득원가에 포함한다.
- 매도는 지원금 주식을 먼저 처분하며, 주문 접수 시 배정한 수량·취득원가는 체결 또는 취소까지 고정한다. 부분 매도나 체결 순서가 달라져도 다른 예약분을 침범하지 않는다.
- 매도대금 중 지원금 원금과 이전 지원금 손실 복구분은 제한 현금으로 돌아간다. 본인이 산 주식의 손실·수익과 섞지 않는다. 종목 졸업도 같은 회계 함수를 사용한다.
- `제한 현금 + 보유 주식의 지원금 취득원가 + 지원금 손실 이월 + 정책 적용 전 출금된 지원금 = 누적 지급 지원금`을 서버에서 검증한다.
- 개인 입금 미회수 원금에는 신규 지원금을 더하지 않는다. 일반 위스의 수익·등급 집계는 기존 출금 회계 계약을 유지한다.
- 학생 응답에는 출금 가능액과 필요한 계좌 정보만 반환하고, 매수별 자금 출처 원장은 보내지 않는다.

## 기존 계좌 전환

`migrate-wispi-bonus-restriction.mjs`는 해당 캠페인의 영수증만 조회한다. 계좌별 전체 거래 기록을 재생해 현재 현금과 기존 원금을 대조하고, 본인 원금과 남은 지원금을 분리한다. 보상 이후 체결이나 대기 주문이 있는 계좌는 이 전환 도구가 임의 추정하지 않고 중단한다.

실행은 기본 읽기 전용이며, 검토한 집계 계획의 SHA를 확인해야 적용할 수 있다. 적용 시 계좌를 다시 읽고 거래 내역의 SHA를 대조하며, 계좌·투자 현황·새 전환 영수증을 하나의 트랜잭션으로 기록한다. 기존 거래 영수증·일반 지갑·현금 잔액은 바꾸지 않는다. 재실행은 중복 기록 없이 종료한다.

2026-11-17 사전 검사에서는 지급 계좌 29개, 지급액 14,500위스, 남은 지원금 14,000위스, 정책 적용 전 출금된 지원금 500위스가 확인됐다. 최종 실행 시점에 다시 검증한다. 로컬 증거에는 학생 이름·UID·개별 잔액을 기록하지 않는다.

## 배포와 검증

- 제한 회계를 적용한 계좌만 `schemaVersion: 2`로 전환한다. 이전 버전의 서버가 새 원장을 무시하고 계좌를 변경하지 못하도록 기존 스키마 검사를 이용한다. 읽기 호환 함수를 먼저 배포하고 나머지 거래 함수를 배포한 뒤 계좌를 전환한다.
- 운영 함수별 기존 소스에 이번 diff만 적용한다. 이전에 별도로 배포한 업종·가격 최적화와 entrypoint, lockfile, 런타임, 스케줄러·작업 큐·IAM을 보존한다.
- 회계·마이그레이션 단위 검사, Firestore 에뮬레이터의 입출금·매매·졸업·중복 요청 검사, Functions 기본 검사와 앱 빌드를 수행한다. 합성 브라우저로 320/390/768/1280/1440px의 매수·출금 표시와 오류·키보드 동작을 검사한다.
- 배포 후 각 함수의 전체 소스 SHA와 운영 설정을 비교한다. Vercel 운영 도메인의 배포 커밋과 실제 JS 자산을 확인하며, 운영 학생 계좌로 시험 매매나 시험 출금을 하지 않는다.

검증·배포·전환 결과는 `output/wispi-event-principal-lock-20261117/`에 보관한다. 운영 반영 성공은 최종 결과에서 별도로 보고한다.

검증 결과: `npm run build`, `npm --prefix functions run check` 통과. 새 회계·전환 단위 검사 31개, 기존 일반 거래 에뮬레이터 16그룹, 신규·기존 이벤트와 졸업 에뮬레이터 13그룹 통과. 실제 배포용 원본에 패치를 적용한 패키지에서도 13그룹을 다시 통과했다. 독립 검토에서 전량·분할 매도 23,852개 조합의 제한 현금·손실 이월 불일치는 0건이었다. 학생 지갑 합성 브라우저 검증 8그룹을 통과했으며, 사용자 요청에 따라 화면 캡처와 운영 계좌 시험 거래는 하지 않았다.
