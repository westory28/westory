기준 checkout은 `C:\westory`, 기준 커밋은 `c30f889740350cb683f6530a185c16b388c1a782`다. 시작 당시 main과 origin/main이 같았고 운영 도메인의 Vercel 소스도 같은 커밋이었다. 진행 중인 메뉴·신문고 변경과 `output/`, `tmp/`는 이 패치에서 제외한다. 별도 검증 worktree에 이번 변경만 복사해 빌드한다.

## 주문 화면

- 학생 주문의 버튼 비활성 여부와 가까운 안내문을 같은 조건으로 판단한다. 총 잔액이 충분해 보여도 예약금, 수수료, 매수 후 최소 잔액 때문에 부족할 수 있으므로 예약액·수수료 포함 결제액·필수 잔액·부족액을 설명한다.
- 매도 대기 수량, 최소 주문 단위·최대 수량, 매도 전용 종목, 거래 정지, 지갑·시세 조회 중과 오류도 구분한다. 취소 처리 중 중복 명령은 보이는 이유와 함께 차단한다. 서버의 최종 거래 검사는 유지한다.
- 수량 입력과 매수/매도 실행 버튼을 같은 행에 둔다. 예상 금액과 수수료도 가능한 한 한 행에 표시한다. 기존 주문·취소·영수증·재인증 경계는 바꾸지 않는다.
- 교사 미리보기의 `주문 체험` 제목은 `주문`으로 변경한다. 이 화면의 합성 예시 계좌를 실제 학생 계좌로 바꾸지 않으며 예시 구분은 유지한다. 학생 주문 화면은 실제 거래 API를 그대로 사용한다.

## 학생별 수익률 꺾은선

- 교사의 학생 투자 현황에서 현재 범위의 모든 학생을 선택해 보유 수익률 변화를 본다. 기존 상위 5명 비교는 유지한다. 이름 가림은 학생 선택·차트·접근 가능한 이름에 함께 적용한다.
- 확정 체결 원장으로 당시 보유 수량과 수수료 포함 보유 원가를 복원하고 실제 저장된 시세로 평가손익을 계산한다. 계산 결과를 현재 계좌의 수량·원가와 대조한다. 현금·입출금·이미 매도한 주식의 실현손익은 이 보유 수익률에 섞지 않는다.
- 시세가 보존된 범위만 표시한다. 시세 누락·전량매도 구간은 선을 끊고, 동일 값의 관측 시각도 보존한다. 현재 보유량으로 과거 값을 꾸미지 않는다. 한국 시간축·0% 기준선·마우스·터치·방향키 값 확인을 제공한다.
- 신규 `getWisStockInvestmentHistory`는 읽기 전용이다. 현재 학기, 교사/허용 직원 권한, 점검·세션·승인 상태, 선택 범위의 학생, 학생Key/UID/계좌 해시를 서버에서 검사한다. 학생과 권한 없는 요청은 투자자료를 읽기 전에 차단한다.
- 선택 학생의 계좌를 서버 필터로 찾고 해당 계좌의 확정 체결만 완전 조회한다. 분석에 임의 limit을 적용하지 않는다. 계좌 중복 검출의 limit 2는 유일성 검사다. projection은 전송량 감소이며 읽기 건수 감소로 보고하지 않는다.
- 성공 조회는 기존 세션/점검 guard 읽기 외에 트랜잭션 8개 경계 문서 + 계좌 1개 + 선택 학생 체결 N개다. 조회·재조회는 0쓰기다. 학생 선택/명시 새로고침에만 조회하며 정렬·페이지·이름 가림·차트 조작은 추가 조회하지 않는다. 진행 중인 동일 계정·로그인 세대·학기·학급·학생 요청만 공유하고 완료 후 제거한다. 영구 캐시·폴링·새 trigger는 없다.

## 검증과 배포

- 학생 브라우저 24개 및 클라이언트 15개 회귀: 예약금/수수료/최소 잔액·수량·정지·중복 명령·오류·응답 유실 재시도, 320/390/768/1280/1440px 입력/버튼 배치와 44px 조작 영역. 근거는 `output/wispi-order-actions-20261117/student-browser/summary.json`이다.
- 보유 수익률 계산 12개, 새 API 어댑터 및 실제 Firebase 리전 분기 14개, 교사 보드 브라우저 9개 그룹: 학생·학급 선택, 세션/학기/계정 경계, 가림, 단일·빈·누락 시계열, 지연 응답·오류 재시도, 조회 횟수와 반응형 검증. 신규 조회를 기존 주식 함수와 같은 미국 리전으로 연결하며 기존 서울 기본 분기를 보존한다. 교사 화면 근거는 `output/wispi-history-20261117/board/report.json`이다.
- 원장 시계열 15개 그룹과 실제 Firestore 거래 통합 검사에 신규 읽기 권한/학기/학급/원가 대조/0쓰기 검사를 추가했다. 운영 원본 패키지로도 신규 함수 의존성을 검증했다. 근거는 `output/wispi-investment-history-prepared-20261117/trading-integration.json`이다. 선택 학생의 체결 1건 기준 트랜잭션 10읽기와 기존 세션/점검 3읽기, 쓰기 0이다.
- `scripts/prepare-wispi-history-release.mjs`는 운영 `getStudentWisStockHistory`의 ZIP을 보존하고 신규 모듈 2개와 export 등록만 이식한다. 신규 `getWisStockInvestmentHistory` 하나만 선택 배포하고 `--verify`로 운영 전체 파일 해시·ACTIVE·자원 설정 및 기존 함수 소스 보존을 확인한다. 기존 거래·가격 writer, Functions 전체, rules를 재배포하지 않는다.

전체 `npm run build`가 통과했다. 검사 중 main에 반영된 메뉴 통합 `632ca0d2`를 충돌 없이 포함했고, 최종 타입 검사와 실제 메뉴/위스피 브라우저 통합 검사를 추가로 통과한 상태에서 Vite 산출물을 만들었다. 필수 수행평가 XLSX의 hair 테두리 검증도 유지됐다.
