## 원인과 변경

- 학생 명예의 전당의 누적 위스 요청은 wrapper에서 `hall-index`로 바뀌는데
  실제 조회 함수의 `rankingMetric` 검증 목록에 이 projection이 없어 HTTP 400으로
  거절됐다. `hall-index`에 기존 누적 기준만 허용하는 한 줄을 고쳤다.
  로그인·학기·학생 학적·공개 범위·타인 접근 경계와 읽기 전용 동작을 유지한다.
- 교사 수신 토스트의 `persistent: true`와 일반 토스트의 최소 시간 연장이 원인이었다.
  수신 알림에만 정확한 지속 시간을 적용하고 기본 5초로 종료한다.
  `site_settings/notification_config.teacherToastDurationSeconds`의 1~60초 정수를
  교사 설정에서 저장하며 서버 승인 뒤 다음 알림부터 적용한다. 현재 떠 있는 알림,
  읽음 상태·알림 기록·학생 토스트·일반 작업 결과 알림은 기존 동작을 유지한다.
  마우스 올림·키보드 포커스·숨긴 탭에서는 기존 타이머 일시정지를 유지한다.
- 위스피 전광판 중앙 속보는 전체 크기의 80%, 한 종목씩 3초 순환으로 바꾼다.
  우측 상단의 실제 44px 닫기 영역·바깥 클릭·Escape는 현재 회차를 종료하며
  전광판을 닫지 않는다. 기존 10분 반복과 30분 사건 만료를 유지한다.
  알림음·한국어 음성은 기본 켜짐으로 시작하고 오디오 활성화·음성 목록 지연·
  재생 차단 시 수동 복구를 처리한다. 숫자는 화면에 표시하고 음성은 종목과 사건을
  짧게 읽는다. 화면 자동 종료 후 마지막 음성은 끝맺게 하되 재생 요청부터
  최대 8초 또는 사건 만료까지만 허용한다. 새 소식·수동 닫기·숨김·연결 중단은
  즉시 음성을 취소한다.
- 덩기덕 쿵더Rock은 다른 게임의 저장된 배경음 음소거를 이어받지 않고 진입 시
  소리를 켠다. 화면에서 직접 끈 설정은 곡 선택·재시작에도 유지한다.
  서버 시작 확인을 기다리는 동안의 음소거/해제 선택도 실제 오디오 생성에 반영한다.
  숨김·오디오 중단은 판정도 일시정지하고 터치/클릭의 계속 연주로 함께 복구한다.

## 검증과 조회량

- 실제 ranking wrapper→query core에서 수정 전 400을 재현하고 학생 자기 학년·반,
  교사 전체, 실패 후 재시도, 세션/권한 거부를 검사했다. 기존 hall-index 36개,
  ranking-modes 23개 및 최신 화면 로딩 17개·표시 9개 검사 통과.
  합성 80명 준비본의 학생 조회는 문서 get 40회와 쿼리 3회(반 1·순위 페이지 2,
  쿼리 반환 41문서), 교사는 get 37회와 같은 3쿼리다. 쓰기는 0이다.
  순위 쿼리의 서버 필터·페이지 크기 20과 필요한 fieldMask는 유지한다.
  fieldMask가 문서 읽기 건수를 줄인다고 해석하지 않는다.
- 토스트 기존 23항목, 알림함 회귀, 실제 설정→저장→종→토스트 6그룹 통과.
  기본5초/수정시간, 중요 알림, hover/focus/숨김, 서버 승인 전 값 무시,
  실패 후 수동 재시도, 계정·학기·역할 변경, 중복 헤더 공유, 학생 무구독을 확인했다.
  설정 열기는 1문서 읽기, 변경 저장은 1문서 쓰기, 동일값은 0쓰기다.
  표시 설정은 같은 계정·학기·역할의 헤더끼리 단일 문서 구독을 공유하며
  마지막 구독 해제·권한 경계·오류 시 상태를 폐기한다. 숨긴 탭은 구독을 해제한다.
  타이머 종료에는 서버 쓰기가 없다. 추가 폴링이나 자동 재시도는 없다.
- 전광판 320·390·768·1280·1366×768·1440·1920px에서 80% 실제 크기,
  44px 닫기, 3초 순환, 내부/외부 클릭·Escape, 음소거 독립, 음성 준비·정리,
  기존 구독 수 보존을 확인했다. 설정 입력은 390·768·1280px에서 가로넘침이 없다.

  TTS 시작·정상 종료(약 3.6초, 오류 0)를 확인했다. 기존 투자현황 12그룹도 통과했다.

실제 운영 화면 조작이 불가능했고 사용자가 현재 PC 조작이 어렵다고 답했다.

## 갤럭시탭 음성과 차임 후속 수정

기준은 모바일 토스트 위치 배포 `38528510`이다. 갤럭시탭에서 음성 켬 뒤에도
음성 엔진 오류가 보고되어 설치된 기본 한국어 음성을 우선하고, 실패하면 다른
브라우저 제공 한국어 음성 및 기기 기본 엔진으로 최대 3회 대체한다. 사용자 켬
동작 안에서 즉시 재생하며 속보가 없으면 짧은 확인 음성을 읽는다. 시작이 없는
3초 대기와 200ms 미만 즉시 종료도 실패로 감지한다. 전체 8초 상한, 사건 만료,
닫기·음소거·숨김·연결 중단 시 취소와 이전 요청의 지연 콜백 차단을 유지한다.
브라우저 재생 차단은 자동 재시도하지 않는다.

[Chromium Android 구현](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/content/browser/speech/tts_android.cc)의
resume 제약과 [Web Speech 계약](https://wicg.github.io/speech-api/)을 참고했다.
사용자가 갤럭시탭의 한국어 음성 데이터 미설치를 확인하고 설치했다. 기기에서
실제 읽기 성공까지 직접 청취한 것은 아니며 브라우저의 실제 오류 코드는 수집하지 않았다.
설치된 음성도 실패할 수 있으므로 언어 미설치·연결·출력·엔진 응답 오류를 구분한다.
새 외부 API·AI 호출·학생 정보 전송·서버 조회/쓰기는 추가하지 않는다.

알림음은 392/523.25Hz의 낮은 사인파, 최대 gain 0.045, 80ms의 완만한 시작과
650ms 감쇠를 사용한다. 기존 peak 약 0.12에서 약 0.045로 줄였으며 기기의
물리적인 스피커 음량을 측정한 값은 아니다.

사용자가 열어 둔 방재석 Chrome으로 운영 전광판의 실시간 연결을 확인했다.
같은 프로필의 로컬 합성 자료에서는 모든 한국어 엔진이 시작 이벤트 없이
즉시 종료되는 현상을 관찰해 회귀 검사와 대체 처리에 반영했다. 격리 Chrome과
Edge에서는 실제 음성 시작·종료와 파형 출력이 확인됐다. 운영 데이터와 기기
설정은 바꾸지 않으며 갤럭시탭 실기기 청취 여부는 별도 확인이 필요하다.

최종 변경만 복사한 `38528510` 기반 별도 worktree에서 Chrome 브라우저 검사
통과: 실제 TTS 시작·종료 각 1회, 2.743초, 오류 0, 파형 peak 0.044882.
이름 지정 엔진 실패·시작 없는 즉시 종료·재시도 대기 중 끔·지연 콜백·재생 차단·
확인 음성·숨김/연결 중단과 기존 7개 화면 폭·3초·8초·조회 수 회귀를 확인했다.
원래 작업 폴더의 병행 윷놀이·주식 지갑 수정은 이번 패치의 커밋과 검증 범위에서
제외했다. 별도 worktree의 `npm run build`, `npm run format:check`가 통과했다.
음성 후속 패치는 Functions·rules 변경 없이 프론트엔드만 배포한다.
