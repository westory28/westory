# 이전 학기 수행평가 다운로드 및 학생 데이터 연동 점검

점검일: 2026-10-18. 작업 전 코드와 운영 도메인은 모두 `e1671e0b0bfbee33d91730cf4a426c9de7403316`이었다.

## 원인과 수정

- 일람표 생성 직전 `getPrintClientInfo`를 호출하는 공통 클라이언트가 `openApplicationSession`을 요청했다. 이전 학기 창은 이 호출을 읽기 전용 보호 장치로 차단하므로 점수·서명 조회 후에도 다운로드가 실패했다. 운영 2026학년도 1학기 화면에서도 같은 오류를 확인했다.
- 이전 학기 내보내기는 부가 출력 IP 조회를 건너뛰고 기존 푸터의 IP 자리에 `확인 불가`를 표시한다. 현재 학기의 IP 조회 및 인증·쓰기 차단 정책은 유지한다.
- 구형 점수표에 `enteredScoreCount`가 없을 때 학생 공통 점수 판정 기준으로 입력 개수를 계산한다. 실제 0점과 합계만 있는 구형 0점을 보존하고, 명시적인 미등록 값과 입력하지 않은 항목은 미등록으로 유지한다.
- 조회 시 누락 문서를 자동 생성하는 기능은 활성화하지 않는다. 운영 데이터에 연결 문서 누락이 없고, 자동 복구를 켜면 다른 창의 삭제 작업과 경합할 수 있다.

## 운영 DB 읽기 전용 대조

점검 시 운영 학기는 2026학년도 2학기이며 저장된 성적 점수표는 2026학년도 1학기에 있었다. 운영 DB에 데이터를 생성하거나 수정하지 않았다. 개인 이름·UID·서명 이미지·인증 정보는 이 기록에 포함하지 않는다.

| 항목 | 확인 결과 |
| --- | --- |
| 점수표 / 전체 행 | 4개 / 1,158행 |
| UID가 연결된 행 | 1,153행 |
| 연결된 학생의 점수 문서 누락 | 0건 |
| 학생 프로필 누락 | 0건 |
| UID·학기·총점 불일치 | 각각 0건 |
| 확인 서명 | 1,076건, 기존 버전·확인 시각 규칙으로 모두 유효 |
| UID 미연결 행 | 5행, 모두 전출 상태 |

입력 여부 표현 차이 1건도 전출 기록이었다. 이 차이를 실제 0점으로 간주하여 운영 데이터를 고치지 않았다.

## 저장·조회 계약

- 교사 업로드·점수 수정은 Firestore 트랜잭션으로 학기별 `performance_score_rosters`와 `users/{uid}/performance_scores/{rosterId}`를 함께 저장한다. 최신 학생 식별 정보와 점수 버전을 다시 확인한다.
- 학생은 자기 UID 아래에서 해당 학기 점수를 서버 조회한다. 확인 서명은 점수 버전과 연결하며 저장 후 서버에서 재확인한다.
- 이전 학기 일람표는 과거 명단을 유지하고 UID별 점수 문서·서명을 다시 읽는다. 현재 학년·반·전출 상태로 과거 명단을 바꾸지 않는다. 서명 조회가 실패하면 다운로드를 중단한다.
- 현재 학기 저장 흐름의 검증은 합성 데이터와 로컬 에뮬레이터를 사용한다. 실제 학생 계정으로 운영 성적·서명을 시험 저장하지 않았다.

- `npm run build`: 타입 검사, 학기 보관 보호, 원본 XLSX `hair` 점선 회귀를 포함하여 통과.
- `node scripts/verify-score-roster-management.mjs`: 구형 점수·실제 0점·미등록, 학생 연결, 원자적 저장, 서명 무효화 및 조회 실패 처리 통과.
- `node scripts/verify-score-archive-download.mjs`: 실제 브라우저에서 과거 명단 32명·2평가 XLSX, 최신 서명, 0점, 푸터, 최종 OOXML 테두리, callable·쓰기 0건 확인. 수정 분기를 제외한 대조 실행은 기존 오류를 재현했다.
- `node scripts/verify-score-workflow-browser.mjs`: 390·768·1280px에서 현재 학기 업로드·수정·다운로드 등 23개 검증 묶음 통과, 브라우저 오류 0건. 기존 검사에 빠진 도움말 CSS와 현재 portal 위치를 가리키는 `aria-controls` locator를 보완했다.
- `node scripts/verify-score-warning-rules.mjs`: 로컬 Firestore에서 권한·동의·서명 11개 검사 통과.
- `node scripts/verify-performance-score-deletion.mjs`: 로컬 Firestore에서 삭제·타인 접근 차단·다른 학기 보존 8개 검사 통과. 오래된 테스트에 현재 필수 `auth_time`·애플리케이션 세션 fixture를 보완했다.
- 관련 파일 Prettier 및 `git diff --check` 통과.

Functions 및 Firestore/Storage rules의 제품 코드는 변경하지 않는다. 배포 대상은 프런트엔드이며 운영 도메인에서 최종 다운로드를 별도로 확인한다.
