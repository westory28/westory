# 위스피 학생 거래·분리 계좌 연결

## 범위

기존 교사 종목/규칙/가격 서버에 학생 계좌, 입출금, 주문 예약, 서버 체결, 거래 내역과 교사 전광판을 연결한다. 기존 `C:\westory`의 미커밋 작업은 수정하지 않고 별도 작업 트리를 사용했다. 운영 개장 여부와 학생 잔액은 검증을 위해 변경하지 않는다.

## 계약

- 최초 개장 시 studentOpen을 켠다. 이후 종료는 halted/epoch만 변경한다. 메뉴 숨김은 설정의 studentMenuVisibility.wispi만 담당한다. 중지 화면은 배경을 흐리게 하고 조작을 막으며 `위스피의 거래가 중지되었습니다.`를 표시한다.
- 마이페이지의 본인 계좌·내역은 시장 종료/메뉴 숨김에도 조회할 수 있다. 입금은 현재 일반 위스의 50% 이하이며 성공 후 24시간 간격이다. 주식 자산은 일반 위스·순위와 분리한다.
- 출금 전액은 현재 위스, 회수하지 않은 원금을 뺀 출금 수익만 누적 획득량에 반영한다. 활동 등급 rankEarnedTotal은 변경하지 않는다.
- 접수 때 가격·수량·수수료를 확정하고 현금/주식을 예약한다. 서버가 5~60초 후 처리할 비공개 Cloud Task를 생성한다. 브라우저 카운트다운은 표시용이다.
- 시간·요일·수수료·주문/일일/보유/비중 한도·발행량·최소 잔액·종목 정지·가격 유효기간은 서버에서 재검증한다. 미래 가격 모델과 seed는 학생에게 제공하지 않는다.
- 종료/권한 상실/학기 변경은 미체결 예약을 한 번만 해제한다. 재개 후에도 이전 epoch 주문은 체결하지 않는다. 영수증·주문 키로 중복 요청, 취소/체결 경합, 응답 유실을 처리한다.

## 저장·조회·복구

학기별 wis_stock_accounts/orders/transfer_receipts/history/supplies와 비공개 trade_state를 사용한다. 일반 원장의 STOCK_TRANSFER_OUT/IN에는 연결 영수증·회수 원금·출금 수익을 기록한다. 일반·주식 계좌, 원장, 교사 전체/학급 전광판을 같은 transaction에서 갱신한다. 최초 입금 때만 계좌를 만들며 조회만으로 쓰지 않는다.

학적 슬롯 trigger는 자산을 보존하며 전광판 학적/종료 상태를 동기화한다. 이전 학기 지연 이벤트와 중복 이벤트는 쓰지 않는다. 메뉴는 작은 상태 문서만 구독하며 가격 변화로 메뉴 문서를 다시 쓰지 않는다. 계좌/가격 구독은 화면에서만 유지하고 계정/auth_time/학기를 경계로 공유한다. 숨김·오프라인·세션 종료 시 구독과 화면 자료를 해제한다. 일반 잔액은 입출금 응답, 기존 points 이벤트, 화면 복귀, 명시적 새로고침으로 갱신하며 실제 거래는 항상 서버 최신 잔액을 검사한다. 폴링은 없다.

정상 transaction의 문서 읽기/쓰기: 계좌 조회 15/0, 입출금 18/11, 주문 접수·체결·취소 19/7, 중복 입출금/접수 16/0, 완료 task 재호출 1/0. 학생 callable의 공통 세션 검사 약 3읽기는 별도다. 내역은 본인 accountId/sequence 커서로 20건+다음 페이지 확인 1건을 읽으므로 가득 찬 페이지는 권한·계좌·공통 세션을 포함해 최대 39문서다. 필드 축소를 읽기 건수 감소로 계산하지 않는다.

인스턴스당 학기별 최대 40개 대기와 SDK transaction 재시도 최대 10회를 둔다. 정확히 일치하는 일시적 closed-transaction 오류만 제한 시간 내 새 transaction 한 번으로 복구한다. 원자성은 메모리 큐가 아니라 Firestore가 보장한다. 5분 복구 작업은 기한이 지난 PENDING 최대 50건만 처리한다. 손상 주문 하나는 예약을 보존하고 다른 주문 복구를 계속한다. 경고에는 개인정보를 남기지 않는다.

## 검증

- 실제 Firestore/세션 통합 14그룹: 중복 입출금/주문/체결, 원금·수익 회계, 고정 가격, 종료→재개, 예약 취소, 부족 발행량, 중복 매도, 커서, 권한/학적, 지연 task와 손상 주문 복구.
- 30학생×10개 독립 factory 부하: 접수/체결 최초 실패 0, 클라이언트 재시도 0, 원장·현금·예약·보유·발행량 일치. 최종 90 commits, 재시도 포함 transaction 읽기 2,611회, 쓰기 750회. 운영 지연 보장을 뜻하지 않는다.
- 실제 rules 7그룹 및 기존 성적 요청·리듬 공개·개발자 일지 회귀 통과. 최초 계좌 생성 구독, 타인 차단, 학적 이동, 세션 종료, 점검 bypass와 10문서 rules 예산을 검사했다.
- 학생 client: 중복 호출 공유, 응답 유실/aborted 후 동일 영수증·원래 quote, 확정 거절 후 새 quote, auth 경계, 늦은 응답 차단, 내역 커서.
- 학생/교사 브라우저 320/390/768/1280/1440px: 개장 버튼, 중지 blur/inert, 거래/내역, 공유 구독, 오류 재시도, 세션·오프라인 해제. 대기 61초 동안 추가 서버 조회/로컬 체결 0.
- 기본 build/Functions check와 준비 패키지의 실제 export 로딩·전체 파일 해시 검사. 증거는 로컬 output/wispi-access-20261115에 보관하며 운영 ZIP·인증 자료·학생 자료는 커밋하지 않는다.

재현: npm run test:wispi-trading, npm run test:wispi-access, npm run verify:wispi-client 및 scripts/verify-student-wispi-browser.mjs.

## 배포

기존 함수별 운영 ZIP을 대조해 관련 파일만 교체한 패키지를 배포한다. 미국의 학생 거래 10함수/기존 종목 5함수와 서울 executeCommand가 대상이다. 미국 executeWisCommandFast는 rebuild 명령을 받지 않음을 확인했으며 재배포하지 않는다. 기존 리전·메모리·인스턴스·환경을 보존한다. 복합 인덱스 2개만 추가하며 기존 인덱스를 삭제하지 않는다. 운영 성공·queue·도메인 최종 확인은 아래에 기록한다.

- 16개 대상 함수 ACTIVE 및 운영 ZIP 전체 파일 해시 일치. 기존 runtime 설정 보존 확인.
- Firestore rules 운영 release의 실제 소스가 검증한 파일과 동일함을 확인했다. CLI의 503/409 보고 뒤에도 실제 release를 다시 읽어 확인했으며 성공을 로그 문구로만 판단하지 않았다.
- 주문 복구/개인 내역 복합 인덱스 2개 READY.
- queue enqueuer와 worker invoker는 기존 프로젝트 서버 계정 하나로 제한했다. Firebase task `invoker`에 이 계정을 명시하여 이후 배포에서도 권한이 유지된다. 서버 계정이 자기 OIDC로 task를 보낼 수 있도록 해당 계정에만 serviceAccountUser를 부여했다.
- 존재하지 않는 고정 검증 주문 ID로 Cloud Tasks→worker 요청 HTTP 204 확인(학생 계좌·주문 생성/변경 0). 비로그인 학생 callable 5개는 401, worker 직접 호출은 403.
- 최종 학생 브라우저 12그룹, 교사 차트 회귀 25그룹, 학생 client 8그룹, build/Functions check 통과. 실제 체결은 에뮬레이터에서 검증했으며 운영 학생 잔액을 시험에 사용하지 않았다.

## AI 영향

런타임 AI 호출이나 외부 AI로의 학생·교과 자료 전송을 추가하지 않는다. 교사가 직접 개장/중지하고 정해진 서버 규칙으로 계산한다. 실제 학생 거래를 테스트로 생성하지 않는다.
