# 정기시험 분석·새로고침 개편 검토 기록

확인일: 2026-11-14 (Asia/Seoul)

이 문서는 이번 변경의 검증 근거와 서논술형 후속 설계 제안을 구분한다. 서논술형 분석·성찰 기능은 이번 변경의 구현 대상이 아니다. 운영 배포 확인은 문서 말미에 별도로 기록한다.

## 화면과 분석 연결

- 기본 하위 메뉴는 `점수 확인·운영`이며 기존 이의제기·업로드·서명 현황을 유지한다. `평가 분석`에 들어가기 전 분석 서버 조회는 없다.
- 정기시험 분석은 업로드 자료를 기존 `QuizAchievementAnalysis`의 데이터 형식으로 투영한다. 전체 분포·문항 통계·선지 분포·성취기준·학생별 추정 수준·S–P표·학급별 비교를 제공한다. 가져온 자료에 온라인 풀이 시간·답안 변경·성찰 기록이 없으면 이를 만들지 않는다.
- 두 XLSX의 모든 비어 있지 않은 시트를 읽는다. 문항정보의 동일 문항은 값이 같을 때만 합치고, 서로 다른 값·문항 누락·학생 학적/UID 중복·파싱 실패는 시트명을 포함한 오류로 처리한다. 첫 시트만 읽거나 오류 시트를 건너뛰지 않는다. `1반` 같은 시트명은 답안표에 반 열이 없을 때만 보완한다.
- 사용자가 확인한 방식은 기존 누적 모형이다. 모의고사 각 회차와 정기시험 선택형의 점수·해당 시험지 추정 분할점수를 100점으로 환산하고 평가마다 같은 비중으로 평균한다. 실제 시험일 이후의 모의고사, 다른 학기, 동명이인·학적 중복, 명시 UID 모순, 원시험지 메타데이터가 없는 결과를 합치지 않는다.
- 학년·반·번호·이름이 모두 일치하는 유일한 학생만 모의고사 자료에 연결한다. 유효 모의고사가 없으면 정기시험 선택형만으로 추정한다. 정기시험에 포함된 서논술형 총점을 선택형 배점으로 나누지 않는다.
- 원안지는 브라우저 PDF.js에서 처리한다. 정답 선지에 형광펜만 표시하고 체크표시를 넣지 않는다. 스캔/번호 중복/영역 불명확은 수동 확인으로 돌리며 드래그와 키보드 숫자 입력을 제공한다.
- 계정·인증 세대·학기가 바뀌면 이전 목록/학생/문항 팝업을 표시하지 않는다. 늦은 서버 응답은 폐기한다. 기존 공식 성적·서명·이의 처리 상태와 학생 공개 설정은 바꾸지 않는다.

## 새로고침과 브라우저 검증

새로고침은 공통 44px `RefreshButton`을 사용하며 해당 메뉴 서버 데이터만 재조회한다. 필터·검색·비교·회차·분석 보기·미저장 초안은 보존하고 중복 클릭을 차단한다. 실제 초기화 작업은 필터 해제 아이콘으로 구별한다. 평가 분석, 명단, 역사교실, 질문함, 위스·주문, 접속 설정, 윷 방 현황, 아바타 오류 복구를 점검했다.

- `verify-written-exam-analysis-browser.mjs`: 390/768/1440px의 7개 보고서(21화면), 넘침 없음, 제목 계산 배경 투명·그림자 없음, 첫 메뉴 분석 조회 0회, 보고서 전환 재조회 0회, 새로고침 list/load/mock 각각 1회, 학급·보고서 유지, 동일 tick 중복 클릭, 서버 오류 재시도, 실제 XLSX/PDF 파일 선택·크롭·저장, 키보드 영역 보정, 문항 이미지 실패복구·체크표시 없음·Escape 포커스 복원.
- 실제 XLSX 다중 시트 검사: 첫 빈 시트·문항정보 2개 시트·동일 문항 중복·답안 2개 학급을 합쳐 8문항/24명 저장. 충돌·누락·오류 시트·학생 중복·20MB 초과를 거부했다. 크롭 x/y=100으로 너비/높이가 0이 되는 입력도 차단했다.

- `verify-written-exam-paper-crop.mjs`, `verify-written-exam-paper-crop-browser.mjs`: 실제 한글 2쪽/2단/8문항 PDF, 벡터 그림 보존, 정답만 강조, 서술형 시작 제외, 스캔·번호중복·경계 모호성 회복.
- 기존 평가 분석·학급 분석·학생 명단·역사교실·질문함 브라우저 회귀와 `verify-refresh-contracts.mjs`의 실제 핸들러 검증을 통과했다.
- `verify-performance-score-contracts`, `verify-written-score-mobile-browser`: 수행·정기시험 10개 화면 크기에서 기존 서명 현황·점수 저장 계약·새로고침 오류·재시도를 확인했다. 늦은 명단·점수·설정 응답의 계정/학기 경계와 미저장 경고 문구 보존을 검토했다.
- `verify-refresh-avatar-browser.mjs`: 편집 모습/캐릭터/검색/보유·성별 필터 유지, 중복 클릭 조회 1회, 잔액·가격 갱신, 조회 실패 재시도 후 정상 썸네일 저장. 390/768/1280px 넘침·브라우저 오류 없음.
- 배포 전 원격 `1e706f2c` 위스 변경을 병합했다. 기존 신규 기능은 보존하고 주문 조회의 `{scope, view}` 경계와 거래 새로고침 Promise를 연결했다. 새 주식 화면도 선택 종목·미저장 입력을 보존하는 공용 새로고침을 사용한다. 통합 후 `verify-refresh-contracts`, `verify-wis-stocks-browser`(320~1440px), `verify-wis-wallet-browser`(390/768/1280px, 커서·선택·미사용 탭·identity 포함)를 통과했다.

위 검증은 합성 자료를 사용한다. 실제 학교 원본 XLSX/PDF는 이 작업에 첨부되지 않았다. 운영 학생 점수·서명·이의 상태를 시험 목적으로 수정하지 않는다. 외부 AI/OCR/에이전트 실행과 외부 데이터 전송을 추가하지 않는 기존 서비스 유지보수다.

## 분석 자료 저장과 권한

- Firestore 메타데이터: `years/{year}/semesters/{semester}/written_exam_analyses/{examId}`.
- 버전 상태: 같은 시험의 `revisions/{revision}`. `staging`과 `ready`를 구분한다.
- 학생 응답: `revisions/{revision}/classes/{grade-class}`. 학급 문서에는 해당 학급의 학생 응답만 저장한다.
- 원안지·페이지 이미지: Storage `years/{year}/semesters/{semester}/written_exam_analyses/{examId}/{revision}/{fileName}`.
- 메타데이터에는 평가명·시험일·학년·문항정보·학급 ID·학생 수·현재 버전·크롭 위치·파일 manifest를 넣는다. 학생 이름·응답 배열은 목록 메타데이터에 넣지 않는다.
- `examDate`는 `YYYY-MM-DD`로 검증한다. 입력 시험일과 업로드 시각을 구분한다.
- 분석 저장은 기존 점수 원장·학생 점수·확인 서명·이의제기·이전 답안지 확인 요청을 변경하지 않는다. legacy 경로를 읽는 fallback도 추가하지 않는다.
- 읽기는 기존 점수 관리와 동등한 교사/지정 관리자 및 application session·가입 승인·점검 fence를 적용한다. 학생 본인·타인, staff, 비로그인, 만료·철회 세션, 미승인 및 외부 이메일은 차단한다.
- 쓰기는 서버의 `site_settings/semester_active.semesterId`와 일치하는 학기로 제한한다. 교사의 과거 학기 읽기는 허용하지만 새 분석의 과거 학기 쓰기는 차단한다.
- 확정한 버전의 학급 문서와 파일은 수정하지 않는다. 새 버전으로 교체한다. 서버는 `ready` 상태의 학급·파일만 읽게 한다.
- 파일 읽기는 인증된 `getBlob(ref(...))`를 사용한다. `getDownloadURL`을 호출하거나 공개 다운로드 토큰 URL을 메타데이터에 저장하지 않는다. 이는 Storage 서비스 자체가 내부적으로 다운로드 토큰을 생성하지 않는다는 주장이 아니다.

## 저장 실패·재시도·동시 작업

1. 고유 revision을 만들어 작성자 소유의 `staging` 문서를 생성한다.
2. PDF와 페이지 파일을 모두 올린다.
3. 학급별 학생 응답을 batch로 저장한다.
4. transaction에서 기존 manifest의 revision과 `expectedRevision`을 비교한다.
5. 일치할 때 revision을 `ready`로 전환하고 manifest를 같은 transaction에서 교체한다.

파일·학급 쓰기가 실패하면 기존 manifest가 그대로 남는다. 미완료 revision은 읽기 화면에 나타나지 않는다. 실패한 작업에서 생성한 파일과 학급 문서는 가능한 범위에서 삭제하며, cleanup에 실패하면 staging marker를 남겨 상태를 식별한다.

transaction 응답만 유실된 경우에는 서버의 revision 상태와 manifest를 재조회한다. 이미 확정한 버전은 삭제하지 않고 성공 결과를 복구한다. 서버 상태를 확인하지 못한 경우에는 데이터를 보존하고 오류를 반환한다. 뒤에서 다른 작업이 확정한 버전을 오래된 화면의 저장으로 덮어쓰지 않는다.

과거의 확정 revision은 이 패치에서 삭제하지 않는다. 운영 보관·정리 기능이나 자동 만료 작업을 새로 추가하지 않았다.

## 조회·쓰기 범위와 비용 해석

| 동작 | 실제 클라이언트 요청 | 반환 문서 범위 |
| --- | --- | --- |
| 평가 목록 | 학기별 메타데이터 질의 1회, 학년 선택 시 서버 `where` | 조건에 맞는 평가 메타데이터만 |
| 선택 시험·한 학급 | 서버 `get` 2회 | 시험 메타데이터 1개 + 선택 학급 1개 |
| 선택 시험·학년 전체 | 메타데이터 `get` 1회 + 해당 revision의 학급 질의 1회 | 메타데이터 1개 + 그 시험의 모든 학급 |
| 선택 학급 새로고침 | 위 한 학급 조회 반복 | 선택 조건을 유지하며 두 문서를 서버에서 다시 읽음 |
| 문항 이미지 | 선택 파일의 인증된 bytes 요청 | 해당 페이지 파일만 |

학년 전체 분석에는 임의 `limit`을 넣지 않는다. manifest의 학급 목록·학생 수와 실제 반환 문서를 대조해 불완전한 자료를 오류로 처리한다. 스토어에는 별도 학생 응답 캐시·폴링·전체 학생 명단 조회가 없다. 매번 `getDocFromServer`/`getDocsFromServer`를 사용한다.

성공 저장의 기본 Firestore 쓰기는 학급 수를 C라 할 때 `C + 3`회다: staging 1개, 학급 C개, 최종 revision 상태와 manifest 2개다. transaction은 manifest 1개를 읽으며 충돌 시 SDK 재시도가 추가될 수 있다. 파일 F개는 Storage 업로드 F회다. 실패 복구에는 상태 확인과 staging 데이터 삭제 요청이 추가될 수 있다.

검사에서 기록한 조회 수는 앱 SDK가 실제로 요청·반환한 문서 수다. 보안 규칙의 종속 문서 읽기, 빈 질의의 최소 과금, 인덱스 읽기 및 transaction 재시도까지 포함한 청구서 측정값으로 보고하지 않는다. 메타데이터/응답 분리는 학생자료 전송을 줄이며, projection만으로 문서 읽기 건수가 줄었다고 주장하지 않는다.

## 입력·용량 제약

- 한 저장은 한 학년의 자료다. 중복 학생 key와 문항번호, 다른 학년, 문항정보에 없는 응답 번호를 차단한다.
- 문항은 1~200개, 학급은 최대 99개, 학급당 학생은 최대 150명이다. 해당 크기를 넘으면 조용히 자르지 않고 명시적 오류를 반환한다.
- 메타데이터와 학급 응답은 각각 약 800KB 이내로 검증해 Firestore 문서 크기 제한 전에 중단한다.
- 원안지는 PDF 1개·30MB 이하, 페이지는 PNG/WebP·페이지당 12MB 이하·최대 80페이지, 모든 파일 합계는 128MB 이하다.
- 파일 확장자·MIME type·크기·소유자·학기·시험·revision 경로를 확인한다. 규칙에는 해당 새 경로만 추가했으며 기존 경로의 권한은 변경하지 않았다.
- 외부 AI·OCR 서비스·런타임 에이전트 호출을 추가하지 않는다. 기존 Firebase에 정기시험 분석용 복사본을 저장하며 학생 공개 범위를 확대하지 않는다.

## 백엔드 검증 결과

검증 파일: `scripts/verify-written-exam-analysis-rules.mjs`.

전용 `demo-westory-written-analysis`의 Firestore `127.0.0.1:18228`, Storage `127.0.0.1:9298`에서 실제 스토어와 SDK를 연결해 **38개 검사 통과**.

- 메타데이터 목록에 학생 응답이 없으며 서버 질의 1회만 발생한다.
- 한 학급은 메타데이터 1개+학급 1개, 합성 2개 학급 전체는 메타데이터 1개+학급 2개를 반환한다.
- 선택 학급을 두 번 새로고침하면 정확히 네 문서를 다시 읽는다.
- 학급 쓰기 실패·재시도, PDF 업로드 성공 후 응답 유실·재시도, stale revision 저장 충돌, manifest commit 응답 유실 후 복구를 검증했다.
- 교사·관리자 허용, 학생 본인/타인·staff·미인증·세션 오류·가입 승인 오류·외부 이메일 차단을 확인했다.

## 성취수준 추정의 설명 경계

사용자 요청은 고정분할보다 추정분할을 사용하고, 실제 모의고사 기록이 있으면 활용하며 없으면 정기시험 자료를 기준으로 삼는 것이다. 모의고사는 정기시험 날짜 이후 기록을 섞지 않아야 한다. 다른 시험의 문항 원점수를 동일 척도로 간주하지 않고 각 시험에 명시된 기준과 적용 여부를 표시해야 한다.

현재 `achievementEstimates.ts`의 `westory-reference-2026-11-08`은 목표 성취수준·배점에 근거한 위스토리 가정모형이다. 목표수준에서의 약 65% 정답률을 참고점으로 사용하고 logistic 간격은 코드가 채택한 가정이다. 이는 관측 응답에 적합한 IRT 모형, 대학에서 검증한 공식 추정식, 경기도교육청의 공식 분할점수 산출식이 아니다. 목표수준이 빠졌을 때 난이도로 보완한 항목 수와 추정이라는 사실을 표시해야 한다. 이 문서는 실제 통합 UI의 완료 상태를 대신하지 않는다.

성찰의 성적 향상을 보장하지 않는다. [다강좌 원 연구](https://www.nsta.org/journal-college-science-teaching/journal-college-science-teaching-septemberoctober-2020/effect-exam)는 1,100명 이상의 자료에서 성찰 활동과 성적의 작은 양의 관계를 보고했지만 강좌별 운영 차이와 일반화의 한계가 있다. 대학 적용 사례를 곧바로 한국 중학생의 인과 효과로 표현하지 않는다.

### 권장 지표와 입력

- 문항: 평균·중앙값·표준편차, 평균 득점률, 실제 0점/부분점수/만점의 분포. 미채점·미응시·파일 누락은 0점과 분리한다.
- 평가 요소: 요소별 획득점수 합/대응 배점 합, 수행 수준별 인원, 학급별 비교. `2/3점`만으로 공식 성취수준을 지정하지 않는다.
- 성취기준: 연결된 문항의 배점과 득점, 증거 문항 수, 누락 상태. 한 문항으로만 측정한 기준은 해석의 제한을 표시한다.
- 변별: `corr(문항 부분점수, 그 문항을 제외한 총점)`. 표본 수와 분산 부족 등 산출 불가 사유를 제공한다.
- 채점 검토: 두 채점자의 정확 일치율·허용 차이 내 비율·평균 차이, 필요시 가중 κ·ICC. 검토 표시는 점수를 자동 변경하지 않는다.
- 신뢰도: Cronbach α는 문항 수와 측정 내용의 동질성을 고려한 보조 지표다. 논술 한두 문항에 자동 품질 등급을 붙이지 않는다. 다국면 Rasch·일반화가능도 이론은 충분한 문항·표본·복수 채점 설계를 마련한 이후의 확장안이다.

필수 추가 자료는 `문항 번호 / 평가 요소 ID·이름 / 배점 / 수준별 기준 / 성취기준 / 학생별 요소 점수 / 채점 상태`다. 원인별 진단에는 교사의 구조화한 오류 코드 또는 학생의 자기보고가 필요하다. 현재 `writtenExamEssayScoreWorkbook.ts`의 요소별 점수·배점·피드백·`scoreEntered`를 활용할 수 있지만, 기존 `quizAnalysis.ts`/`achievementAnalysis.ts`의 `correct: boolean`만으로 부분점수를 축약해서는 안 된다.

### 학생 성찰 흐름 제안

1. 교사가 루브릭·요소별 점수·피드백을 올리고 연결 정보를 확인한다.
2. 실제 점수와 승인된 안내문에 따라 강점·보완점·근거 문항·다시 볼 학습자료를 표시한다.
3. 학생이 `준비한 방법 / 놓친 이유 / 다시 쓴 설명 / 다음에 바꿀 행동 하나`를 입력한다.
4. 교사 화면에서 측정한 평가 결과와 학생의 자기보고를 구분해 집계한다.
5. 다음 평가 전에 계획을 다시 보여주고 같은 기준·비슷한 루브릭의 결과를 나란히 확인한다.

업로드 직후 자동으로 제공할 수 있는 것은 **평가 요약과 성찰 질문**이다. 학생의 실제 성찰은 입력 이후에만 생긴다. 기본 구현 순서는 부분점수·요소 통계, 성찰·재학습 연결, 복수 채점 검토 순서를 권한다. 외부 AI 전송과 자동 채점은 별도 검토·별도 승인 범위이며 이번 제안의 필수 조건이 아니다.
