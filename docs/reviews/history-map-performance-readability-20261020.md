# 역사 지도 이동·배율·설명창 개선

## 기준과 범위

- 시작 시 원격 main을 가져와 `180c6b3105b344f76b2c6f84e29f0a043083e3a3`로 fast-forward했다. 운영 `www.westory.kr`의 Vercel 배포 소스도 같은 커밋임을 확인했다.
- 배포 직전 추가된 공통 로딩 수정 `f49e4652`를 fast-forward로 반영했다. `DESIGN.md` 상단의 두 작업 기록을 모두 보존하고, 지도 코드에는 충돌이 없음을 확인했다.
- 학생·교사가 함께 사용하는 한국사/세계사 지도와 상세 설명 컴포넌트만 변경했다. 지구본에는 공유 설명창 구조만 적용했다. 역사 자료, 권한, 로그인, 학기, Firebase 함수·rules는 변경하지 않았다.
- 기존 미추적 `output/`는 보존하고 커밋에서 제외한다.

## 변경

- 지명 선택마다 투영을 다시 맞추던 경로를 제거하고 카메라만 이동한다. 장소·강·지역·국가 설명을 열 때 현재 지리 배율을 최소값으로 사용한다. 국가·지역의 선택 카메라와 배지는 동일한 고정 지리 앵커를 사용한다. 전체 보기와 지역 필터의 범위 탐색은 유지한다.
- 선택 애니메이션의 매 프레임 React 동기 렌더를 제거했다. 드래그·핀치·선택 이동은 이미 그린 SVG 표면을 합성 이동하고 지명 글자 크기는 유지한다. 종료 시 정밀 선·질감과 라벨 충돌을 한 번 갱신한다. 중간에 자료나 팝업 높이가 바뀌면 새로 렌더된 앵커를 기준으로 이어간다.
- 새 지형·투영을 준비하는 React 커밋 시간은 카메라 이동 시간에서 제외한다. 지역 필터가 새 지형을 표시한 직후 애니메이션의 절반 이상을 한 프레임에 건너뛰는 사례를 방지한다.
- 운영 확인 중 실제 카메라와 배율 숫자가 어긋나는 문제를 발견해 배율을 하나의 React 텍스트로 렌더한다. 제스처 중 직접 갱신한 텍스트가 종료 후에도 정상 동기화되며, 카메라 검사에서 표시 숫자와 실제 화면 변환 배율을 대조한다.
- 제목과 닫기 버튼을 고정하고 제목 아래 본문만 스크롤한다. 설명 본문은 16px/400/1.65와 동일한 왼쪽 정렬, 문단 8px·구역 16px 간격을 사용한다. 출처·소제목은 역할에 맞는 14px를 유지한다.
- 본문을 키보드로 초점 이동할 수 있는 명명된 영역으로 제공한다. 새 설명 선택 시 스크롤을 처음으로 돌리고 출처 내용과 펼침 동작을 보존한다. 로그인 공개 지도 미리보기의 기존 목록 스타일은 유지한다.

## 검증 기록

- `npm run build`: 타입 검사, 학기·학습지·사전·지도·엑셀 hair 테두리 검증을 포함하여 통과했다. 기존 대형 번들 경고는 남아 있다.
- `node scripts/verify-history-atlas-interactions.mjs`: 실제 제스처 28개, 선택 흐름 24개 통과. SVG 경로/패턴 재사용, 배율 유지, 직접 조작 이어받기, 취소·원복을 확인한다.
- `ATLAS_CAMERA_ONLY=flat node scripts/verify-history-map-camera.mjs`: 390/768/1280/1366px 평면 지도 20개 검사 통과, 브라우저 실행 오류 0개. 모든 선택/필터 이동에서 실제 보간 위치 4~5개를 관측했다. 직접 터치 이동, 핀치, 국가·강·섬 앵커, 강/국가 겹침, Home 복원을 확인했다. 긴 프레임은 별도로 기록했다.
- 운영 배율 표시 보완 후 1280px의 카메라 11개 검사를 다시 통과했다. 정지·이동·핀치·선택 후 표시 숫자가 실제 카메라 배율과 일치한다.
- `npm run verify:portal-design`: 학생·교사 320/390/768/1280/1366/1440px의 지도·탭·계층 탐색 및 교사 설정 화면 검사 통과. 지도 높이·가로 넘침·메뉴·키보드 계약을 유지한다.
- 팝업 별도 브라우저 검사: 390/768/1280px × 한국사/세계사/지구본 9개 조합에서 본문 스크롤·고정 제목·타이포·출처·선택 초기화 확인. 유지 가능한 회귀 검사는 `verify-history-map-ui.mjs`의 기존 흐름에 통합했다.
- 통합 팝업 검사에서 320/390/768px 흐름을 통과했고, 1280/1366/1440px 최종 실행은 11개 검사 모두 통과했다. 본문으로 Tab 이동, PageDown 스크롤, 제목 고정, 16px/26.4px 본문, 가로 넘침 없음, 선택 변경 시 스크롤 초기화를 확인했다. 데스크톱에서 짧은 설명이 모두 보이는 경우에는 불필요한 스크롤을 요구하지 않도록 검사 조건을 맞췄다.
- 수정 전 CPU 4배 제한의 선택 검사 33개 중 17개에서 배율 감소가 재현됐다. 지리 경계의 실제 화면 길이를 측정하므로 투영 변경까지 반영한다. 부분 수정 후 검사 18개에서는 배율 감소가 없었다.

증거는 `output/atlas-performance-20261020/`, `output/atlas-selection-performance-20261020/`, `output/atlas-popup-20261020/`에 저장한다. 데스크톱 Edge의 화면 크기·DPR·CPU 제한을 사용한 검사이며 실제 저사양 기기의 FPS를 보장하지 않는다. 병렬 검증 중 프레임 간격이 크게 흔들려 최초 카메라 샘플 수 검사가 실패했으므로 최종 카메라·성능 검사는 브라우저를 순차 실행한다.

카메라 검사는 DOM 변경 시각과 화면을 읽은 시각을 별도로 기록한다. 첫 지형 선택·확대의 래스터화에서 100ms 이상의 프레임 공백이 관측됐으며 이 지연까지 해소됐다고 보고하지 않는다. 네 개 이상의 보간 프레임 조건은 브라우저가 프레임을 제공한 경우에 적용하고, 긴 공백은 `delayedCameraFrames`에 별도로 남긴다. 실제 경과 시간 대비 위치 튐, 역행, 지형·표식의 변환 일치, 선택 이후 직접 조작 검사는 유지한다.

전체 카메라 스크립트의 별도 지구본 확대 프레임 수 조건은 이 환경에서 실패했다. 지구본 렌더러는 수정하지 않았으며 이번 평면 지도 변경의 카메라 검증은 `ATLAS_CAMERA_ONLY=flat`으로 분리한다. 기본 전체 검사와 지구본 전용 검사는 유지한다. 지구본의 공통 설명창은 별도 UI 검사로 검증했다.

## 단독 드래그 비교

다른 검증 브라우저와 빌드를 종료한 뒤 같은 PC·Edge 155·CPU 4배 제한·지형 표시 켬·60개 동일 드래그 입력으로 각 조건을 1회씩 순차 실행했다. 단일 측정이며 물리 기기의 입력 지연/전체 성능 보장은 아니다. 세부 프레임과 측정 조건은 `before-drag-solo.json`, `after-drag-solo.json`에 있다.
