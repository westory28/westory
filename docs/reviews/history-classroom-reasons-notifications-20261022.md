# 역사교실 사유·목록·결과 알림

## 원인과 수정

운영 현재 학기에서 삭제되지 않은 역사교실 원본 7개와 대응 평가 정의를 확인했다. 원본은 남아 있었으나 원본을 교체 저장하는 서버 분기가 기존 `createdAt`·`createdBy`를 다시 넣지 않아 생성 정보를 지웠다. 교사 화면도 저장 직후 아직 확정되지 않은 서버 시각을 목록 정렬에 사용하여 날짜 미정·목록 마지막으로 이동할 수 있었다. 서버는 기존 생성 정보를 보존하고, 화면은 기존 생성 일시와 저장 성공 후의 표시용 시각을 유지한다.

사유는 기존 선택지 뒤에 `직접 입력`을 둔다. 선택하면 학생 추가 행 또는 배정 학생 행 아래의 전체 가용 폭에 입력칸이 나타난다. 기존 자유 사유는 직접 입력으로 표시하고 보존하며, 빈 입력은 저장할 수 없고 일반 사유로 돌아가면 입력칸을 숨긴다. 기존 색상·간격·44px 조작 영역을 재사용한다.

교사 결과 알림은 과제 제목 없이 `학생 이름 학생이 역사교실을 정답률%로 통과했습니다.` 또는 `미통과했습니다.`로 만든다. 미통과 이벤트를 별도로 제공하며 교사·평가 권한자 수신, 이벤트별 설정, 중복 방지와 읽음 상태를 유지한다. 이미 저장된 표준 결과 알림도 목록과 실시간 알림에서 짧게 표시한다. 학생 배정·면제·자동 종료 문구는 유지한다.

## 운영 복구 범위

복구 도구는 명시한 현재 학기 원본 7개의 누락된 생성 일시·작성자만 복원한다. 최초 저장 감사 기록과 평가 정의를 대조하고, 검토한 계획 해시·학기 포인터·문서 버전을 다시 검사한다. 저장소 밖의 새 백업 파일을 만든 뒤 단일 transaction으로 적용한다. 원래 삭제한 1개는 제외하며 공개 여부, 삭제 상태, 자료 revision, 배정·답안·결과·보상·알림은 수정하지 않는다.

운영 `executeCommand`의 기존 배포 원본은 기준 커밋 `fbb5d8d7`과 LF 정규화 해시로 대조했다. 백엔드 배포 대상은 서울 `executeCommand` 하나이며 규칙과 다른 함수는 배포 대상이 아니다. 프론트엔드는 해당 커밋의 Vercel 배포를 운영 도메인으로 승격한다.

운영 함수의 event filter도 대조했다. 역사교실 원본 쓰기에 연결된 직접 또는 포괄 Firestore trigger가 없어 생성 정보 복구로 알림·공개·배정을 재생성하는 함수 경로는 없다.

## 검증

`npm run build`, `npm --prefix functions run check`, 생성 정보 복구 도구 검증, NotificationBell 목록·실시간 알림 검증, 변경 TSX·타입의 Prettier 및 `git diff --check`를 통과했다. 교사 브라우저 검증은 390·768·1024·1280·1366px에서 직접 입력 선택, 아래 행 너비, 한국어 조합·줄바꿈, 필수 입력, 기본 사유 전환, 저장·새로고침 후 사유·날짜 보존을 확인했다.

실제 canonical callable의 로컬 Firestore 통합 검증에서 통과·미통과, 저장된 과거 템플릿, 교사 수신 권한, 설정별 비활성, 재전송 중복 방지, transaction 실패, 알림 삭제 후 재생성 억제와 학기 경계도 통과했다. 공식 에뮬레이터의 한국어 ResourceBundle 오류는 해당 Java 프로세스에만 영문 locale 옵션을 지정해 검증했으며 운영 환경과 PC 언어는 변경하지 않았다.
