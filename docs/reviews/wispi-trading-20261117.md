기준은 `main`의 `f6770b706fdac92f8a4fac4e12050cf9d6dbebc5`다. 작업 전 원격 main과 같았으며 Vercel 운영 도메인의 배포 `dpl_GNeCaEvJ7gJQQ9eGRdUE3F7zF6nj`의 Git 소스도 같았다. 기존 `output/`, `tmp/`는 커밋 대상에서 제외했다.

## 거래 실패와 수정

- 학생이 최근 인증 유효 시간을 넘겨 정상 재인증을 마쳐도 주식 클라이언트가 재인증 전 `auth_time`을 검사해 매수·매도·취소·입출금을 전송 전에 차단했다. 같은 Firebase User 객체의 재인증 이후 경계를 사용하며 다른 계정과 응답 중 세션 변경은 계속 거절한다.
- 같은 사용자 객체·학기·명령은 첫 비동기 처리 전부터 요청을 공유한다. 재인증과 영수증 이관이 겹쳐도 새 주문 번호로 중복 전송하지 않는다. 응답 유실 시 원래 주문 번호·가격·시각으로 명시적 재시도하며 자동 주문은 없다.
- 계좌 미입금, 대기 주문 한도, 사라진 종목 등 서버의 확정 거절은 기존 견적을 폐기한다. 불확실한 오류의 영수증은 유지한다.
- 로컬 주문 폼은 동일 학생의 재인증 동안 선택 종목·수량·진행 상태를 보존한다. 자료 구독은 기존 로그인 세대·학기 경계를 유지하고 계정 변경 시 화면을 초기화한다.
- 종목의 일시 정지 기한이 지났을 때 한 번 화면을 갱신해 다음 시세 수신까지 주문 버튼이 계속 잠기는 문제를 막는다. 이 타이머는 서버를 조회하지 않으며 서버 거래 가능 여부를 대신 승인하지 않는다.

## 화면

[토스증권](https://www.tossinvest.com/)의 실제 PC·390px 화면을 확인했다. 종목명과 현재가·등락을 정렬하는 목록, 큰 현재가, 빨간 상승/파란 하락, 목록과 상세 탐색을 참고했다. Westory의 투명 제목·탭·필터, 공통 차트·도움말·알림을 유지했다.

PC는 목록과 차트·주문을 함께 표시하며 넓은 본문에서는 세 영역으로 나눈다. 좁은 본문은 목록 선택→상세→목록 복귀 흐름이다. 종목 검색과 전체/상승/하락 필터는 이미 받은 공개 자료 안에서 처리한다. 등락액·등락률은 한국 시간 전 거래일 마지막 관측(첫날은 첫 관측) 대비다. 실시간 시세가 필터 경계를 넘어도 입력 중인 주문 대상은 바뀌지 않는다. 종목이 제거되면 새 종목으로 자동 주문 대상을 바꾸지 않는다.

주문 전송은 비활성 버튼 대신 `주문 접수 중`으로 표시한다. 서버가 접수한 주문은 `주식 체결 중`과 서버 기한 기준 `남은 시간 N초`를 표시한다. 기한이 지나도 서버 체결 전에는 `체결 확인 중`이며 완료로 추정하지 않는다. 진행 주문은 모바일 목록으로 돌아와도 보인다. 대기 때문에 탐색/새 유효 주문을 막지 않으며 잔고·보유 수량·최소 단위 제한은 사유를 표시한다. 거래 조건은 제목 옆 i 도움말에서 확인한다.

## 조회·쓰기와 검증

- 최초 활성 화면: 기존 상태/시세/세션/본인 계좌 구독 4개, 본인 상태 callable 1회. 미사용 내역 조회 0회. 변경 응답을 재사용해 입금·주문 후 중복 상태 조회 0회.
- 초 단위 카운트다운·검색·필터의 추가 서버 읽기/쓰기 0회. 서버 계좌 revision 변경 때만 본인 상태를 한 번 갱신한다. 숨김·오프라인·계정/학기 변경 시 기존 구독 정리 계약 유지.
- 클라이언트 회귀 15개: 정상 재인증, 계정 전환, 전송 중 세션 변경, 동시 호출, 영수증 이관 경합, 오류·재시도와 원견적 보존.
- 실제 Firestore 에뮬레이터 거래 15개 그룹과 계산/계약 30개 테스트 통과. 30학생/10인스턴스 동시 매수에서 1건 경합 후 동일 요청 번호 재시도로 성공, 체결 재시도 0건. 현금·보유·예약·원장 일치.
- 실제 클라이언트/훅/화면과 합성 SDK를 사용한 브라우저 검증: 320/390/768/1280/1440px, 긴 종목명, computed style, 선택·수량 유지, 매수→매도, 초과 수량, 중복 클릭, 정확한 카운트다운, 조회 횟수, 취소·오류·유실 재시도, 실시간 공개 차단·세션·학기 경계.
- 실행: `npm run build`, `node scripts/verify-student-wispi-client.mjs`, `node scripts/verify-student-wispi-browser.mjs`, `npm run test:wispi-trading`. 스크린샷/검사 결과는 `output/wispi-trading-20261117/`, 서버 점검은 `output/wispi-trading-audit-20261117/`에 보관한다.

## 운영 조사와 범위

2026-11-17 조회 시 현재 학기 서버 집계는 체결 10건, 취소 1건, 대기 0건, 기한 초과 대기 0건이었다. 11월 16일 이후 해당 서비스 오류 로그 33건은 주문 HTTP400이었다. 요청 로그에는 상세 거절 이유가 없어 개별 학생의 실패 원인을 이 로그만으로 단정하지 않는다. 운영 주문·생성·체결 함수는 ACTIVE이고 핵심 소스 7개가 checkout과 일치했다. 조회는 해당 학기와 함수에 제한하고 학생 신원/개별 자산을 수집하지 않았다.

서버 거래 규칙·학생 공개·보유 자산·수수료·학기·권한·Functions/rules는 바꾸지 않는다. 기존 서비스의 주문 클라이언트와 화면 유지보수이며 런타임 AI 호출, 외부 AI 전송, 개인정보 수집/공개 범위 확대가 없다. 운영 학생 거래는 시험 목적으로 실행하지 않는다. 배포 대상은 Vercel main 프론트엔드다.
