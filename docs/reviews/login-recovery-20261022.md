# 모바일 웹앱 로그인 대기·복구 안정화 (2026-10-22)

## 신고와 확인 범위

아이폰과 갤럭시탭 웹앱에서 새 Google 로그인 후 처리 중 상태가 지속되고, 지연 안내 또는 다시 확인/다시 로그인 화면으로 돌아가는 문제가 보고됐다.

운영 `openApplicationSession`의 2026-10-22 KST 요청 101건을 읽기 전용으로 확인했다. HTTP POST 96건은 200, 5건은 401이었고 서버 처리 시간은 중앙값 0.70초, 95백분위 1.32초, 최대 1.66초였다. 이 기록으로 서버 콜드 스타트를 원인으로 단정하지 않는다. 기기에서의 저장소 초기화, OAuth 왕복, 스크립트 로드, 프로필 수신 및 앱 중단 시간은 이 서버 시간에 포함되지 않는다. 계정 식별자나 토큰을 검증 문서에 보관하지 않는다.

기존 코드를 실제로 결합한 재현에서는 프로필이 준비되어도 세션 응답이 30초 걸리면 다음과 같이 실패했다.

1. 새 로그인 후 15초에 시작 제한 시간이 끝나 정상 응답을 기다리던 시도를 폐기한다.
2. 다시 확인을 눌러도 기존 취소 불가 RPC를 먼저 기다리므로 새 요청이 시작되지 않는다.
3. 다음 15초도 지나 두 번째 시도가 실패하고, 뒤늦게 도착한 첫 정상 응답은 폐기된다.

설치된 Firebase SDK의 일반 callable 기본 제한은 70초였으므로 화면의 15초 제한과 불일치했다. `signInWithRedirect` 또한 탐색 후 완료하지 않는 Promise를 반환하므로 모바일에서 원래 문서가 숨겨져 유지되는 동안 계정 선택 시간이 네트워크 실패로 계산될 수 있었다.

## 변경

- 로그인 시작·저장소 대기·redirect 결과 대기의 제한을 공통 60초로 맞췄다. 실제 진행 화면이 켜져 있는 시간만 차감하며, `visibilitychange`와 `pagehide/pageshow`로 모바일 앱 중단·복귀를 처리한다. 재개 시 남은 시간을 보존하고 완료·취소 시 모든 타이머와 리스너를 정리한다.
- `openApplicationSession` RPC만 45초로 제한해 시작 예산 안에서 실제 통신 오류를 반환하도록 했다. 다른 읽기·저장 callable의 제한과 재전송 정책은 그대로다.
- 이미 폐기된 로그인 시도 또는 이전 인증 시각의 진행 중 요청은 새 시도를 막지 않는다. 살아 있는 같은 시도의 요청은 계속 공유·직렬화한다. 늦은 성공·실패가 새 세션 proof나 요청을 덮어쓰거나 무효화하지 못하는 경계를 검증했다.
- 서버가 확인한 프로필, 현재 Firebase 사용자, 인증 시각, 권한·등록 승인 및 서버 세션 검사는 그대로 유지한다. 쿠키/저장소를 삭제하거나 사용자를 일괄 로그아웃하지 않는다. 30일 기기 비활동 정책과 토큰·서버 만료 시간도 바꾸지 않는다.
- 실제 네트워크 오류는 다시 확인할 수 있는 오류로 남고, 계정 비활성화·권한 거부 등은 계속 차단한다. 로그인 복구를 위해 저장 작업을 자동 재실행하지 않는다.

## 검증

- 실제 시작 컨트롤러와 세션 어댑터 결합 11건: 교사·학생의 30초 정상 응답, 지연 프로필, 복구, 이전 성공·실패, 인증 시각 변경, 로그아웃, 캐시 프로필 제한. 기존 코드에서는 지연 응답 검사가 실패하는 것을 확인했다.
- foreground deadline 8건: 5분 백그라운드, 처음부터 숨겨진 앱, 지연된 숨김 이벤트, page cache 중단·복원, 반복 노출, 취소된 이전 시도, 동시 타이머 및 정리.
- 시작·프로필·계정 경계 95건, proof 재사용 20건, 로그인 acquisition 92건, redirect 복구 23건.
- 저장소 복원·차단 시 대체 저장 6건, 민감 작업 인증 18건, route gate 검사.
- 실제 React 화면을 합성 인증 서비스에 연결한 브라우저 검사 117건 통과, 브라우저 오류 0건. 390·768·1280px를 확인했으며, 390·768px에서는 redirect 응답이 30초 걸려도 학생 포털로 진행하는 경로를 추가했다. 이 검사는 실제 기기 OAuth를 대신하지 않는다.
- 새 결합·deadline 검사는 `npm run verify:auth-recovery`로 실행하며 `npm run build` 선행 검사에도 포함한다.
- `npm run build` 전체 통과. 타입·기기 세션·학기 보관·엑셀 원본 선·학습지·사전·지도 검사를 포함한다. 기존 대형 번들 경고는 남아 있으며 이번 로그인 패치에서 관련 없는 번들을 변경하지 않았다.

실제 아이폰/갤럭시탭의 설치 웹앱에 원격으로 접근할 수 없어 해당 기기의 Google 계정 선택부터 완료까지는 직접 재현하지 못했다. 브라우저 검증과 운영 확인 결과는 저장소 밖 `C:\evidence\login-recovery-20261022`에 기록한다. 기존 로그인 유지 검증만으로 새 OAuth 성공을 확인했다고 보고하지 않는다.

이번 패치는 프론트엔드만 바꾸며 Functions·rules·Firebase 인증 설정의 운영 배포는 필요하지 않다. 검증한 커밋을 Vercel Production으로 승격하고 `www.westory.kr` 연결과 로그인 복원을 확인한다.
