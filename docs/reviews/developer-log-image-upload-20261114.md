# 개발자 일지 이미지 게시 복구

## 관찰과 변경 범위

실제 아바타 콘테스트 글 작성에서 본문 문서는 생성됐으나 기존 Firebase Storage 직접 이미지 업로드는 `storage/unauthorized`로 거부됐다. 운영 Storage 규칙은 저장소 원본과 일치했고 개발자 이미지 허용 경로도 있었다. 구체적인 규칙 평가 실패 원인은 확정하지 않았다. 공유 규칙이나 접근 권한을 완화하지 않는다.

이미지는 기존 알림장 업로드와 같은 세션 증명 방식의 전용 callable `uploadDeveloperLogImageContent` / `deleteDeveloperLogImageContent`로 관리한다. 서버는 정확한 개발자 계정, 활성 앱 세션, 기존 점검·가입 정책을 검사한다. 720 KiB 미만·4096px 이하의 정지 WebP/PNG/JPEG만 실제 파일 형식과 전체 디코딩까지 확인한다. 서버가 파일명과 토큰을 생성하며 삭제는 `developer_log_images`의 허용 경로로 제한한다. 클라이언트 압축·원본 비율·700 KiB 상한은 유지한다.

신규 글은 문서 ID만 예약하고 모든 이미지 업로드가 끝난 뒤 한 번에 게시한다. 업로드가 실패하면 문서를 만들지 않고 입력·첨부를 보존하며 재시도에서 같은 예약 ID를 사용한다. 수정은 기존 문서를 갱신해 조회수·좋아요를 보존한다. 실제 운영에서 이미 생성된 콘테스트 글은 새로 만들지 않고 같은 글에 이미지를 보완한다.

## 검증과 운영 경계

- 실제 클라이언트 모듈의 합성 PNG 압축, 세션 연결, 서버 반환값, 계정 변경 차단과 오류 처리: `node scripts/verify-developer-log-image-client.mjs` (14개).
- 실제 페이지의 게시·수정·업로드 실패·재시도·동시 클릭: `node scripts/verify-developer-log-browser.mjs` (37개).
- 신규 서버 처리기 권한·파일 형식·경로·실패·삭제: `node functions/scripts/verify-developer-log-images.cjs`.
- 기본 앱 빌드 및 `npm --prefix functions run check`를 사용한다. 운영 원본 소스에서 새 진입점 2개만 분리해 배포하고 다른 함수·Storage/Firestore 규칙은 변경하지 않는다.
- 새 함수는 서울 리전, Node 22, 메모리 512 MiB, 동시성 4, 제한 시간 60초, 최소 0·최대 5개 인스턴스다. 배포 후 실제 소스 SHA와 설정을 확인한다.
- 테스트는 합성 이미지와 로컬 대역을 사용한다. 실제 업로드는 사용자가 요청한 콘테스트 포스터 한 장이며 학생 자료·접수·위스 지급을 테스트 목적으로 변경하지 않는다. 런타임 AI 호출이나 개인정보 외부 전송을 추가하지 않는다.

## 서버 배포 사후 확인

2026-11-14 신규 두 함수만 격리 배포했고 모두 ACTIVE 상태를 확인했다. 고정 generation으로 다시 받은 실제 소스 18개(각 함수 9개)의 SHA가 준비본 및 저장소 모듈과 일치했다. 서울 리전·Node 22·512MiB·동시성 4·제한 60초·최소 0·최대 5를 확인했다. 활성 Storage ruleset도 변경되지 않았다.

사전 운영 목록에는 다른 작업의 위스 함수 5개가 이미 DEPLOYING 상태였다. 사후 기존 소스가 존재한 159개 함수의 소스·자원은 동일했고, 그중 4개는 ACTIVE로 상태만 전환됐다. 당시 소스 없는 생성 중 항목이던 setWisStockMarketHalted는 별도 배포로 완성됐다. 이를 이번 변경으로 인한 대상 외 수정이나 전체 160개 불변으로 잘못 집계하지 않았다.

신규 서버 58개 검사는 원본과 격리 준비본에서 각각 통과했다. 정상 업로드의 이미지 저장은 1회이고 게시글 조회·쓰기는 0회다. 개발자 공통 점검 설정 조회 1회와 실제 세션 검사의 필수 읽기는 유지한다. 업로드 응답이 유실된 경우 자동 재시도는 없으며, 명시적 재시도는 새 UUID 파일을 만든다. 삭제는 이미 없는 파일을 성공으로 처리한다.

원본·준비본·배포 로그·사후 메타데이터·소스 검증 기록은 커밋하지 않는 output/developer-log-upload-20261114 경로에 보관한다. 서버 작업에서는 실제 운영 글·이미지·학생 자료·위스를 조회하거나 쓰지 않았다.
