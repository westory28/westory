# 모의고사 등록 및 응시 자료 준비 검토

기준 커밋: `8e2c01d71968f0ecbc79c20f3f864a2c51efe9c5` (`main`). 작업 전 원격 main과 일치했다. 운영 Vercel 원본 `d8bca8b475df93b530f605e7acbde7d9bcedde53`과의 차이는 출제 지침 문서 네 커밋이며 앱 소스 누락은 없었다.

## 변경과 영향

- 모의고사 등록 창에 우측 실시간 미리보기와 넓은 두 열 배치를 적용했다. 좁은 화면은 한 열로 이어지며 바깥 스크롤만 사용한다. 일반 진단·형성평가의 등록 창은 유지한다.
- 보기·공통 지문 세트·밑줄·빈칸 네모·클립보드 버튼을 제공한다. 편집 중 서버 쓰기는 없고 최종 저장 명령에서만 반영한다. 기존 세트 조회도 버튼을 누를 때만 수행한다.
- 세트 자료는 문항에 스냅샷으로 저장한다. 같은 회차·세트 ID는 동일 내용과 연속 번호를 서버에서 검증한다. 출제 후 과거 응시·제출 기록에는 변경이 전파되지 않는다.
- 학생 고정 회차 모의고사는 승인된 이미지와 글꼴을 준비한 뒤 서버 응시를 시작한다. 중복 이미지 제거, 최대 4개 동시 로드, 디코딩 완료 확인, 30초 제한과 재시도를 적용했다. 기존 응시의 시간은 연장하지 않는다.
- 공통 렌더러·서식 변경은 교사 미리보기, 학생 시험지·확대, 제출 결과에 함께 적용한다. 인증·학기·공개·학생별 권한·규칙·AI 호출·외부 데이터 전송 대상은 바꾸지 않았다. 기존 서비스 범위의 화면·자료 저장 유지보수다.

## 검증

- `npm run build`, `npm --prefix functions run check` 통과.
- 실제 교사 편집기 합성 브라우저 검사: 390/768/1280/1366px, 입력 중 조회·쓰기 0회, 실시간 미리보기, 보기·세트 연결, 저장 실패 후 재시도, 선지와 정답·이미지 동시 정렬, 읽기 전용, 24문항 전체 회차의 자동 페이지 배치.
- 학생 합성 브라우저 검사: 390/768/1280px, 느린 이미지 준비 중 응시 시작 0회, 실패 후 재시도, 출제본 변경, 기존 응시 복원, 시간 만료 제출, 재응시, 회전·키보드.
- 편집기 검사: 문서 모델 32개와 실제 브라우저 35개, 한글 조합·선택 복원·실행 취소·클립보드·기호 비노출·빈칸 너비.
- 일반 진단평가 등록 창도 390/768/1280px에서 모달 높이·본문 스크롤·하단 버튼 유지·모의고사 미리보기 미노출을 확인했다. 이미지 처리 요청의 완료 순서 역전·초기화·조회 범위 변경 등 14개 경계도 검사했다.
- 서버 자료·생명주기, 카탈로그 11개, 목록 페이징 14개 검사 통과. 운영 학생이나 문제 자료를 생성·변경하지 않았다.
- 구형 답안 빈칸 표기 안의 정답은 공개 지문과 사전 글꼴 목록에서 제거하며 기존 너비만 유지한다. 신규 빈칸 네모는 표시 기호와 실측 너비만 저장한다. 채점 원본·제출 후 기록은 유지하는 회귀 검사도 통과했다.
- 로컬 증거는 임시 폴더에 보관하며 공개 Git에는 합성 검사 코드와 검토 문서만 포함한다.

## 배포 범위와 확인 한계

운영 원본의 `executeCommand`, `getAssessmentState`, `getQuizEditorCatalog`, `getCommandStatus`, `saveAssessmentProgress` 관련 소스를 기준 HEAD와 대조했다. 줄바꿈을 정규화한 관련 모듈은 일치했다. 검토 해시는 `functions/productionGateway/source-manifest.json`에 기록했다. 실제 배포 대상은 변경 코드가 실행되는 서울 `executeCommand`, `getAssessmentState`, `getQuizEditorCatalog` 세 함수와 Vercel 프론트엔드다. Firestore·Storage 규칙은 변경하지 않는다.

실물 iOS/Android의 통신 속도를 측정한 검사는 아니다. 회차가 없는 과거 무작위 모의고사는 서버 출제 이후 자료를 준비하므로 기존 시간 시작 계약을 유지한다. 브라우저 도구에서 방재석 Chrome 프로필과 운영 탭 연결은 확인했으나 Esc 중단 신호 이후 사용자 브라우저 조작을 중단했다. 운영 화면의 로그인 후 수동 확인과 배포 파일·커밋 확인은 구분하여 보고한다.

## 팝업 높이와 독립 스크롤 후속 수정

`bfda56f4` 배포 후 사용자가 팝업 전체를 화면에 고정하고 작성·미리보기를 따로 스크롤하도록 요청했다. 이 요청은 위 초기 바깥 스크롤 배치를 대체한다. 팝업 높이와 가운데 그리드 행을 남은 화면 높이로 제한하고, 제목·저장 버튼을 제외한 두 영역에만 스크롤을 둔다. 1023px 이하에서는 같은 높이의 위·아래 영역으로 전환한다. 미리보기는 키보드로도 스크롤할 수 있다. 숨은 파일 입력의 절대 위치도 작성 영역 안에 묶어 바깥 스크롤을 만들지 않게 한다.

390×568, 390×900, 768×900, 1280×900, 1366×768, 1870×888에서 긴 지문을 입력한 실제 브라우저로 팝업 전체 경계, 상단·하단 고정, 양쪽 스크롤 위치 독립, 가로 넘침 없음, 키보드 이동을 검사했다. 기존 일반 평가 창과 최종 저장 때만 서버에 반영하는 검사도 유지했다. 변경은 교사 등록 창의 배치·접근성과 검사·지침에 한정하며 학생 러너, 저장 계약, Functions, rules, AI·외부 데이터 전송에는 영향이 없다.
