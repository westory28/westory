# 모의고사 누적 A–E 및 S–P 분석 개선

- 기준 checkout: `C:\westory`, main `7a9da91f6ac380a1f5d54dafa52d620a3767971a`.
- 사용자 요청: 회차별 누적 모의고사 점수로 수준을 분석하고 기존 진단·형성 분석 알고리즘을 제거한다. 사용자가 **시험지별 추정 분할점수** 적용을 선택했다.
- 같은 작업 공간의 시험지 조회 성능 개선과 공유한 `quizClassAnalysis.js`의 명부·문항 조회 변경은 보존한다. 공동 검증 후 최신 main 하나를 배포한다.

## 계산과 데이터 범위

1. 선택 회차까지 같은 학기·학생의 각 회차 최초 유효 제출만 한 번 반영한다. 재응시, 미래 회차, 다른 학생·학기 결과는 제외한다.
2. 회차별 실제 점수와 당시 시험지의 A/B·B/C·C/D·D/E 추정 경계를 100점으로 환산한 후 각각 동등 평균한다. 평균 점수가 충족하는 가장 높은 수준을 A–D로 분류하고 D/E 경계 미만은 E다. 표시 반올림 전 값으로 판정한다.
3. 기존 65% 앵커 및 0.8 간격의 시험지 분할점수 모형을 재사용한다. 현재 문제은행으로 과거 목표수준·난도·배점을 덮어쓰지 않는다. 목표수준 보완 여부를 표시한다. 공식 중학교 성취도 기준이나 성적 저장을 대체하지 않는다.
4. 실제 0점은 유효 점수다. 미응시는 평균에서 제외하고 부족 회차를 표시한다. 당시 시험지·가중치 일치가 확인되지 않으면 점수는 표시하되 수준은 미분류로 둔다. 시각이 같은 서로 다른 최초 결과는 추측하여 선택하지 않는다.
5. canonical 결과와 학기 하위 legacy 결과의 기존 호환·중복 제거를 유지한다. 과거 동일 문항 가중 점수에는 동일 가중 경계를, 배점 가중 점수에는 동결 배점 경계를 적용한다.

## 서버 읽기 및 폐기 범위

- 진단·형성·학습지 성취 근거 구성·압축, 교사 확인 프로필 조회, 진단·형성 기반 추정 알고리즘과 화면의 수동 수준 저장을 제거한다. 일반 진단·형성평가 응시와 원본 결과는 보존한다.
- 구 클라이언트의 `saveAchievementProfile`은 데이터 조회·쓰기 없이 폐기 오류를 반환한다. 기존 저장 프로필을 운영 데이터에서 일괄 삭제하지 않는다.
- 배포 전 열려 있던 클라이언트의 `compactEvidence: true` 요청은 새 응답을 잘못 읽지 않도록 분석 조회 전에 새로고침 안내 오류로 거부한다. 현재 클라이언트는 해당 플래그를 보내지 않는다. 구형 알고리즘을 복원하지 않으며 이 경로의 데이터 조회·쓰기 0을 검증했다.
- 선택 회차는 문항·선지·S–P 분석에 필요한 상세 자료를 읽는다. 이전 회차는 점수와 동결 출제 메타데이터만 읽고 원문·이미지·답안·행동 기록을 제외한다.
- 배점 복원이 꼭 필요한 가중 결과만 동일 응시의 `gradingSnapshot`을 필드 마스크로 읽는다. 학생·학기·정의·결과 연결·제출시각·source hash를 재검사하며 임의 자료로 보완하지 않는다.
- 기존 세션·교사 권한·현재 학기·학급 범위·읽기 상한·동시성 제한·조회 중 변경 감지를 유지한다. 신규 폴링·예약 작업·클라이언트 영구 학생 캐시는 없다.

## 운영 전체 학년 조회 보완

- `54f38d23` 운영 확인 중 학급 단위 조회는 정상이었으나, 3학년 전체 1회차 성취 분석이 반복된 동결 시험지 본문을 합산해 32 MiB 제한에 걸리는 것을 확인했다. 이 상태는 완료로 처리하지 않았다.
- `sourceHash`는 발문·이미지·목표수준 전체의 내용 해시가 아니므로 대표 학생의 시험지를 다른 학생에게 재사용하지 않는다. 각 응시의 실제 동결 내용을 확인해 완전히 동일한 문항만 메모리에서 공유하고, 기존 사전과 참조 형식으로 반환한다.
- 현재 회차의 큰 본문은 10개 문서씩 읽고, 32 MiB 보유량·8 MiB 응답 상한은 유지한다. 이전 회차는 기존 점수용 필드 마스크를 유지한다. 중복 본문의 메모리 보유·반환 표현을 줄이는 변경이며 Firestore의 원문 읽기 자체를 없애는 변경은 아니다.
- 설치된 Firestore SDK의 `DocumentSnapshot.data()`는 호출마다 필드를 다시 해석하므로, 결과당 한 번 해석한 값을 범위 검사와 본문 처리에 재사용한다. 소유자·학기·평가 범위 재검사는 그대로 유지한다.
- 보완 후 집중 회귀 57개 및 전체 `npm --prefix functions run check` 통과. 합성 80응시의 원문 36,919,109 bytes는 보유 자료 981,537 bytes로 처리되며, 32 MiB를 넘는 서로 다른 본문은 계속 거부한다. 동일 sourceHash의 서로 다른 발문·이미지·목표수준, 원점수·정답·동결 배점 및 문서당 한 번 해석을 검사했다.
- 독립 코드 검토에서 차단 결함 없음. 별도 demo Firestore의 실제 callable→분석 코어 통합 검사도 최신 소스로 다시 통과했다.
- 추가 경계 검토에 따라 누적 직렬화 원문 처리량(정규화 JSON 크기 추정)은 중복 여부와 무관하게 별도 256 MiB로 제한한다. Firestore 네트워크 전송량의 실측값은 아니다. 이는 최대 10,000건의 반복 자료가 보유량 상한만 통과해 계속 읽히는 것을 막는다. 상한 초과 시 일부 결과를 반환하지 않고 명시적으로 조회를 거부한다. 58개 집중 검사에서 공통 예산 객체 유무와 무관한 차단 및 뒤쪽 배치를 읽지 않는 동작까지 확인했다.
- 원문 처리량 상한을 포함한 최종 소스로 전체 Functions check를 다시 통과했다.
