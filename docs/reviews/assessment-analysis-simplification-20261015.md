# 평가 결과와 교사 분석 정리

## 표시 원칙

학생 결과는 평가명, 단원명, 도넛 점수, `정답 15문제 / 총 20문제` 형식의 정답 수, 이전 점수 비교, 답안 및 해설 보기, 다시 풀기를 표시한다. 이전 점수는 비교할 수 있는 실제 기록이 있을 때만 표시한다. 풀이 시간과 답안 선택·수정 기록은 결과와 마이페이지에서 노출하지 않는다. 서버의 응시 기록, 채점, 보상, 응시 제한은 유지한다.

교사 문제 은행과 학습 진단은 평가 분석으로 합친다. 단원·평가·학급 필터를 공유하고, 같은 평가의 점수 분포와 문항 정답률에서 학생·문항 상세로 이동한다. 원문과 선택 분포를 확인한 뒤 수정·파생 출제를 이어 갈 수 있다. 설명 문단, 임의의 위험 등급, 원시 시간값은 표시하지 않는다.

## 자료 검토와 적용

- [미국 IES, Using Student Achievement Data to Support Instructional Decision Making (2009), 권고 1](https://ies.ed.gov/ncee/WWC/Docs/PracticeGuide/dddm_pg_092909.pdf): 데이터를 해석하고 수업 변경을 시도한 뒤 후속 결과를 확인하는 반복 과정을 제안한다. 이를 참고해 그래프에서 실제 오답·문항 원문·수정으로 이어지도록 구성했다. 이 권고의 인과적 효과에 대한 근거 수준은 낮으며, 특정 대시보드가 학습 향상을 보장한다는 뜻은 아니다.
- [University of Washington, Understanding Item Analyses](https://www.washington.edu/assessment/scanning-scoring/scoring/reports/item-analysis/): 단일 정답 문항의 정답 비율, 선택지별 인원·비율은 문항과 수업 내용을 검토하는 자료다. 이를 문항 정답률·선지 분포에 적용한다. 오답 선택 하나만으로 학생의 오개념이나 능력을 확정하지 않는다. 현재의 반복 연습 문제 은행에 일반적인 변별도·신뢰도 임계값을 그대로 적용하지 않는다.
- [Alfredo 외, Designing a Human-centred Learning Analytics Dashboard In-use (2024)](https://learning-analytics.info/index.php/JLA/article/view/8487): 간호교육 교사 5명의 사용 경험에서 시각화 세부 정보를 줄여 이해를 돕는 변화가 관찰됐다. 이는 역사 수업의 효과 검증은 아니지만, 교사 요구에 따라 불필요한 세부 정보를 줄이는 설계에 참고했다.

## 집계 계약

- 단원·평가 종류·회차·학기를 구분한다. 서로 다른 평가를 한 점수 분포로 합치지 않는다.
- 점수 분포와 평균에는 학생별 최근 제출 한 건을 사용한다. 실제 0점과 점수 기록 없음은 구분한다.
- 서버 결과와 기존 로그는 명시적인 연결 정보로 중복을 제거한다. 이름이 같거나 제출 시각이 비슷하다는 이유로 서로 다른 학생을 합치지 않는다.
- 문항 통계는 학생별 최근 응답을 사용하고 현재 문항의 버전과 일치하는 기록만 집계한다. 버전을 확인할 수 없거나 수정 전인 응답은 현재 정답률·선지 분포의 분모에서 제외한다.
- 정답률은 실제 집계 인원과 함께 표시한다. 반복 응시 수를 학생 수로 표시하지 않는다.
- 수집 범위가 제한되거나 일부 조회가 실패하면 전체 통계인 것처럼 표시하지 않는다. 미확인 기록을 0점·미응시로 바꾸지 않는다.
- 답안 선택 시간·수정·풀이 기록은 기존 서버에 학생/응시/문항과 함께 저장한다. 화면을 간소화해도 수집을 끄지 않는다. 속도만으로 학생 수준이나 찍기를 판정하지 않는다.

## 변경 범위

프론트엔드 결과 표시, 교사 분석 화면, 순수 집계 함수가 대상이다. 서술형 출제와 AI API는 도입하지 않는다. 기존 서버 결과에 필요한 데이터가 있으므로 이번 후속 작업에서는 백엔드 저장 구조를 변경하지 않는다.

## 검증

- `npm run verify:quiz-analysis`: 27개 합성 시나리오. 명시 ref 중복 제거, 학기·학급·회차 분리, 0점과 누락, 문항 버전, 최신 응답, 실제 교사 데이터 어댑터 및 과거 원문·해설 보존을 검증한다.
- `npm run verify:student-quiz-result`: 도넛 점수, 명시적 정답 수, 점수 비교, 재응시·답안 연결 등 33개 검사.
- `node scripts/verify-mypage-assessment.mjs`: 실제 기록 정규화·원문·점수·중복 구분 등 25개 검사.
- 기존 telemetry, 응시 안전성, 파생 출제 10개, 시각 편집기 26개 회귀 검사 통과.
- 학생 브라우저 검증: 390·768·1280px에서 결과 표시와 가로 넘침을 확인했다. 실제 `QuizRunner`를 사용하는 격리된 합성 환경에서 0/7·1/7 제출, 다시 풀기, 답안 이동을 확인했다. 운영 학생 기록을 생성하지 않았다.
- 교사 브라우저 검증: 390·768·1280px에서 가로 넘침과 그래프 기준선을 확인했다. 학년이 다른 같은 반의 분리, 학생 당시 원문→현재 문항→수정→파생, 수정 후 이전 버전 통계 제외, 빈 상태, 조회 오류·키보드 재시도, 읽기 전용 화면의 수정·파생 버튼 제외를 확인했다.
- `npm run build`와 `npm run format:check` 통과. 빌드에 포함된 수행평가 원본 XLSX 점선(`hair`) 회귀 검사도 통과했다. 최신 지도·역사교실 운영 변경을 병합해 배포 기준에 포함했다.
- 운영에서 현재 학기에 없는 평가를 검증용으로 만들지 않는다. 실제 학생 제출에 대한 운영 쓰기 검증과 합성 검증을 구분한다.

## 결과·풀이·문항 등록 후속 개선

- 학생 풀이 화면은 중첩된 카드·뱃지·굵은 테두리를 줄이고, 넓은 화면의 자료/답안 두 열과 좁은 화면의 세로 흐름을 유지한다. 선택한 답은 번호·배경·왼쪽 선으로 구별한다. 힌트는 문제 우측 상단의 작은 버튼에서 열고 닫으며, 다시 열어도 추가 횟수를 차감하지 않는다.
- 결과는 176px 도넛과 점수, 명시적인 정답 수를 중심으로 정리했다. 비교는 동일 학생·학기·평가의 바로 이전 유효 제출을 사용한다. 출제 원본 해시가 같거나 문항별 버전이 모두 일치해야 한다. 원본 변경, 시각 누락·동률, 조회 실패, 비교 기록 없음은 비교 문구를 생략한다. 점수 차이를 학습 능력 향상으로 단정하지 않는다.
- 기존 마이페이지와 동일한 학생/학기 조회 조건을 사용하며, 비교 조회는 제출 성공 후 비동기로 진행한다. 조회 실패가 제출·채점·결과 버튼을 막지 않는다. 서버 및 보안 규칙 변경은 없다.
- 교사 등록 창의 떠다니는 `자료의 본문을 입력하세요.` 안내와 해당 가상 요소를 제거했다. 제목과 하단 작업 버튼은 고정하고 본문만 스크롤한다. 입력 라벨, 보기 번호 정답 선택, 미리보기 포커스, 모바일 보기 편집 배치를 정리했다. 짧은 발문에 생기던 2px 내부 스크롤도 제거했다.
- `npm run verify:quiz-score-comparison`: 실제 0점, 상승·하락·동일 점수, 학기/평가 분리, 중복 제거, 원본 버전 및 조회 실패 등 14개 시나리오 통과. canonical client 12개, release, telemetry, 응시 안전성, 파생 출제 10개, 시각 편집기 26개 검사도 통과했다.
- 반응형 QA는 브라우저 안 iframe의 실제 뷰포트 320·390·768·1280px로 수행했다. 학생 결과/풀이의 가로 넘침, 힌트 열기·닫기·재열기, 키보드 다음 문제, 0점 제출 후 재응시 14점 및 이전 0점 비교를 확인했다. 학생 데이터와 제출은 모두 격리된 합성 환경이다.
- 교사 합성 환경에서 모바일 등록, 밑줄 서식, 정답 선택, 미리보기, 등록 성공, 연결형 입력, Escape 닫기와 등록 버튼 포커스 복귀를 확인했다. 마지막 수정 후 짧은 발문의 clientHeight/scrollHeight는 모두 42px이며 불필요한 내부 스크롤이 없다.
