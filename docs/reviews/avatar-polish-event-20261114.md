# 아바타 품질 보완과 1회 소개 이벤트

## 범위

기존 아바타 상점·옷장·개별 관리 구조를 유지한다. 카드 높이, 교사 판매/성별 배지, 성별 선택·착용 제한, 짧은 검색 입력, 종류 순서, 장식 하위 분류를 보완했다. 용신중 하복의 흰색/남색 카라를 수정하고 애쉬 보울·애쉬 몽실·꽃리본 단발 헤어와 선글라스를 추가했다. 총 117개이며 기존 아이템 ID와 구매 기록은 보존한다.

학생은 옷장에서 저장한 아바타와 300자 이내 소개를 한 번만 보낼 수 있다. **최종 사용자 정정은 자동 지급이 아니라 교사 확인 후 `보상 지급하기`로 100위스 지급**이다. 운영 설정에서 접수 여부와 지급액을 관리하며 접수 당시 금액을 보존한다. 이전 질문 접수와 별도로 동작한다.

## 상태·권한·통신

- 기존 공부의 神문고 public 문서 구독을 공유한다. 옷장 진입에는 참여 상태를 추가 조회하지 않으며 버튼을 열 때 본인 마커와 해당 접수만 읽는다. 계정·학기 전환 시 컴포넌트를 폐기한다.
- 서버가 현재 학생의 저장된 아바타 이미지·모습·revision을 읽는다. 브라우저가 보상액·학생 ID·이미지 URL을 지정할 수 없다. 이미지 캡처용 추가 업로드가 없다.
- UID 해시 기반 전역 마커로 학기·기기·requestId를 바꾸어도 한 계정은 한 번만 접수한다. 기존 접수의 이미지는 이후 아바타 저장에서도 보존한다. 계정 삭제 시 이미지를 제거하고 최소 참여 tombstone만 유지한다.
- 접수는 질문·마커·영수증을 원자적으로 기록하며 지갑은 쓰지 않는다. 교사 지급은 현재 학기·학생 계정·정규 위스 계좌를 확인하고 원장·잔액·순위·경제 합계·마커·질문·영수증을 한 트랜잭션에 반영한다. 재시도와 동시 클릭은 지급 한 번으로 수렴한다.
- 알림 off, 비경합 성공 기준 접수 18읽기·3쓰기, 지급 21읽기·8쓰기다. 무변경 설정과 중복 접수/지급은 쓰기 0이다. 경합 테스트의 staged 쓰기 횟수는 실제 커밋 수와 구분한다. 선택한 접수의 상세만 이미지로 표시하며 학생 공개 스토리에 이미지를 자동 노출하지 않는다.
- 버전 충돌 시 소개를 유지한 채 아바타를 다시 읽을 수 있다. 열린 접수창의 보상 안내는 기존 공개 구독의 최신 금액을 반영한다. 네트워크 실패의 명시적 재시도는 같은 요청 ID를 사용한다.
- 런타임 AI 호출이나 학생 자료의 외부 AI 전송은 추가하지 않았다. 공지 이미지만 가상의 캐릭터로 제작했다. 기존 서비스·접근 역할을 유지하는 내부 기능이며, 외부 서비스/저장 위치/학생 간 공개 범위는 확대하지 않는다.

## 검증

- 52,920개 의상 조합, 6,552개 머리 장식 조합, 신규 헤어/피부/포즈 96개. 전시 프리뷰 231개.
- 학생/교사 320·390·768·1280px: 동일 카드 높이, 성별 차단, 필터/페이지 변경 추가 조회 0, 장식 하위 분류, 수정 팝업, 전체 학생 미리보기.
- 학생 이벤트: 진입 추가 조회 0, 공유 listener 1, 조회 실패/접수 실패/중복 클릭/계정 전환/실시간 마감/보상 금액 변경/아바타 버전 충돌 복구.
- 교사 이벤트: 기존 설정 기본값 false/100, 무변경 저장 0, 저장 실패 재시도, 보상 응답 유실·재시도 1회 지급, 타 학생 접수 노출 0, 공개 이미지 자동 게시 0.
- Functions 단위 61개와 실제 Firestore 에뮬레이터 21개(이벤트 9개 포함), 20동시 접수·20동시 지급, 학기 변경·위조·권한·원자적 실패 롤백을 확인했다. 실제 학생의 접수나 위스 잔액은 검증 목적으로 변경하지 않는다.
- 전체 앱 빌드와 Functions check를 통과했다. 병행 main 변경 통합 후 최종 빌드를 다시 확인한다. 세부 산출물은 `output/avatar-polish-20261114/`에 둔다.

## 운영 반영

운영 원본 소스와 런타임 설정을 보존한 격리 배포본을 사용한다. 기존 아바타/위스 projection 12개와 신문고 2개, 계정 삭제 cleanup 1개만 선택 배포한다. 루트 Functions 전체 배포·rules·index 배포는 하지 않는다. Vercel 검증 커밋을 운영 도메인에 연결한 뒤 실제 교사 화면과 학생 미리보기를 확인한다. 이벤트를 100위스로 열고 요청받은 이미지 공지를 추가한다. 배포 결과는 확인 후 기록한다.
