# 미니미 세대 교체: 서버와 기존 선택 정리

## 계약

- 카탈로그는 version 2, 가격 정책은 version 3이다. 41개 항목은 `minimi-슬롯-이름`이라는 새 ID를 사용하며 구 ID를 저장·구매 요청에 허용하지 않는다. 각 선택값은 `mm-`로 구분하고 character의 girl/boy만 타입으로 유지한다.
- 용신중 학교복 6개는 무료다. 일반 상의 2개는 160위스, 일반 하의 2개는 100위스이며 다른 항목은 기본 무료다. 기존 양수 의류 가격 정책과 교사 가격 설정 권한은 유지한다. 남성 캐릭터의 치마 선택·저장을 거절한다.
- 구 보관함은 읽을 때 기존 선택·보유품·이미지를 전부 끊는다. revision만 충돌 검사에 사용하며 조회 시 자동 저장하지 않는다. 기본 미니미 값에 썸네일이나 갱신 플래그를 붙이지 않으므로 학생에게 기존 선택이 있는 것으로 표시하지 않는다.
- 신규 요청 키에는 카탈로그 버전을 포함한다. 구 영수증을 새 요청의 결과로 돌려주지 않으며 과거 구매 영수증·위스 원장·잔액·감사 기록을 보존한다. 새 썸네일은 v2 경로, nearest 리사이즈, 무손실 WebP, 64KiB 상한을 사용한다.
- 계정 삭제 시 해당 사용자의 해시 경로 안에 있는 v1/v2 이미지를 모두 정리한다. 기존 삭제 잠금·재시도·타인 경로 차단은 유지한다.

## 운영 정리 도구

`functions/scripts/reset-retired-avatars.cjs`는 기본 dry-run이다. 적용 시 `--apply --backup <저장소 밖의 새 비공개 폴더>`를 사용한다. 백업 기록을 디스크에 기록·동기화한 뒤 삭제하며 Storage 원본은 세대 번호를 지정해 백업하고 동일 세대 조건으로 삭제한다. 경합이 있으면 새 이미지를 지우지 않고 실패 건수로 남긴다. 재실행은 새 백업 폴더를 사용한다.

백업 경계는 가장 가까운 기존 상위 폴더의 realpath와 새 하위 경로를 합쳐 판정하고 폴더 생성 후 다시 확인한다. 저장소 내부의 `..avatar-backup` 같은 이름이나 외부 junction으로 저장소를 가리키는 경로는 허용하지 않는다. 실제 Windows junction을 포함한 별도 경로 회귀 검사도 통과했다.

보관함 두 컬렉션은 필요한 버전 필드만 100개씩 커서로 조사한다. 공개 복제는 `users`에서 `avatar != null` 서버 필터와 avatar/role projection을 사용하므로 아바타 없는 사용자는 읽지 않는다. 버전 없는 구형 공개 복제와 보관함 없는 고아 복제도 처리한다. 실제 갱신 transaction에서 선택·revision·공개 복제를 다시 읽으며 새 버전의 선택을 보존한다. 보관함의 구 선택과 소유품을 초기화하고 공개 avatar 필드만 제거한다. 이모지·학적·성적·계좌는 수정하지 않는다.

2026-11-11 운영 dry-run 결과는 보관함 26개, 공개 복제 26개, 구 이미지 32개(818,748바이트), 가격표 변경 대상 0개, 쓰기 0개다. SDK 문서 스냅샷 조회는 105개다. 이는 청구 읽기 건수와 같지 않으며 빈 query의 최소 읽기 비용이나 별도 인덱스 읽기를 포함하지 않는다. field projection은 전송량을 줄일 뿐 문서 읽기 건수를 줄이는 것으로 계산하지 않는다. 백업이나 실제 학생 식별자를 저장소에 포함하지 않는다.

## 검증

- `npm --prefix functions run check` 전체 통과. 아바타 관련 단위 44개는 가격·중복 구매·불충분 잔액·권한·구 영수증·구 선택 단절·저장 실패 복구·픽셀 색/알파의 완전 보존·이미지 한도·교사 격리를 포함한다.
- 후속 백업 경계 검사 1개는 실제 파일·junction으로 검증했고 Functions check에도 연결했다. 아바타 검증은 총 45개다.
- 실제 Firestore 에뮬레이터 11흐름 통과. 중복 구매 4개 동시 요청의 차감 1회, 저장의 공개/비공개 원자성, 직접 쓰기·타인 읽기 거절, 정리의 반복 실행, 새 선택 보존, 버전 없는 고아 공개 복제, 백업 실패 시 무변경을 확인했다.
- 조회·무료 선택은 쓰기 0회, 이미 산 품목의 새 요청은 추가 쓰기·영수증 0회다. 통합 스튜디오 조회는 사용자·신원·아바타·가격표 각각 한 번 읽으며 아바타 세대 교체에 새 폴링·런타임 AI·외부 전송을 추가하지 않는다.
- 초기 에뮬레이터 종료 후 기존 websocket 포트가 남아 재실행이 실패했다. 다른 전용 포트로 재실행한 최종 로그가 통과 근거다. 사용자 데이터나 운영 계정은 시험 입력으로 사용하지 않았다.

로컬 증거는 `output/avatar-minimi-20261111/`의 functions-check.log, avatar-emulator.log, migration-dry-run.json 및 release-audit/staged-verification.json에 있다.

## 격리 배포 준비

현재 운영 14개 리전별 함수의 메타데이터와 원본 ZIP을 받아 대조했다. 원본이 다른 함수는 세 그룹으로 분리했다. 준비 도구는 `scripts/prepare-avatar-minimi-release.mjs`이며 운영 반영을 직접 실행하지 않는다.

- 아바타·순위 10개: catalog/helper/pricing/studentAvatar 4파일 변경, 다른 208파일 SHA 보존. 이 네 파일은 작업 기준 HEAD와 운영 원본이 일치했다.
- 가격 조회·저장 2개: catalog/helper/pricing 3파일 변경, 다른 209파일 SHA 보존.
- 계정 삭제 2개: 운영 studentAvatar의 이미지 정리 한 줄만 v1/v2 루프로 변경, 다른 176파일 SHA 보존.

원본 index·export·package·lockfile·runtime·권한 정책을 유지하며 모든 대상의 실제 export를 확인했다. getWisEconomyState의 서울·미국 양 리전을 유지한다. 각 격리본에서 새 저장·가격·구/신 이미지 삭제 검사를 통과했다. 배포 명령은 `release-audit/prepared-release.json`에 있다. 운영 배포와 실데이터 정리는 별도 실행 단계이며 이 문서의 준비 검증만으로 운영 반영 완료를 뜻하지 않는다.

사후에는 각 함수의 메타데이터를 `release-audit/post-deploy/metadata/<함수>--<리전>.json`, 새 원본을 `post-deploy/sources/<함수>--<리전>/`에 저장하고 `node scripts/verify-avatar-minimi-deployment.mjs`를 실행한다. ACTIVE·리전별 runtime/자원/서비스 계정/이벤트 권한과 모든 보존·변경 파일 SHA를 비교한다.
