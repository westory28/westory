# 아바타 상점·옷장 분리와 한복 확장

## 변경 범위

- 학생 구매는 `위스 상점 → 아바타 상점`, 착용·저장은 `마이페이지 → 아바타 옷장`으로 분리했다. 옷장은 보유품과 무료품을 표시한다. 기존 `menu=avatar` 주소는 옷장으로 유지하며 `menu=wardrobe`도 같은 권한으로 정규화한다.
- 관리자 상품 관리는 위스 상점 하위로 이동했다. 기존 설정 링크는 새 위치로 이동한다. 관리자 판별과 서버의 교사 권한 검사를 보존한다.
- 상점 전체/보유/유료/무료와 성별은 위스 순위의 작은 배지 표현을 사용한다. 검색은 종류 탭 오른쪽에 두고 좁은 컨테이너에서 돋보기로 펼친다. Escape 또는 돋보기를 다시 누르면 해제한다. 상점·옷장은 18개 단위 숫자 페이지를 사용한다.
- 상점의 보기 조작은 `현재 모습`만 남기며 착용 저장은 옷장에서 한다. 관리 카드 하단은 `수정 / 저장`, 수정 팝업은 큰 아이템 이미지와 이름/성별·판매 방식·가격/설명의 3행 폼이다. 입력 초안은 팝업을 닫아도 남고 카드 저장으로 확정한다.
- 상단 `학생 미리보기`는 실제 학생 상점 컴포넌트를 사용한다. 현재 초안을 보여 주되 합성 어댑터와 UI·함수 양쪽 가드로 구매와 저장을 막는다.

## 그림과 데이터 호환

한복 26종(상의 8, 하의 6, 신발 4, 머리장식 8)을 더해 총 113개다. 원본 게임 이미지 파일은 사용하지 않고 기존 픽셀 렌더러의 관절·몸 좌표에 맞춰 제작했다. 모자의 헤어 가림, 긴옷·치마의 발목 범위와 소매 연결을 검사했다. 정적 프리뷰는 223장, 총 109,428바이트다. 기존 카탈로그 버전 2·가격 정책 3·ID·구매 기록·위스 잔액은 유지한다.

## 공개·조회·저장 계약

상점 진입은 일반 포인트 본문을 마운트하지 않으며 아바타·가격·지갑의 기존 단일 조회를 사용한다. 옷장에서는 마이페이지의 프로필/등급/성적 조회를 시작하지 않는다. 필터·검색·페이지 이동과 관리자 미리보기는 추가 서버 조회를 만들지 않는다.

새 `avatar_shop` 공개키를 메뉴 설정과 원자적으로 저장한다. 구매는 기존 `mypage/avatar` 검사와 상점 공개 검사를 모두 통과해야 한다. 새 키가 있으면 기존 config 1회만 읽으며, 이전 설정은 실제 메뉴 문서 1회를 추가 조회해 부모·일반 상점·아바타 상점 숨김을 확인한다. 이 fallback을 위해 운영 설정을 임의 수정하지 않는다. 비공개 구매와 재시도는 영수증·소유권·잔액에 쓰기 0회이며 보유품 옷장 조회/저장은 유지한다.

AI 호출·외부 AI 전송·개인정보 항목·공개 범위 확대는 없다. 실제 학생·위스 자료를 시험 목적으로 변경하지 않는다.

## 검증

- 기본 빌드, Functions check, TypeScript 포맷 및 diff 공백 검사.
- 실제 학생 컴포넌트의 219개 선택/정적 이미지, 320·390·768·1280px, 검색 펼침·키보드 해제·필터·두 목록 페이지·미보유 제외·구매 후 옷장·오류 재시도.
- 관리자 320·390·768·1280·1366px, 3행 수정 팝업, 카드별 저장, 전체 학생 미리보기 쓰기 차단, 초안·충돌 복구 및 교사 옷장 수명주기.
- 메뉴/레거시/공개/역할/추가 query/미사용 본문 미마운트 18개 시나리오. 공개키 클라이언트·서버 회귀와 전용 Firestore 에뮬레이터 13개 통합 시나리오 및 점수 요청 rules 회귀.
- 전신 조합 45,360개, 머리장식 조합 5,184개, 하의·신발 조합 5,460개, 단독 프리뷰 독립성 198개, 피부 누출 144개와 실제 한복 착용 시트.
- 공통 포털 회귀에서 기존 HEAD에서도 발생하는 SettingsAccess 로딩→빈목록 portal 제거 오류를 확인했다. 빈목록 텍스트에 span 한 겹을 추가해 React 자식 교체 충돌을 해결했다. 권한·조회 로직은 변경하지 않았다. 검사 하네스에는 기존 ThinkCloud 폰트/문구와 새 옷장·상점 탐색 기대값을 반영했다.

증거는 `output/avatar-wardrobe-20261114`, `output/avatar-hanbok-20261114`에 보관하며 커밋에서 제외한다.

## 배포 범위

작업 중 들어온 위스 main `1e706f2c`를 통합해 순위·지갑·상품 운영 변경을 보존했다. Firebase는 운영 generation을 고정한 원본 세 그룹으로 준비한다. pricing/projection은 카탈로그만, avatar 그룹은 카탈로그와 구매 공개 검사만 바꾼다. 최신 위스 조회 소스, index, 의존성, 리전·메모리·동시성·최소/최대 인스턴스를 보존한다. 12개 대상의 사후 source hash와 runtime을 확인하며, 프론트엔드는 Vercel main 배포 성공·운영 승격·실제 화면 반영까지 확인한다.
