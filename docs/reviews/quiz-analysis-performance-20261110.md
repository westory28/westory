# 평가 분석 조회 최적화와 점진 표시

## 범위

교사 평가 분석의 학년 전체 모의고사 조회, 긴 학생 목록, 문항 원문 팝업을 개선한다. 학생 포털·성적·제출 답안·학적·권한 정책은 변경하지 않는다. 기존 교사 세션·활성 학기·현재 학급 검사를 유지하는 통상 유지보수이며 AI 호출이나 외부 서비스 전송은 추가하지 않는다.

## 조회 계약

- 새 클라이언트는 `analysisProjection: compact-v1`을 협상한다. 기존 클라이언트는 원문 포함 계약을 유지한다. 통계 대상 학생·응시·회차는 생략하지 않는다.
- 서버 전용 `quiz_achievement_result_views`는 원본 경로의 SHA-256 key, Firestore updateTime의 초·나노초, 학기·소유자·평가 범위, 내용 해시를 검증한다. 원본 버전이 정확히 같은 통계 자료만 사용한다. `sourceHash`만 같은 별도 원문을 합치지 않는다.
- 트리거가 전달한 원본으로 작은 자료를 생성하므로 원본 추가 조회가 없다. 중복·역순 이벤트는 쓰지 않으며 삭제는 개인정보 없는 tombstone으로 바꾼다. 파생 자료 갱신 실패가 기존 live cursor·학생별 결과 무효화를 막지 않는다.
- 조회 중 파생 자료를 쓰지 않는다. 없거나 손상되거나 오래된 자료만 해당 원본의 필요한 필드를 읽고 복구한다. 버전이 도중에 바뀌면 재조회 오류로 종료한다. 원문 fallback은 최대 10개 문서씩 2개 요청만 병행한다.
- 과거 원문의 식별 해시는 축약 전에 산출한다. 채점 정정도 축약 전에 검증한다. 학기·권한 경계는 서버 요청마다 검사하며 브라우저 요청 병합은 계정·세션·조회 범위별이다.
- 파생 자료의 `rawCompact`는 검색 인덱스에서 제외해 불필요한 인덱스 기록을 줄인다. 문서 ID로만 조회하며 클라이언트 직접 접근은 기존 default deny에 의해 차단된다.
- 빈 legacy 단원은 필드 없는 존재 확인 한 번으로 판별하여 학생별 여러 별칭 조회를 생략한다. legacy 자료가 있으면 기존 모든 소유자 별칭을 유지한다. 답안 복구는 정확히 결합된 submission의 검증 필드와 answers만 조회한다.
- 문항 팝업은 선택 결과의 현재 소속·학기·평가·회차·정확한 원본 버전을 다시 검사하고 선택 문항 하나만 반환한다. 다른 문제은행으로 대체하지 않으며 원문에 유효한 채점 정정을 반영한다.

필드 선택은 전송량을 줄이며 Firestore 문서 읽기 수 자체를 줄이는 것으로 계산하지 않는다. 파생 자료의 저장·트리거 비용은 결과 변경당 최대 한 문서이며, 정상 조회에서는 파생 문서가 원본 본문 조회를 대체한다.

## UI 계약

평가 분석의 S–P 표·회차별 점수·성취수준·분할점수와 일반 학생 목록은 30명씩 더보기로 표시한다. 전체 자료로 계산한 통계·분모는 변하지 않으며 더보기에 서버 호출은 없다. 이름은 학적이 확인될 때 `이학무(30922)` 형식으로 표시한다. 원문은 오답 노트와 같은 renderer를 사용하는 dialog에서 열고 닫는다. 초기 원문 요청은 0회, 클릭 시 1회다.

## 검증과 운영 측정

- 서버 회귀: 정상 파생 자료에서 원문 본문 0회, 누락·구버전·손상 자료만 단건 fallback, 동시 변경 차단, legacy 호환, 팝업 범위·정정·미보관 검사.
- 파생 자료: 원문별 버전 구별, 정정 검증, 10문서/2동시 제한, 중복·역순·삭제 이벤트, 갱신 실패 시 기존 cursor 보존, backfill dry-run·재실행·동시 변경 차단.
- 클라이언트와 브라우저: 65명 30→60→65 표시, 독립 목록·정렬 초기화, 전체 분모 유지, 원문 오류·재시도·미보관·닫기·계정 및 범위 변경 응답 폐기, 390/768/1280px, 동작 줄이기 그래프 재생.
- 변경 전 같은 로컬 네트워크·서비스 코드·운영 범위(2026-2, 3학년, 초시) 측정: 317명/288결과, 총 46,747ms, 결과 원본 처리 137,363,579bytes, 브라우저 응답 892,143bytes. 이는 로컬에서 서버 서비스를 실행한 비교 측정이며 실제 운영 callable 응답 시간과 구분한다.

변경 후 같은 비교 측정은 18,546ms(약 60% 단축), 원본 본문 fallback 0건·파생 자료 288건 적중, 파생 자료 입력 5,023,459bytes, 브라우저 응답 243,711bytes(약 73% 감소)였다. 학생 317명·결과 288건을 유지했다. 목록 query RPC는 142→77회, getAll RPC는 43→15회였으며, RPC 수와 문서 읽기 과금은 구분한다. 측정 도구가 수집한 반환 문서는 2,011→1,999개로, 큰 감소는 원문 전송·처리량과 빈 legacy 조회 제거에서 발생했다.

운영 backfill은 dry-run 뒤 288건 모두 변환했고 원본은 수정하지 않았다. 충돌·오류 0건이었다. `rawCompact` 인덱스 제외 작업은 SUCCESSFUL로 완료했다. 서울의 조회 함수와 canonical/legacy 결과 트리거만 선택 배포한다.

최종 관련 서버 검사 95개, client 계약, 390/768/1280 성취분석 브라우저와 일반 평가 분석 전체 브라우저 검사를 통과했다. 다른 작업의 미커밋 LoadingOverlay 변경이 같은 파일에 있었으므로 해당 변경은 그대로 남기고, HEAD와 이번 패치만 합친 별도 스냅샷에서 전체 브라우저 검사와 빌드를 수행했다. 원문 누락 학생 다음의 동일 시험지에서 보관된 문항을 찾아 여는 경우도 검증했다. 기본 Functions check와 포맷 검사도 통과했다. 배포·운영 UI 확인의 상세 증빙은 `output/quiz-analysis-performance-20261110/`에 학생 원문·식별자를 제외하고 기록한다.
