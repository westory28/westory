## 학생 경험과 보존

- 전체 시험지를 가용 폭에 맞춰 표시하고 문항을 선택하면 자료·선지를 확대한다. 어절 단위 줄바꿈과 이미지 실패 재시도, 키보드 포커스·Escape·닫기 복귀를 제공한다. 문항은 단·쪽 경계에서 잘리지 않는다.
- 터치 가로 화면에서는 윷놀이의 고정 작업면 원리를 역방향으로 적용하여 세로 시험지를 CSS 회전한다. 실제 기기 방향을 바꾸면 복귀하며 입력 키보드에 의한 높이 축소는 회전으로 오인하지 않는다. 데스크톱은 회전하지 않는다.
- 모든 문항에서 돌아갈 수 있는 하단 제출 동작과 미응답 확인을 사용한다. 기존 자동 저장·학기·소유자·세션·마감 시간·revision·영수증 재시도 계약을 유지한다.
- 제출 성공 응답의 판정만 문항 번호순 빨간 원·빗금으로 표시한다. reduced motion에서는 즉시 표시한다. 첫 장 우측 상단은 100점 환산 점수이며 원배점 합계와 구분한다. 점수를 클라이언트에서 채점하거나 운영 결과를 다시 쓰지 않는다.
- 진단·형성평가의 기존 러너와 채점 방식은 유지한다. 마이페이지는 저장 당시 원문·내 답·정답·배점만 표시하고 과거 누락 원문을 현재 문제은행으로 대신 채우지 않는다.

## 출제·서버 계약

직접 출제·JSON 입력·회차별 공개 준비·배점 채점은 [출제 절차](../runbooks/mock-exam-papers.md)와 [기록 연결 검증](mock-exam-history-20261106.md)을 따른다. 패치 작성 문항은 교사용 JSON 산출물을 통해 같은 검증·미리보기·저장 경로로 넣는다. 정답을 공개 JavaScript 번들에 넣지 않는다. 이번 패치로 실제 시험 문항을 운영에 등록하거나 새 공개 대상을 지정하지 않았다.

회차·문항 순서·배점·쪽 나누기를 응시 스냅샷에 저장한다. 고정 시험지는 해당 회차 전체 문항이며 타 회차를 섞지 않는다. 객관식은 5선지와 길이/가나다 정렬, 단답형은 기존 20자 상한을 적용한다. 논술형의 교사 수동 채점이나 AI 채점은 이 패치에 추가하지 않았다. 서버 `score/total`의 정답 개수 의미를 유지하며 `percent`는 배점 비율, `earnedPoints/maxPoints`는 원배점이다. 새 시험지 점수는 소수 둘째 자리까지 보존한다. 학생 통계와 교사 분석이 `score/total`로 배점 점수를 덮어쓰지 않는 회귀를 검사했다.

스냅샷은 문항당 96KiB·전체 500KiB를 넘으면 누락 저장 대신 응시 시작을 거절한다. 교사 작성 단계는 더 작은 92KiB/480KiB 한도로 검사한다. HTTPS 이미지 URL은 참조 값이 보존되며 외부 파일 자체의 불변성을 보장하지 않으므로 내용이 바뀌지 않는 자료 경로를 사용한다.

권한·Firestore/Storage rules·개인정보 항목·AI 호출·외부 AI 전송은 추가하지 않았다. 기존 승인 범위의 평가 유지보수이며 기관 승인·면제 상태를 새로 단정하지 않는다. 실제 학생 자료·시험 점수·서명·이의 처리 상태를 운영 검증에 사용하거나 변경하지 않는다.

## 검증과 배포 경계

로컬 전체 빌드·포맷·Functions 전체 검사, 회차별 서버/클라이언트 원본 해시, 기존 채점·점수 비교·분석 회귀를 수행한다. 합성 브라우저 검사는 390/768/1280px의 교사 출제·학생 풀이·마이페이지, 가로 터치 회전, 입력 키보드 높이 모사, 긴 자료, 16문항 두 단 구성, 새로고침 복원, 미응답 확인, 저장 실패·재시도, 배점 결과를 포함한다. 실물 iOS/Android 검증으로 표현하지 않는다.

운영 `executeCommand`의 배포 closure 57개가 동기화한 원격의 파일과 일치함을 확인했다. 이전 로컬 기준과 달랐던 `historyClassroomExemptions.js`를 최신 상태로 보존했다. `getCommandStatus`는 이전 lifecycle/면제 처리 배포, `getAssessmentState`는 이전 조회 배포였으며 최신 운영 command closure 기준으로 공통 의존성을 대조했다. source-manifest 해시를 병합 후 다시 검증했다.

Firebase 배포 대상은 `executeCommand`, `getCommandStatus`, `getAssessmentState`, `saveAssessmentProgress`, `getQuizEditorCatalog`, `getQuizClassAnalysis`, `getMyQuizHistory` 일곱 함수다. Functions Node 22와 `FUNCTIONS_DISCOVERY_TIMEOUT=60`을 사용한다. 프론트엔드는 GitHub main의 해당 커밋을 Vercel westory에서 검증·승격하고 `www.westory.kr`에서 확인한다. 운영 확인은 Chrome `방재석` 프로필의 교사 화면에서 읽기만 수행한다.

회사 PC는 GitHub 원격과 맞춘다. 집 PC는 현재 연결 목록에 없어 로컬 checkout을 직접 검증할 수 없다. 집에서 미커밋 변경이 없는 `main`임을 확인한 뒤 `git fetch origin --prune`과 `git merge --ff-only origin/main`으로 같은 커밋을 받는다. 이미 배포한 서버를 PC 동기화만을 이유로 재배포하지 않는다.
