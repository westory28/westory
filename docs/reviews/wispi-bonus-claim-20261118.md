# 위스피 지원금 직접 받기와 지갑 표시

## 범위와 기준

- 기준 checkout은 `C:\westory`, `main`의 `f871706426aed7c787c83581317eae7f0a2c15a7`이며 시작 시 원격과 일치했다. 기존 `output/`, `tmp/`는 보존했다.
- 사용자 정정에 따라 **기존 누적 500위스 입금 기준을 유지**한다. 사진의 100위스 입금은 지급 조건 미충족이며, 100위스로 기준을 낮추거나 운영 계정을 대신 입금·수령 처리하지 않는다.
- 앞선 지원금 계좌 조회 권한 복구는 사용자가 실제 화면에서 정상 표시를 확인했다. 이번 변경은 지급 시점과 지갑 조작 배치, 학생 학습 도구의 배경 흐림이다.

## 지급과 조회

입금은 입금액만 반영한다. 지갑의 `500위스 받기`를 누르면 현재 학생·학기·세션·학적·점검·위스피 공개 상태를 서버에서 확인하고 지급한다. 기존 캠페인 ID와 계정별 전역 영수증을 유지해 과거 자동 지급, 다른 요청 ID, 동시 실행, 다른 학기의 재수령을 차단한다. 지급은 계좌·거래 내역·영수증·투자 집계를 같은 트랜잭션에 기록한다. 지원금 원금 출금 제한과 손실 회복 후 수익 출금 규칙은 유지한다. 과거 운영자 자동 지급 helper는 즉시 거부한다.

지원금 조건은 지갑을 연 경우에만 조회하며 숨긴 탭이나 오프라인에서는 새 요청을 보내지 않는다. 현재 계정·세션·학기·계좌 revision을 경계로 상태를 폐기하고, 실패 후 재시도와 응답 유실 시 같은 요청 ID 복구를 유지한다. 추가 폴링은 없다.

서버 조회는 본인 `DEPOSIT` 이력으로 필터하고 필요한 필드만 선택한다. 정상 이력의 최소 단위가 1위스이므로 최대 500개면 지급 자격을 완전하게 판정할 수 있다. 반환 입금액은 500에서 상한을 둔 조건 충족 표시이며 평생 총입금액 통계가 아니다. 필드 선택은 전송량만 줄이며 읽기 건수 감소로 계산하지 않는다.

## 화면

입금·출금 선택과 도움말, 위스 금액 입력, 실행 버튼을 같은 form 행에 둔다. 넓은 화면은 한 행, 작은 화면은 필요한 만큼 줄바꿈한다. 상단 가능 금액은 입금·출금 선택에 따라 서버의 해당 가능 금액으로 전환하고 다음 입금 시간은 유지한다. 제목과 지원금 라벨은 배경 카드 없이 표시한다.

봉차트의 하락 몸통에 흰색을 덮어쓰던 CSS만 제거해 기존 파란색을 내부까지 채운다. 교사 종목·지수·기획 봉차트에 적용되며 학생 기본 선차트와 관측 기록·가격 계산은 변경하지 않는다.

학생 학습 도구의 기존 scrim에 `backdrop-filter: blur(4px)`와 Safari 접두 속성을 추가한다. 메뉴와 실행 버튼은 위 레이어에서 선명하게 유지하며 Escape·바깥 클릭으로 닫으면 흐림이 사라진다. 학생 전용 controller에서만 쓰는 CSS이므로 교사 플로팅 메모와 공통 페이지 레이아웃은 영향이 없다.

기존 서비스의 통상 유지보수다. 이용자·개인정보 항목·외부 서비스·공개 범위 확대, 런타임 AI 호출·에이전트 실행·외부 데이터 전송 변경이 없다. 운영 검증으로 학생 잔액·거래·점수·서명·이의 상태를 변경하지 않는다.

## 검증과 운영 절차

- 캠페인 단위 검사 5개와 실제 Firestore 에뮬레이터 15그룹에서 499/500 경계·분할/이전 학기 입금·권한·과거 수령·동시/재시도·제한 회계·졸업 회귀를 확인했다.
- 합성 두 입금의 수령 트랜잭션은 21읽기/6쓰기, 중복 수령은 17읽기/0쓰기다. 각 callable 공통 세션 검사 3읽기는 별도이며, 실제 재시도 횟수도 검증 결과에 기록한다.
- 실제 학생 학습 도구 컴포넌트와 합성 배경 본문으로 390/768/1280px 화면을 확인했다. 계산 스타일은 배경 `blur(4px)`, 메뉴·버튼 `filter: none`이며 Escape·바깥 클릭 후 scrim 제거를 확인했다. 운영 자료 조회·쓰기는 0건이다.

- 클라이언트 22항목, 전체 위스피 브라우저 27항목, 지원금 지갑 브라우저 12항목이 통과했다. 320/390/768/1280/1440px에서 PC 동일 행·모바일 줄바꿈·상단 가능 금액 전환·키보드·오류/재시도·계정/세션/학기/숨김 경계를 확인했다. 시장에서 지원금 조회 0회, 중복 클릭 명령 1회, 수령 직후 추가 자격 조회 0회, 일반 위스 갱신 알림 0회를 확인했다.
- 봉차트 기존 브라우저 검사가 320/390/768/1280/1440px에서 통과했다. 실제 하락 몸통의 파란색 채움, 교사 종목/지수/가상 시세, 학생 기본 선차트·키보드/터치·OHLC 보존을 확인했다.
- 포맷·diff 검사와 전체 `npm run build`가 통과했다. 기존 대형 번들 경고만 남아 있다.

## 서버 운영 반영 결과

CLI의 설정·서비스 ID·결제 설정 조회에서 응답 전 연결 오류가 반복됐다. 결제 활성 상태와 정상 조회 응답을 확인하고, 인증서 검증을 유지한 TLS 1.2·IPv4 우선·시스템 CA 설정으로 변경 함수만 재시도했다. `transferStudentWisStock` 업데이트와 신규 두 함수 생성이 모두 성공했고 `firebase functions:list`에서도 us-central1 / Node 22 / 2세대 함수를 확인했다.

배포 후 세 함수 각각의 고정 generation ZIP 전체 261파일이 준비본과 일치했다. 실행 자원·기존 함수 환경·호출 IAM과 scheduler·task queue·정산 함수 소스는 보존됐다. 신규 확인 함수에서 선택 환경값 `FUNCTION_SIGNATURE_TYPE`만 생략되어 [Functions Framework의 공식 HTTP 기본값](https://github.com/GoogleCloudPlatform/functions-framework#specification-summary)으로 비교했다. 기존 함수 검사는 엄격하게 유지하고 신규 함수도 빈 값·다른 signature·다른 환경 차이는 허용하지 않는다. 운영 환경을 맞추기 위한 별도 수정은 하지 않았다.

운영의 신규 두 endpoint에 인증 없는 요청을 보내 각각 HTTP 401 / `SESSION_AUTH_REQUIRED`를 확인했다. 실제 학생 지급 요청은 실행하지 않았다. 준비본 patchSet SHA-256은 `4b70b3c7ad61639c5ce9d51d0df475895a58acefa008d269d524cc14b8b90804`이며 `verification-post-deploy.json`에 함수별 revision·generation·확인 시각을 기록했다.
