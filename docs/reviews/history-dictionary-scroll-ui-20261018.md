# 사전 스크롤 탐색 UI 검증 (2026-10-18)

## 변경 범위

- 학생·교사·수업 중 사전이 공유하는 초성 필터를 64px 단일 열 sticky 색인으로 변경했다.
- 숫자·영문 펼치기와 클릭·키보드는 유지하며, 포인터를 누른 채 움직이면 해당 글자를 연속 선택한다.
- 화면과 대화상자의 실제 가용 높이에 맞춰 색인 높이를 제한하고 끝부분에서 자동 스크롤한다.
- 기본 사전의 단어·뜻을 기존 `ws-surface` 흰 배경·1px 테두리 안에 배치했다. 학생 단어장과 교사 등록 목록도 흰 배경과 테두리를 유지한다.
- 검색창과 다섯 분류 선택을 넓은 화면 한 줄, 좁은 화면 두 줄로 배치했다. 작은 태그 배지와 12px 출처 글자는 유지한다.
- 데이터·권한·저장 API·Firebase rules는 변경하지 않았다.

## 자동 검증

- `npm run verify:history-dictionary`: 통과. 2,373개 표제어, 118개 분류, 교차 필터·초성·조회 세션·계약 검증을 포함한다.
- `verify-history-dictionary-initial-drag.mjs`: 실제 컨트롤러에 EventTarget 기반 포인터 이벤트를 전달해 mouse/touch 경로, 캡처, 중복 클릭 억제, 키보드, 그룹 펼치기, 스크롤 끝 도달, viewport/dialog 교집합, 첫 화면 높이 제한, resize/scroll/observer 정리, 취소·비활성화·unmount를 검증한다. 기존 initials 검증과 기본 빌드에 연결했다.
- 변경된 TypeScript/TSX의 Prettier 검사와 `git diff --check`: 통과.
- 최신 `origin/main`(`820c2c6`)을 병합한 상태에서 `npm run build`: 통과. TypeScript, 수행평가 XLSX 테두리, 수업자료, 지도, 사전 회귀와 Vite 번들을 포함한다.

## 브라우저 검증

실제 React 컴포넌트를 `scripts/preview-history-dictionary.mjs`의 메모리 자료로 실행하고 승인된 CUA 브라우저로 조작했다. 운영 학생 자료는 수정하지 않았다.

| 화면 폭 | 검색·필터 줄 수 | 초성 폭 | 본문 배경 / 테두리 | 문서 가로 넘침 |
| --- | --- | --- | --- | --- |
| 320px | 2 | 64px | 흰색 / 1px | 없음 |
| 390px | 2 | 64px | 흰색 / 1px | 없음 |
| 768px | 2 | 64px | 흰색 / 1px | 없음 |
| 1280px | 1 | 64px | 흰색 / 1px | 없음 |
| 1440px | 1 | 64px | 흰색 / 1px | 없음 |

- 교사 기본 사전에서 문서를 800px 스크롤한 뒤 색인의 top=80px을 확인했다. ㄱ→ㅁ 드래그 후 `ㅁ · 141개`, 첫 단어 `마그데부르크`, 색인과 결과 top=80px을 확인했다.
- 390px 화면에서 ㄱ부터 아래쪽으로 드래그해 `ㅈ · 137개`로 이동했다. 하단을 누른 동작에서는 색인 자체의 scrollTop이 47px 증가하고 다음 글자 ㅋ로 바뀌었다.
- 숫자 펼치기에서 0–9 열 개를 확인하고 Enter로 4를 선택해 `4군`을 표시했다. 영문 펼치기에서 a–z 26개와 z 선택 후 빈 결과를 확인했다.
- 존재하지 않는 단어 검색 → 0개/빈 결과 → 전체 단어 보기로 초기화했다.
- 떠 있는 사전에서 본문 스크롤 후 초성을 선택하면 결과 처음이 다시 보인다. 대화상자 본문의 viewport 위치를 포함해 판단하며 헤더 뒤에 결과가 가려지지 않는다.
- 학생 단어장 목록에서 흰 배경, 1px 테두리, 저장된 단어 표시를 확인했다.
- 손가락 입력은 포인터 이벤트 회귀로 검증했고 실브라우저에서는 마우스 드래그를 사용했다. 실제 모바일 기기에서 직접 터치한 검증은 아니다.

## 독립 리뷰

읽기 전용 리뷰에서 발견한 대화상자 스크롤 좌표와 필터 행 추가 후 색인 높이 재측정 문제를 수정했다. 선택된 글자의 hover 배경 대비도 수정했다. 추가로 확정된 포인터 캡처·취소·자동 스크롤·리소스 정리 결함은 없었다.
