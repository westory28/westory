## 실제 정산 전 필요한 별도 계약

이번 PASS는 교사용 미리보기와 관리 기능의 판정이다. 실제 학생 매매 출시 판정으로 사용할 수 없다.

현재 `studentWisWallet.write`는 양수 delta 전체를 GRANT로 기록하며 획득·등급 누적을 함께 올린다. 출금 전액을 이 helper에 넣으면 원금 회수가 획득액이 되고 등급까지 상승하므로 이번 계약과 맞지 않는다. 현재 원장 감사기의 허용 type에도 주식 입출금·예약 정산은 없다. 출시 전에는 원금 이동, 수수료, 보유 원가, 미회수 원금, 출금 이익만의 획득 증가와 등급 0을 표현하는 전용 원장 계약과 복구·역분개 정책이 필요하다.

실제 주문 transaction은 학생 역할·현재 학적·공개 상태·canonical 일반/주식 계좌, 보유량, 예약, 시장 공급량, 미회수 원금, 마지막 성공 입금 시각, 규칙/시세 revision을 다시 읽고 검증해야 한다. 잔고·포지션·공급량·회계 날짜별 한도·원장·멱등 영수증을 원자적으로 기록하고 경합·재시도·취소의 전체 회귀를 통과한 후 별도로 공개해야 한다. 일반 누적에 출금 이익을 더할 때의 overflow도 실제 계좌 값으로 검사해야 한다. 서버가 선택한 지연과 시각을 사용하며, 클라이언트 체험의 portfolio·receipt·clock·난수·권한 flag를 실제 승인 자료로 사용하면 안 된다.

## 중앙시장과 지연 주문

사용자의 후속 확정 요구를 구현한 순수 예약·체결·취소 계약과 교사용 합성 체험을 독립 검증했다. 실제 정산 RPC나 계좌 transaction의 출시 검증은 아니다.

- 중앙 교사 시장은 시스템 공급·환매를 뜻한다. 별도 교사 개인 지갑이나 지급 예산 제한은 이번에 추가하지 않는다.
- 접수 시 신선한 견적, 권한·공개 상태, 거래 시간과 한도를 확인하고 가격·수량·수수료·총액을 확정한다. BUY의 현금/시장 공급량, SELL의 학생 보유량을 중복 사용하지 못하도록 예약한다.
- 예약 지연은 5~60초다. 서버 wrapper는 `crypto.randomInt(5, 61)`로 논리적 새 주문마다 한 번 선택하며 transaction 재시도에서 다시 뽑지 않는 계약이다. 브라우저의 합성 timer는 실제 주문 승인이나 서버의 난수 선택을 대신하지 않는다.
- 견적 TTL은 접수 때만 적용한다. 접수 후 60초 대기가 30초 견적 TTL을 넘어도 정상이며, 가격·market revision·수수료 변경으로 고정 계약을 다시 계산하지 않는다.
- due 시각 전에는 체결하지 않는다. due 이후 장이 닫혔더라도 이미 접수된 예약은 체결할 수 있다. 신규 접수만 거래 시간 제한을 받는다.
- due 때 시장·종목 정지 또는 서비스 공개·권한 차단으로 집행할 수 없으면 취소하고 예약을 반환한다. 가격이 바뀌었다는 이유로 취소하지 않는다.
- 같은 예약의 반복 접수·체결·취소는 한 번만 재무 상태에 반영되어야 한다. 예약 전후 및 terminal 재시도의 현금·보유량·시장 공급량 보존을 검증한다.
- 취소는 같은 날 매수 금액 예약만 돌려주고 접수 횟수·쿨다운은 유지한다. 과거 날짜 주문 취소로 오늘의 새 한도를 늘리지 않는다. BUY의 SELL_ONLY 전환은 취소되지만 SELL은 허용되며, 한시 정지가 끝나는 정확한 시각에는 집행된다.
- 15:59:30 접수/60초 예약은 due-1ms에 거부되고 장마감 뒤 16:00:30에 확정 가격·수수료로 체결된다. 예약 후 추가 입금이 생겨도 delta 정산이 그 입금분을 보존함을 확인했다.
- 이번 화면은 합성 주문 한 개만 대기시킨다. 계정·학기·탭 이탈 시 로컬 상태와 timer를 정리한다. 실제 학생 공개, 학생 지갑 읽기/쓰기, 주문 RPC는 추가하지 않는다.

### 별도 주식 계좌

- 일반 지갑의 현재 위스만을 50% 기준으로 삼고 주식 현금·보유 원가·평가 이익을 분모에서 제외한다. 일반 지갑과 주식 계좌는 분리하며, 매매 중에는 일반 현재·누적·활동 등급을 변경하지 않는다.
- 매매의 일반 `mainCashDelta/earnedDelta/rankEarnedDelta`는 0이며 실현 손익은 주식 계좌 안에서 추적한다.
- 입금은 성공 접수 후 24시간 동안 추가 입금을 막고, 24시간이 지나면 그 시점 일반 지갑 현재 위스의 절반을 다시 입금할 수 있는 정책으로 확정했다. 홀수는 내림한다. 소액 입금도 성공하면 24시간 제한을 시작하며, 실패·중복 영수증 재시도는 제한 시각을 갱신하지 않는다.
- 출금·매매·종목 변경은 마지막 성공 입금 시각을 초기화하지 않는다. 주식 현금·보유 원가·평가 이익은 입금 한도 분모에 들어가지 않는다.
- 출금액 전액은 일반 현재 위스에 반환한다. 입금 때 `outstandingPrincipal`을 늘리고, 출금 때 `min(출금액, 미회수 원금)`을 먼저 돌려준다. 그 나머지 출금 이익만 누적에 반영하며 등급은 올리지 않는다. 손실로 주식 현금이 0이 되어도 미회수 원금은 남는다.
- 합성 계좌와 종목별 포지션을 체험 안에서 공유하고, 예약 현금의 중복 출금·체결을 막는 경계는 유지한다. 실제 지갑을 연결할 때 양쪽 계좌를 같은 transaction에서 변경해야 한다.

| 독립 검증 사례 | 결과 |
| --- | --- |
| 일반 현재 1,001 | 최초 입금 한도 500, 성공 후 24시간 직전 0, 정각에 남은 일반 501의 절반 250 |
| 주식 자산만 증가 | 일반 현재가 같으면 입금 한도 변화 없음 |
| 1위스 소액 입금 | 성공 시 동일한 24시간 제한 |
| 예약 200 / 주식 현금 500 | 출금 301 거부, 300 허용 |
| 원금 5,000 → 6,000 출금 | 현재 +6,000, 누적 +1,000, 등급 +0, 미회수 원금 0 |
| 2,000 + 4,000 분할 출금 | 한 번에 6,000 출금한 것과 동일 |
| 이익을 재입금 후 같은 금액 출금 | 새 누적 증가 0 |
| 원금 5,000 → 4,000 출금 | 누적 0, 미회수 원금 1,000 유지 |
| 위 손실 후 5,000 재입금 → 6,000 회복 출금 | 미회수 원금 6,000을 반환하므로 새 누적 증가 0 |

실패·중복 요청에서 입금 시각 연장과 재무 효과가 없고, 정확히 24시간 경계에서 다시 허용됨을 확인했다. 안전 정수 overflow, 잘못된 시각·계좌·학기·예약 잔액도 거부된다.
