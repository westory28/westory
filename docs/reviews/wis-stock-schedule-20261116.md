# 위스피 기획 종목 상장 일정 연결

기준 checkout은 `C:\westory`, 시작 커밋은 `fa749dff82326d44e9350722f7cb736b61fd9f57`이다. 운영 교사 화면에서 시장은 열렸지만 등록 종목은 0개였다. 기존 80개 종목의 상장 시각은 6주 합성 미리보기에만 있었고 서버는 등록된 종목의 가격만 갱신했다. 사용자가 2026-11-16 09:00 KST부터 기존 6주 기획안을 적용하도록 확인했다.

## 변경 계약

- 교사의 `activateWisStockCatalogPlan` 명령으로 현재 활성 학기에만 시작일을 저장한다. 역할·세션·최근 인증·활성 학기·revision·요청 영수증 검사를 유지한다. 같은 요청 재시도와 같은 일정의 재적용은 쓰지 않으며 적용된 시작일을 바꿔 재등록하지 않는다.
- 원본 카탈로그를 `functions/wisStockCatalog.json`으로 옮겨 교사 미리보기와 서버가 같은 ID·이름·상장 순서를 사용한다. 평일 09~15시의 210개 기획 시점 중 실제로 도래한 종목만 등록한다. 상시 가치 종목 10개는 첫 시점에 등록한다.
- 기존 시간당 서버 작업을 한국 시간 정각 cron으로 맞춘다. 공개·거래 중인 현재 학기에만 상장하고, 휴장·주말·중지 동안 도래한 상장은 다음 거래 시간에 보완한다. 중지 후 교사가 시장을 다시 열 때에도 도래분을 반영한다. 가격 자동 변동을 꺼도 상장 일정은 유지한다.
- 안정적인 카탈로그 ID 또는 이미 등록한 동일 이름은 중복 생성하지 않는다. 기존 종목의 교사 설정·가격·이력은 보존한다. 새 종목에는 실제 등록 시각의 기준가 한 점과 기존 자동 가격 모델을 적용한다. 미리보기의 미래 가격·합병·퇴장 시나리오를 운영 기록으로 복사하지 않는다.
- 일정 적용과 이후 수동 종목 저장 모두 미래 80개 종목 및 각각의 120개 가격 이력을 포함한 한도·문서 용량을 검사한다. 시장·학생 공개 가격·상장 감사 영수증은 하나의 트랜잭션에서 반영한다. 학생 계좌·보유량·일반 위스·거래 원장은 변경하지 않는다.
- 종목 관리 화면은 현재 표시 중인 학기·계정의 안전한 공개 시장 문서와 본인 세션만 구독한다. 종목 ID 목록이 바뀔 때만 권한을 검사하는 관리 조회를 다시 실행한다. 가격만 바뀐 경우 추가 관리 조회는 0회다. 숨김·다른 탭·계정/학기 변경·오류에서는 구독을 정리하며 작성 중인 초안을 보존한다.

## 비용과 경계

관리 조회는 기존 5문서 읽기와 쓰기 0회다. 일정 활성화는 공통 세션 검사를 제외하고 6문서 읽기, 이미 개장한 시장에서 시장·공개 가격·영수증 3쓰기다. 자동 상장은 기존 4문서 읽기와 상장이 있을 때 3쓰기이며 중복 실행은 0쓰기다. 최초 개장으로 공개 상태까지 만드는 경우 공개 상태 문서 1쓰기가 추가된다. 화면의 구독은 최초 연결 시 세션과 공개 시장 각 1문서 및 실제 변경 전달 비용을 사용하며, 상장 변경의 관리 재조회는 5문서다. 서버 폴링과 브라우저 주기 조회는 추가하지 않는다.

새 AI 호출·에이전트 실행·개인정보 외부 전송·공개 범위·권한 변경은 없다. 이미 사용자가 연 위스피의 종목 등록 동작을 기존 승인 범위에서 보완한다. 로그인 공통 코드 변경은 신규 함수 이름의 기존 미국 리전 라우팅 한 줄에 한정한다. Firestore/Storage 규칙은 변경하지 않는다. 레거시 주식 경로 fallback은 없으며 학기 canonical 경로만 사용한다.

## 검증과 배포

순수 시간 계산, 실제 handler 권한·영수증·용량, 실제 Firestore 동시 요청, 클라이언트 세션·재시도, 교사 화면 390/768/1280px 및 공개 가격의 기존 거래 회귀를 검사한다. 기본 앱 빌드와 Functions check를 수행한다. 운영 검증을 위한 학생 거래·잔액 변경은 하지 않는다.

- 순수 모듈·handler 단위검사 42개, 실제 Firestore 에뮬레이터 16그룹 통과. 같은 활성화/상장을 8개 요청으로 경합시켜 1회 반영을 확인했고 보호 지갑·원장 9문서는 조회·변경하지 않았다.
- 클라이언트 9그룹, 전체 주식 브라우저 26그룹 및 일정 전용 390/768/1280px 검사 통과. 제목·일정 행의 투명 배경과 편집 중 상장 반영·초안 보존을 화면으로 확인했다. 기존 합성 주문의 4.9초/5초 경계 검사는 검증 기계 부하에 흔들리지 않도록 테스트 시계를 정지해 고정했다.
- Functions 전체 `check` 통과. 운영 주식 5함수의 기준 ZIP과 저장소 시작 커밋은 일치하며, 운영 프론트엔드도 동일 커밋 `fa749dff`임을 Vercel API로 확인했다.
- `npm run build`의 TypeScript·전체 필수 회귀·Vite 빌드 통과. Firebase 6함수 선택 배포 후 모두 ACTIVE, 준비본 255파일 SHA 일치, 기존 자원 설정 보존 및 `0 * * * *` / Asia/Seoul / ENABLED 스케줄을 확인했다.

`prepare-wis-stock-schedule-release.mjs`는 기존 운영 주식 5함수의 최신 소스 253파일과 scheduler 설정을 보존하고, 주식 모듈/독립 진입점 2파일 변경 및 카탈로그 모듈/JSON 2파일 추가만 준비한다. 다른 운영 의존 파일 251개를 그대로 유지한다. 기존 5함수와 신규 활성화 callable 하나만 선택 배포하고 `verify-wis-stock-schedule-release.mjs --after`로 전체 ZIP 해시·자원 설정·정각 스케줄 및 호출 주체를 확인한다. 운영 데이터 적용은 교사 화면의 인증된 일정 적용 명령을 사용한다.
