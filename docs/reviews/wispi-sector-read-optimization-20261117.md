- 과거 주가·체결·보유 수량·기준 가격은 재계산하지 않는다. 배포가 시장 자료를 수정하지 않으며, 다음 정상 시세 갱신부터 새 모델을 사용한다. 누락된 과거 시각을 새 모델로 소급 생성하지 않는다.
- AI 호출, 외부 시세 구독, 학생 자료 외부 전송을 추가하지 않는다.

## 가격 모형

카탈로그 ID/업종과 기존 수동 등록 종목의 카탈로그 이름을 우선한다. 카탈로그에 없는 종목만 이름의 업종 단서를 사용한다. 생활 공구 업종인 돌끝테크를 전자 업종으로 바꾸지 않는다.

- 건설·제철과 테크·전자에 각각 공통 업종 요인을 적용한다.
- 금융은 공통 시장 요인과 현재 시간보다 앞서 확정된 지수 변화에 반응한다. 같은 갱신 중 계산한 종목 가격을 다시 입력으로 쓰지 않아 처리 순서에 영향을 받지 않는다.
- 시장 전체의 완만한 상승·하락 요인, 잔잔한 구간과 변동 폭이 큰 구간을 공유한다. 기존 종목별 추세·개별 충격·조정·VALUE 기준가 회귀는 유지한다.
- 이미 저장된 지수의 하락 충격은 이후 불확실성을 최대 35% 높이고 12시간 기준으로 감쇠하며 48시간 후 종료한다. 반등이나 수익을 보장하지 않는다.
- 공통 요인은 실제 시간 단위여서 1/6/24시간 종목이 같은 시각 같은 시장·업종 요인을 사용한다. 비공개 seed와 서버 SHA-256 표본, 재시도 결정성, 수동 변동성 0, 기존 가격 범위와 비활성 종목 처리를 유지한다.
- 기존 시장 문서와 지수 이력만 사용하므로 가격 계산의 추가 서버 조회는 0회다.

연동 강도는 교육용 모형의 계수이며 실제 지수에 추정·적합한 수치가 아니다. Nasdaq의 [변동성 국면 설명](https://www.nasdaq.com/articles/are-we-in-a-new-volatility-regime)과 연준 연구의 [하락과 이후 변동성의 비대칭성](https://www.federalreserve.gov/econres/ifdp/fluctuating-confidence-and-stock-market-returns.htm)을 현상의 참고 근거로 삼았다. 실제 코스피·나스닥 차트나 가격을 복제하거나 실시간으로 가져오지는 않는다.

## 조회와 무효화

- 학생: 살아 있는 같은 SDK 사용자 객체·auth_time·학기·계좌 revision·cursor의 진행 중 내역만 공유한다. 완료 결과는 보관하지 않는다. 명령 시작, 계좌 변경, 연결 중단 및 오류 후 재시도 경계를 유지한다.
- 교사: 보드 row에 계좌의 `accountRevision`을 선택 필드로 전달한다. 동일 거래 transaction 안에서 기록하고 가격 변경만으로는 바꾸지 않는다. 변경된 학생의 이력만 다시 읽는다.
- 기존 projection은 revision이 없으므로 기존 전체 `sourceRevision` 무효화를 사용한다. 혼합 projection에서는 학생별로 적용한다. 기존 자료를 채우기 위한 계좌 전체 조회나 별도 마이그레이션 쓰기는 하지 않는다.
- 상위 5명 조회 중 한 학생을 선택하면 진행 중인 해당 학생 요청을 공유한다. 사용자 객체·세션·학기·학급·관측 revision이 다르면 공유하지 않는다.
- 저장된 재무 수치가 같다는 이유로 거래 이력이 불변이라고 추정하지 않는다. 실시간 연결 해제·수동 새로고침·범위 전환은 캐시를 비운다. 과거 전체 원장과 필수 권한 확인은 생략하지 않는다.

- 거래 에뮬레이터의 기존 기대값 3곳은 이미 기준 커밋에 있던 `graduationJobsQueued: 0` 응답을 반영하도록 갱신했다. 실행 로직은 변경하지 않았다.

## 운영 반영

각 대상 함수의 현재 운영 source archive와 runtime을 보존하고 허용한 파일만 교체한다. 기존 reader가 새 row 필드를 거부하지 않도록 parser 호환 배포, 프런트엔드 반영, writer 및 가격 scheduler 배포 순으로 진행한다. 신규 가격 helper와 기존 카탈로그 JSON을 패키지에서 검증한다. 운영 학생 거래나 시장 강제 갱신을 검증 수단으로 사용하지 않는다.

배포 전에 열어 둔 교사 탭은 예전의 엄격한 row parser를 보유하므로 새 필드를 수신하면 다시 조회 오류가 표시될 수 있다. 새 버전으로 화면을 새로고침해야 한다. 기존 계좌는 다음 정상 계좌 변경 때 revision 필드를 얻으며, 그전에는 종전 조회 방식을 유지한다.
