# 학급 면제권 부여 속도 개선 (2026-10-15)

## 운영 관찰

- 사용자가 운영 교사 화면에서 32명 부여 성공을 확인했다. 해당 `executeCommand` 요청은 `2026-10-15T11:20:32.319252Z`에 HTTP 200으로 처리됐으며 서버 지연은 24.158초였다. 직전 OPTIONS 요청은 인스턴스 기동을 포함해 1.439초였다.
- 원본은 학생마다 학기 포인터·manifest·재적 slot을 읽고, 재적과 사용자 프로필을 다시 순차 조회했다. 면제권 검증 단계만 32명 기준 조회 RPC가 99회였다.
- Tailwind CDN 경고는 이 저장 실패의 증거가 아니다. 이전 화면에서 실패했던 개별 요청의 오류 원문은 확보하지 못했으며, 이후 성공과 이번 지연 측정은 구분한다.

## 변경과 안전성

- 부여 명령의 트랜잭션 시도마다 전용 reader를 생성한다. 같은 트랜잭션에서 읽은 학기·재적 snapshot을 재사용하고, 학생별 slot·프로필 조회를 `getAll`로 묶는다.
- 기존 학기·revision·활성 재적 slot·학생 UID·학급 검사 함수를 그대로 실행한다. 전역 캐시는 없으며 승인·회수·학생 신청 명령의 읽기 방식은 변경하지 않는다.
- 모든 학생의 검증을 마친 뒤 전체 면제권을 저장한다. 배치 조회 실패 시 대기 중인 요청 모두를 거절하고, 기존 명령 ID·receipt 기반 중복 방지를 유지한다.

## 검증

- 로컬 Firestore emulator에서 같은 34명 재적 중 32명을 선택했다. 검증 단계 RPC는 99→4회, 읽은 문서는 197→101개였다. 원본 3회는 1397.7/1420.1/1343.9ms, 최종 개선 3회는 75.2/74.3/40.6ms였다. 평균 1387.2→63.4ms로 줄었다. 이 수치는 로컬 검증 단계의 비교이며 운영 전체 응답 시간은 아니다.
- 1명·선택 32명·학급 전체 34명 모두 RPC 4회 이내를 회귀 조건으로 검사한다. 계측용 트랜잭션은 강제 롤백한다.
- 실제 callable·세션·교사 인가·Firestore 트랜잭션으로 부여·재호출·상태 조회·신청·승인·거절·회수와 원자적 실패를 검사한다. 배치 읽기 실패, 재적 slot 누락·다른 학생 연결, 학생 역할 변경, 학급 보관, 학기 revision 불일치에서는 추가 부여가 없어야 한다.
- `node scripts/verify-history-classroom-sdk-contract.mjs`는 실제 앱의 클라이언트·세션 helper·Firebase Auth/Functions SDK를 사용한다. 로컬 HTTP 서버만 합성하며 외부 요청을 차단한다. 한국어 사유·32명 직렬화, 응답 유실 후 receipt 복구, 동일 ID 재시도, 세션 만료 차단을 확인한다.
- `npm run build`, `npm --prefix functions run check`, `npm --prefix functions run test:history-classroom`이 통과했다. Windows checkout의 지구본 JSON은 내용 변경 없이 Git에 저장된 LF 바이트로 맞춰 기존 자산 해시 검사를 실행했다. 별도 읽기 전용 검토에서 배포를 막는 결함은 발견되지 않았다.

## 운영 반영 범위

- 다른 평가 작업의 최신 `origin/main` 커밋 `924545c`를 병합해 보존했다. 운영 `executeCommand` revision `executecommand-00010-nus`, source generation `1792063259623601`의 gateway 55개 파일과 진입점·세션·학생 접속 설정 3개 파일은 해당 HEAD와 LF 정규화 후 모두 일치했다.
- 이번 함수 배포 대상은 서울 `executeCommand` 하나다. 기존 세션 정책과 조회 함수, rules는 유지한다. 실제 운영 학생에게 시험용 면제권을 추가 발급하지 않는다.
- 배포 후 함수 ACTIVE 상태와 배포 소스 바이트를 확인한다. 개선 후 운영 전체 소요 시간은 다음 실제 부여 요청에서 확인해야 하며 로컬 계측을 운영 시간으로 제시하지 않는다.
