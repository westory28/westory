기준 소스: `bd9b96c462212e22c9639763e6be0be125c08c67`. 운영 자료는 2026-11-08 14:47 UTC에 필요한 메타데이터만 읽었다. 학생 문서·응시 결과를 읽거나 공개 상태·배정·점수를 변경하지 않았다.

## 운영 자료 확인

현재 학기 `2026-2`의 설정·활성 포인터·manifest가 일치하고 3학년 1~10반이 활성 상태다. 각 회차는 23문항, 100점, 문항 번호 1~23, 공통 세트 1개로 구성돼 있으며 확인한 필수 출제 메타데이터에 오류가 없다. 회차 없는 구형 문항은 없다.

세 회차 모두 현재 비공개다. 1회 정의는 DRAFT이고 2·3회 정의는 아직 생성되지 않았다. DRAFT에 저장된 과거 sourceHash는 현재 문항과 다르지만, 교사가 공개 설정을 저장할 때 현재 자료로 다시 생성하는 경로를 검증했다. 이 점검이 학생 공개를 실행한 것은 아니다.

운영 조회는 현재 학기 설정·정의·학급과 해당 모의고사 69문항의 필수 메타데이터로 제한했다. 새로운 회차 필터 쿼리와 회차 존재 확인 쿼리는 운영에서 각각 `limit: 1`로 검사해 기존 인덱스로 정상 처리됨을 확인했다. 학생 명부 조회·전체 학기 조회·운영 부하 검사는 수행하지 않았다.

## 수정 내용과 조회 범위

- 공개·자료 준비·시작은 해당 회차만 읽는다. 최대 201문서로 기존 200문항 상한을 검사한다.
- 빈 회차는 다른 회차로 채우지 않는다. 작성된 회차의 존재를 최대 1문서로 확인하고, 회차 필드가 없는 구형 은행에만 기존 호환 조회를 적용한다.
- 문항 수정·이동·삭제는 영향받은 회차만 갱신한다. 빈 이전 회차가 있어도 유효한 새 회차는 갱신하며, 오류를 숨기거나 다른 회차를 비공개로 전환하지 않는다.
- 첫 회차의 구형 설정키는 교사 저장 시 정확한 새 키로만 전환한다. 역할·학기·revision·다른 정의 식별자는 기존 검사를 유지한다.
- 학생 목록은 학교 설정과 학생 명부를 조회하지 않는다. 현재 공개 설정으로 자기 학급의 표시를 판단하고 실제 입장은 서버에서 재검사한다.
- 학생 목록 제목은 `문제 풀이`다. 단원별 평가와 모의고사는 별도 탭이며, 모의고사에서 회차 선택·시험 정보·입장을 제공한다. 탭 진입 시 본인 회차 개요만 한 번 읽고 선택 변경에는 조회를 추가하지 않는다.

## 검증

- 실제 Firestore 에뮬레이터: 10개 반 공개 후 서로 다른 학생 10명의 동시 START와 동일 commandId 중복 요청. 응시 10개만 생성되고 중복은 같은 영수증·응시를 반환한다.
- 공개 후 신규 조회·자료 준비·시작, 미공개/타반/타학기 차단, 2·3회 선행 제출, 제출 전 정답·해설 비노출.
- lifecycle: sourceHash 불변, 빈 회차 대체 금지, 구형 은행 2·3회 호환, 200문항 상한, 정확한 첫 회차 키 전환과 타 키 거부.
- 교사 공개/문항 편집: 단일 공개 명령, 변경 회차만 갱신, 다른 회차 상태 보존, 회차 이동·삭제와 오류 표시.
- 합성 브라우저: 모바일·태블릿·PC 너비, 현재 공개 설정을 새로 읽는 경로, 명부·문항 원본 조회 금지, 회차 순서 제한. 실제 iPhone·Android 기기나 실제 학생 계정의 동시 사용 검사는 아니다.

재실행 검사는 `functions/productionGateway/scripts/verify-assessment-lifecycle.cjs`, `scripts/verify-assessment-release.mjs`, `scripts/verify-mock-exam-authoring-browser.mjs`, `scripts/verify-student-quiz-entry-browser.mjs`를 사용한다. 10학생 동시 입장 검사는 기존 `functions/productionGateway/scripts/verify-quiz-release-integration.cjs`에 포함했다. 기본 `npm run build`, `npm run format:check`, `npm --prefix functions run check`도 수행한다.

## 운영 반영 범위

운영 원본과 기준 소스의 호출 의존 경로를 비교했다. `executeCommand`의 115개 실행 소스가 기준과 일치하고 `getAssessmentState`의 조회 경로도 일치한다. 후자의 이전 단답형 소스 차이는 새 패키지에 함께 포함한다. 변경 함수는 서울 `executeCommand`, `getAssessmentState`뿐이며 영수증·진행 자동 저장·rules는 배포 대상이 아니다. 프론트엔드는 Vercel main의 해당 커밋을 확인하고 `www.westory.kr`로 승격한다.

이번 변경은 기존 학교 서비스의 공개·입장 유지보수다. 대상 학교·개인정보·외부 서비스·역할 권한을 확대하지 않으며 런타임 AI 호출·학생 자료의 외부 AI 전송은 추가하지 않는다.
