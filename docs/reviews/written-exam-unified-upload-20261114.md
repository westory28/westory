## 사용자 흐름

첫 탭을 **점수 등록 및 확인**으로 바꾸고 각 탭의 버튼을 탭 아래에 배치했습니다. 작은 업로드 창에서 서답형·논술형·원안지/문항정보표를 선택합니다. 과목·학년·기본 반은 PC 한 행이며 선택적 설명은 라벨 옆 i 도움말에만 있습니다. 여러 학급 XLSX의 모든 비어 있지 않은 시트를 함께 파싱하고, 학생·평가·문항 충돌을 파일/시트 단위로 알린 후 미리보기를 엽니다. 기존 점수 저장·서명·이의 처리 계약은 유지합니다.

분석 탭의 자료 업로드 버튼을 제거했습니다. 분석은 현재 학기 등록 점수표 및 선택 학급의 최신 학생 점수 문서를 읽습니다. 선택형과 논술형은 사용자가 지정한 배지 탭으로 구분합니다. 선택형은 기존 일곱 보고서·PDF 문항 보기·누적 추정 수준을 유지합니다. 논술형은 전체·문항·학급·학생 네 가지 원점수 보고서와 저장된 교사 피드백을 표시합니다. 실제 0점과 미입력을 구분하고 일부 입력은 부분합, 전 문항 입력 완료만 총점 분포·평균으로 집계합니다. 원배점이 확인되지 않은 일반 논술형 파일에 득점률·성취수준을 붙이지 않습니다.

원안지·문항정보표·시험일은 기존 점수표를 선택해 첨부합니다. 원안지 없이 메타데이터만 수정해도 기존 PDF와 페이지·크롭을 보존합니다. 저장은 새 파일 revision과 자료 메타데이터만 발행하며, 학생 응답을 분석 저장소에 복제하거나 공식 점수를 바꾸지 않습니다. 시험일이 없으면 모의고사를 연결하지 않고 등록을 안내합니다. 유효한 모의고사가 없으면 정기시험 선택형만으로 추정하며 고정 분할점수를 사용하지 않습니다.

전 사이트 공통 새로고침은 반대 방향의 두 화살표 SVG입니다. 메뉴 필터는 유지하고 서버 자료를 갱신합니다. 배포된 자산 교체는 로딩 화면에서 최신 버전으로 이동합니다. 모든 입력을 미저장으로 취급하던 전역 추적을 없앴으며, 퀴즈 응시는 기존 저장 요청 종료 후 최신 답안을 동일 응시에 저장하고 이동합니다. 저장 실패·오프라인·반복 실패는 내용을 버리는 대신 복구 오류와 재시도를 남깁니다.

## 조회·권한·저장 범위

- 목록은 현재 학기의 `performance_score_rosters` 중 정기시험만 REST `runQuery`의 필드 projection으로 읽습니다. 학생 이름·응답·서명·피드백은 목록에서 제외합니다. 임의 limit은 없습니다. projection은 전송량 감소이며 청구 문서 읽기 감소로 계산하지 않습니다.
- 상세는 선택한 roster와 자료 metadata 각 1회, 선택 학급의 명시적 UID 점수 문서를 최신 서버에서 각 1회 읽습니다. 이름만 연결하지 않고 UID·학적·학기·평가·문항 구성을 대조합니다. 누락·오류를 0점으로 바꾸지 않습니다.
- 모의고사는 선택형에 실제 답안이 있고 시험일이 등록된 경우에만 요청합니다. 보고서 보기·선택형→논술형 전환은 이미 받은 데이터를 사용합니다. 논술형 상태 새로고침에서는 모의고사를 요청하지 않습니다.
- 실제 source mock 검사: 학급 학생 UID 3명 두 번 갱신 시 REST 목록 2회, SDK get 10회(명부2·자료2·대상학생6), 다른 학급 UID 조회0·쓰기0. 전 학년 UID4명 상세는 get6회입니다. 실제 비용 측정값은 아닙니다.
- 자료만 발행하는 경로는 실제 Firestore emulator에서 분석 class 응답 문서가 하나도 생성되지 않는 것을 확인했습니다. 기존 Firestore/Storage 규칙을 유지하며 새 Functions·rules 배포는 필요 없습니다. 학생 본인 조회/교사 조회/타인 차단 회귀를 실행했습니다.
- 계정·auth generation·학기 전환은 이전 응답을 폐기합니다. 업로드 편집기는 identity 변경 시 remount하고 평가 변경 시 파일·미리보기를 초기화합니다. 구버전 논술형의 누락된 유형 필드는 선택형 근거가 없는 기존 논술형 점수에만 읽기 호환을 적용하며 원본을 수정하지 않습니다. NEIS 복수정답·동그라미 숫자·구분자도 기존 업로드 파서와 같은 방식으로 연결합니다. 원안지 revision 충돌·응답 유실·업로드 실패 시 기존 게시본을 보존합니다.
