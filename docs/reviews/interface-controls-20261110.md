# 관리자 인터페이스와 학생 숨김 제어

2026-11-10. 변경 전 기준은 `94325681eb71b71298644abeb1e8bc777ba672c0`이다. `C:\westory`에 진행 중이던 평가·학습지 변경을 보존하기 위해 별도 `codex/interface-controls` worktree에서 작업했다.

## 설정과 접근 경계

- `site_settings/interface_config.dashboard`의 `notice`, `calendar`, `ranking`은 학생 대시보드의 각 영역 표시를 결정한다. 기존 문서에 필드가 없으면 표시를 유지한다. 낡은 메인 이모지·문구·D-Day 입력은 제거하지만 저장된 값은 수정하지 않는다. 푸터·인스타그램 설정은 유지한다.
- `site_settings/menu_config`는 기존 메뉴 배열을 유지하며 학생 상위 메뉴에도 `hidden`을 저장한다. 마이페이지 하위 메뉴와 마우저구 윷놀이 항목을 기본 목록에 보완한다.
- 메뉴 저장 transaction은 같은 작업에서 `site_settings/config.studentMenuVisibility`의 `weplay`, `naval`, `yut`, `mypage`, `avatar`, `profile`, `score`, `wrong_note`를 함께 저장한다. 기존 학년·학기·일반 설정은 merge로 보존한다. 이 맵은 메뉴 부모와 하위 항목의 유효 숨김을 서버·rules가 함께 확인하기 위한 값이다. 기존 게임의 `enabled`는 별도로 유지하므로 메뉴 숨김 해제가 게임을 새로 공개하지 않는다.
- 학생에게는 서버에서 확인된 설정을 사용하며 로딩·조회 실패를 기본 공개 상태로 처리하지 않는다. 대상 메뉴·직접 링크·열린 화면·게임 명령·아바타 저장 및 읽기 경계를 함께 다룬다. 교사 미리보기와 게임 관리는 기존 권한을 유지한다.
- 관리자 초기 설정 조회 실패 시 폼을 표시하지 않고 재시도만 제공한다. 실패 상태에서 기본 메뉴로 덮어쓸 수 없다. 메뉴 저장의 기존 동시 수정 검사를 유지한다.

- `npm run typecheck` 통과.
- `node scripts/verify-interface-controls-browser.mjs`: 실제 `SettingsInterface`와 `StudentDashboard`를 사용하고 서버·하위 패널 경계만 합성 응답으로 바꾼다. 390/768/1280px에서 설정 체크박스와 저장, 메뉴·서버맵 동시 저장, 상위 마이페이지 숨김, 초기 읽기 실패와 재시도, 숨긴 일정·순위의 미마운트 및 미조회, 기존 표시 기본값과 가로 넘침을 확인했다.
- 설정 390px와 사이트맵 1280px 캡처를 직접 확인했다. 학생 대시보드 일부 숨김은 빈 열·고정 높이를 남기지 않는다. 이 검사는 운영 저장·실제 학생 계정을 사용하지 않는다.
- 캡처와 상세 결과는 실행 시 출력하는 임시 `westory-interface-controls-*` 폴더에 보관하며 저장소에 개인 데이터·이미지를 추가하지 않는다. 전체 빌드·Functions·rules 에뮬레이터·운영 배포와 운영 도메인 확인은 통합 작업에서 별도로 기록한다.
