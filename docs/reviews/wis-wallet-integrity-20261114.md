5. 명시적 projection 재구축은 일반 원장의 소유자·금액·잔액 연결 검증이 부족했다. 손상된 원장을 근거로 새로운 합계를 저장하지 않도록 보완했다.

## 변경과 연동 계약

- 공용 `studentWisWallet`은 해당 adapter가 같은 transaction에서 읽은 snapshot만 쓸 수 있다. 복사·위조·타 학생·타 학기·다른 transaction의 snapshot과 같은 시도 내 두 번째 writer 호출은 거부한다. 호출부에서 반환 객체의 잔액을 바꾸어도 저장용 snapshot은 바뀌지 않는다.
- Firestore SDK가 재시도 때 Transaction 객체를 재사용하는 경우를 보존한다. 이전 쓰기 뒤 새 시도의 읽기가 성공한 경우에만 쓰기 상태를 새로 만들고 이전 시도의 snapshot은 거부한다. 같은 source의 불변 원장 ID는 재시도에도 같다.
- 금액·활동 식별자·근거·영수증 학기 경계를 최초 staged write 전에 검사한다. 정상 경로의 추가 Firestore 읽기·쓰기는 0개다. 기본 읽기 10문서, 원장·계좌·잔액 projection·순위 projection·economy의 쓰기 5개라는 공용 writer 범위는 유지하며 각 서비스의 세션·정책·결과·영수증 읽기/쓰기는 별도다.
- `wisLedgerIntegrity`는 순서에 의존하지 않고 모든 원장이 0에서 최종 잔액으로 연결되는지, 소유자·학기·안전 정수·부호·중복 식별자·역분개 원본이 맞는지 검증한다. 같은 시각에 여러 건을 기록하거나 환불로 이전 잔액을 다시 방문하는 정상 거래도 허용한다.
- 교사의 명시적 `rebuildWisProjection`은 올바른 원장만 사용한다. 현재 projection만 잘못된 경우에는 복구할 수 있지만 원장 자체가 손상되면 무변경으로 거부한다. 자동 복구나 운영 자료 보정은 추가하지 않았다.
- 읽기 감사는 누적 획득·순위 누적·상점 사용·조정 합계, 양쪽 projection의 범위/합계/revision, 최근 캐시의 중복/금액/원본 일치까지 검사한다. 실제 학생 식별자는 출력하지 않는다.
- 새 서비스는 가격·소유자·학기·공개 상태를 서버에서 검증하고 하나의 고정 source/request ID로 원장·잔액·서비스 결과·영수증을 같은 transaction에 저장해야 한다. 여러 품목은 검증된 합산 delta로 한 번 처리하거나 별도 검증된 batch adapter를 만들어야 한다. 공용 writer를 여러 번 호출하거나 실패 후 다른 리전/새 요청 ID로 자동 지급하지 않는다.

## 교사 화면의 조회 범위와 페이지 계약

- `ManagePoints`는 선택한 탭에 필요한 자료만 요청한다. 현황은 명단 한 페이지·학교 필터·위스 정책, 지급은 학교 필터·정책과 조건 선택 후 후보 한 페이지, 정책·등급은 정책만, 상품은 상품만, 주문은 주문만 읽는다. 주식은 지갑 명단·상품·주문·위스 정책을 요청하지 않는다. 명예의 전당은 기존 독립 조회를 유지한다.
- 학교 필터·위스 정책은 같은 로그인 사용자·인증 세대·학기·읽기/쓰기 권한 범위 안에서 성공한 결과만 재사용한다. 수동 새로고침은 새 요청을 수행하며 실패 결과는 캐시에 저장하지 않는다. 화면 전환 뒤 완료된 응답은 새 탭·새 학기의 상태를 바꾸거나 숨겨진 거래 내역을 읽지 않는다.
- 현황과 지급 후보는 학기, 학년, 반, 번호를 서버의 equality filter로 제한한다. 이름은 `displayName` 범위 쿼리를 이용한 앞부분 검색이며 화면 라벨도 이를 명시한다. 이름 검색에서는 이름순으로 고정하고 금액 정렬 버튼을 비활성화한다. 문자열 학적 필드의 잘못된 숫자 정렬을 피하기 위해 소속 열 정렬은 제공하지 않는다.
- 한 페이지는 20명이며 정상적인 원본 명단에서는 다음 페이지 유무 확인을 포함해 최대 21계좌를 읽는다. 학적 종료·이동 뒤 남은 오래된 후보는 canonical 학적 확인 후 건너뛰고 같은 서버 필터로 다음 후보를 더 읽어 페이지를 채운다. 각 쿼리는 최대 21계좌이며 후보를 건너뛴 경우의 추가 읽기를 숨기지 않는다. UI는 전체 인원처럼 표시하지 않고 `현재 페이지 N명`과 이전·다음을 표시한다. 선택한 페이지의 원본 학적 연결·권한 확인은 유지한다. account field mask에서 최근 원장 배열을 제외한 것은 전송량 절감이며 Firestore 문서 읽기 수 절감으로 계산하지 않는다.
- 커서는 경제 revision, 정렬 필드·방향, 경계값, 계좌 ID를 묶는다. 다음 요청의 경제 revision이나 경계값·소속이 달라지면 `WIS_OVERVIEW_PAGE_CHANGED`로 거부하고 UI가 첫 페이지를 다시 읽는다. 이미 요청 앞부분에서 읽는 economy 문서를 재사용하므로 세대 확인의 추가 읽기는 0개다. 정상 다음 페이지는 기존 경계 계좌 읽기 1개를 유지한다. 이 방식은 게임 차감으로 경계 계좌가 아래로 이동하거나 다른 계좌가 경계를 넘어서 남은 학생을 조용히 누락하는 문제를 차단한다.
- 수동 지급 후에는 해당 학생의 계좌 요약만 갱신한다. 지급 성공 뒤 조회 실패를 지급 실패로 표시하거나 재지급 명령을 보내지 않는다. 계좌 revision이 더 낮은 응답은 이미 확인한 잔액을 덮어쓰지 않는다. 전체 명단과 숨겨진 거래 내역을 다시 읽지 않는다.
- 추가 색인은 현황용 22개와 순위용 6개를 공유한다. 학기+전체/학년/학년·반의 금액별 정렬, 번호 equality 결합, 이름 앞부분 검색 범위에 필요한 조합이다. 번호 equality와 정렬 색인은 [Firestore equality index merge](https://firebase.google.com/docs/firestore/query-data/index-overview)를 이용하며 운영 배포에서 실제 Query Explain으로 확인한다. 로컬 모의 쿼리의 성공을 운영 색인 사용 성공으로 보고하지 않는다.
- 새 배포 의존성은 `wisOverviewQuery.js`이며 `getWisEconomyStateFast` 조회 bundle에 포함해야 한다. 기존 nested overview selector를 쓰지 않는 클라이언트의 기존 조회 계약과 archive 경로는 유지한다. 계좌 metadata 동기화·학적 종료/이동 경계는 별도 학적 writer 패치 및 통합 검증 기록을 따른다.
- 페이지 세대 보호는 경제 revision을 갱신하는 거래에 적용된다. 계좌 메타데이터만 바꾸고 경제 revision을 유지하는 학적 수정 중에는 전체 명단의 snapshot 일관성까지 보장하지 않는다. 다만 경계 학생의 이름·필터 소속 변화는 경계 검사가 거부하고, 현재 범위 밖 학생이 결과에 노출되지는 않는다. 새 필터 요청은 최신 canonical 계좌 메타데이터에서 시작한다.
