# 교사 평가 화면 검증

## 실행 방법

저장소 루트에서 의존성을 설치한 상태를 기준으로 합니다. fixture는 실제 `ManageQuiz`와 하위 컴포넌트를 빌드하되 인증, Firestore, 평가 서버 명령은 메모리 내 합성 구현으로 교체합니다. Firebase SDK가 번들에 포함되면 실행을 중단하고, CSP의 `connect-src 'self'`로 외부 연결을 제한합니다. 이 fixture에서 등록한 문항은 운영 서버에 저장되지 않습니다.

현재 앱의 `index.html`에서 쓰는 Tailwind CDN 스크립트를 한 번 내려받아 로컬 파일로 제공합니다. 실행마다 외부 CDN을 요청하지 않습니다.

```powershell
$qaTailwindPath = Join-Path $env:TEMP 'westory-assessment-qa-tailwind.js'
Invoke-WebRequest -Uri 'https://cdn.tailwindcss.com' -OutFile $qaTailwindPath
$env:ASSESSMENT_QA_TAILWIND = $qaTailwindPath
node scripts/verify-assessment-teacher-browser.mjs
```

기본 주소는 `http://127.0.0.1:4318`입니다. 포트를 바꾸려면 실행 전에 `$env:ASSESSMENT_QA_PORT='4320'`을 지정합니다. 소스를 바꾸면 서버를 종료하고 다시 실행해야 번들이 갱신됩니다. 브라우저 상호작용은 CUA로 수행합니다. 390, 768, 1280px에서 확인한 뒤 뷰포트 설정을 해제합니다.

- 기본: 긴 단원명, 문항 6개, 합성 학생 2명, 한 학생의 문항 4개 제출(정답 1개), 관찰 정보, 힌트 참고, 분류 정보
- `/?scenario=empty`: 문항과 제출이 없는 상태
- `/?scenario=error`: 읽기 실패 상태

## CUA 확인 기록

교사 전용 CUA 세션에서 390px 등록 화면과 문제 은행의 문서 전체 가로 넘침이 없음을 확인했습니다. 긴 중단원·소단원 제목이 `white-space: normal`, `text-overflow: clip`이며 전체 제목이 줄바꿈되는 화면을 확인했습니다. 문제 은행의 첫 문항에서 파생 문항을 열어 지문 `{{box:(가)}}`, 이미지, 선지, 해설, 힌트, 분류·자료 연결이 보존되는 것을 확인했습니다.

변경 없는 파생 저장, 검토 미완료, 분류 검증, 저장 실패와 공개 반영 실패는 모달 안의 `role=alert`로 표시합니다.

부모 에이전트의 별도 CUA 탭에서 다음을 추가 확인했습니다.

1. 문제 은행 → 첫 파생 문항 → 검토 확인 → 변경 없이 등록: 오류가 모달 안에 보이고 문항 수는 6개로 유지됐습니다. 발문을 바꾼 뒤 등록하면 이미지·자료·선지·해설을 유지한 7번째 문항이 표시됐습니다.
2. 학습 진단 → 가상학생가: 서로 다른 문항 4개, 최근 정답 1개, 오답 3개, 확신한 오답 3개, 힌트 1개가 일치했습니다. 관찰 기록의 열람/첫 응답/최종 응답은 합성 입력 22/12/18초와 일치했습니다. 파생 등록 후 다른 문항 3개 버튼은 은행의 미풀이 3개만 보여 줬습니다.
3. 390px 단원 메뉴·파생 편집, 768px 문제 은행, 1280px 등록·진단 화면을 확인했습니다. 긴 단원명이 줄바꿈되며 문서 전체 가로 넘침은 없었습니다. 넓은 통계 표는 해당 표 영역에서 가로 스크롤합니다.
4. 편집 모달의 마지막 등록 버튼에서 Tab은 닫기 버튼, 첫 닫기 버튼에서 Shift+Tab은 등록 버튼으로 순환했습니다. Escape로 닫으면 이전 파생 버튼으로 포커스가 돌아왔습니다.
5. empty 시나리오는 0문항·빈 목록을, error 시나리오는 기록 조회 실패와 새로고침을 표시했습니다. 문항이 없는 상태를 안정된 학습 상태로 표현하지 않도록 별도 문구로 처리했습니다.

학생 Runner는 320/390/768/1280px에서 확인했습니다. 이미지 보기·순서형 부분 입력·미완성 제출 확인, 선택 답안 유지, 결과의 단원/개념 확인과 복습 버튼을 검증했습니다. 초기 조회·자동 저장·제출의 첫 요청을 각각 실패시킨 합성 시나리오에서 다시 불러오기·다시 저장·다시 제출이 성공했고 답안을 유지했습니다. 실제 복습 경로는 App → MyPage → wrong_note → 제출 attemptId 연결을 코드로 확인했습니다.

화면 기록은 작업 공간의 `tmp/assessment-evidence/teacher-register-1280.jpg`, `teacher-learning-1280.jpg`에 보관했습니다. 합성 자료·학생만 사용했습니다.

## 해석과 운영 범위

- 새로운 제출은 `semester_assessment_results`를 실시간 구독합니다. 이전 방식 기록의 기존 한도·필터는 유지하며 조회 범위를 화면에 표시합니다.
- 답안 원문이 없는 과거 canonical 기록은 정오답 집계에는 포함하되 오답 선지 분포에서는 제외하고, 답안 정보 없음으로 표시합니다. 실제 빈 답안과 구분합니다.
- 같은 문항의 반복 응답은 독립 문항 근거로 늘리지 않습니다. 시간·확신도만으로 찍기나 숙달을 확정하지 않습니다.
- 기존 개념·인지과정 미등록, 현재 문항 분류를 이용한 과거 기록, 크기 제한으로 일부 분류가 생략된 기록을 구분합니다.
- 은행에서 평가 유형/출처 이동은 편집할 수 없으며, 저장 후 현재 출처의 공개 정의를 갱신합니다. 기존 정답 교정은 이전 방식 기록 재계산만 유지하고 새 제출 기록을 소급 수정한다고 안내하지 않습니다.
- 교사의 학습자료 연결은 선택한 자료명을 표시하며 기존 수업자료 관리 화면으로 이동합니다. 학생의 실제 자료 재학습 이동은 학생 화면 변경에서 별도 검증합니다.

이 fixture는 Firebase 권한·실제 서버 저장·공개 정의 갱신·운영 배포 검증을 대체하지 않습니다.
