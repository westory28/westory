# 아바타 의상·헤어·가격 관리 개편

## 범위와 호환성

- 한복·관복·하복의 어깨, 팔꿈치, 허리, 옷자락을 연결된 스킨 메시로 수정했다. 한복 바지의 버선과 치마·관복의 발목이 기존 신발 표면까지 이어진다.
- 헤어 6종은 Higgsfield의 4방향 원본 렌더로 제작한 실제 3D GLB다. 기본 단발·가르마는 기존 모델을 유지하고 긴 웨이브는 기존 상세 메시와 UV를 변형한다. 제작 작업 ID와 최적화 절차는 `public/avatar/ASSETS.md`에 기록했다.
- 품목 카드는 실제 렌더러로 캡처한 정적 WebP를 공유한다. 카드별 WebGL 캔버스나 서버 조회를 만들지 않는다.
- 교사 설정은 기존 `TeacherSubNavigation`을 사용해 주 사이드바 바로 오른쪽에 배치했다. 가로 탭을 세로 탐색으로 바꾸는 것은 사용자 명시 요청에 따른 예외다. 좁은 화면은 기존 접기·펼치기 탐색을 사용한다.
- 관리자 가격표는 미리보기, 품목명, 유형, 착용 대상, 현재 가격과 변경 상태를 함께 표시한다. 종류·유형·착용 대상·검색·변경 항목 필터를 제공한다.

기존 품목 ID와 가격, 학생 소유·구매·서버 저장 검증, 가격표 버전 충돌 검사, 교사 권한은 유지한다. 무료 헤어 `hairStyle:toben`, `hairStyle:twin-tail`, `hairStyle:half-up`만 추가했다. 학생·교사 꾸미기는 공통 렌더러와 미리보기를 사용하며, 교사에게 학생의 지갑이나 구매 흐름을 추가하지 않는다. 저장된 프로필 썸네일은 사용자가 다시 저장할 때 갱신된다.

## 비용과 수명 관리

6개 모델의 합계는 70,785,460바이트에서 11,206,408바이트로 줄였다. 최적화는 지오메트리와 UV를 보존하고 내장 텍스처만 조정한다. 선택한 스타일만 사이트 내부에서 지연 로드하며 실행 중 AI 서비스를 호출하지 않는다. 모델 준비가 끝나기 전에는 새 모습을 저장할 수 없고, 연속 선택·캐릭터 교체·숨김·종료 시 취소와 자원 해제를 처리한다. 로드 오류는 명시적으로 재시도한다.

## 검증과 배포

- 의상 검증: 168개 리그·포즈 조합과 실제 신발 표면에 대한 연결 검사, 30개 실제 렌더 확인.
- GLB 최적화: 6종 모두 소스와 최종 지오메트리·경계·텍스처 연결 대조 및 브라우저 파싱·렌더 비교 통과.
- 헤어 실착: 지원 캐릭터별 11개 스타일, 갓·사모 22개 조합, 염색·회전·포즈 22개 렌더 확인. 외부 헤어는 12,577~17,141개 삼각형이다.
- 비동기 선택: 최초 로딩 중 저장 차단, 연속 선택, 외부 모델 간 경합, 로딩 중 염색, 실패 후 재시도, 캐릭터 교체, 숨김·복귀, 종료 등 11개 실제 React 시나리오 통과. 반복 선택에서 geometry/texture 증가가 없고 종료 시 canvas와 geometry가 남지 않았다.
- 두상 연결: 원본 얼굴의 albedo·ORM을 샘플링해 색·광택을 맞추며 기본·밝은·짙은 피부색 실착과 8개 팔레트 계산을 확인했다. 눈썹 보호, 후두부 닫힘, 긴 묶음머리의 카메라 경계를 함께 검사했다.
- 원본 옷깃: 헤어와 의상이 섞인 UV 경계에서 실제 상의를 헤어로 제거하지 않도록 보호했다. 원본 여성 재킷의 열린 옷깃에는 같은 재질·색상 처리를 공유하는 안감을 덧대고, 한복·관복·하복에서는 숨긴다.
- 학생 꾸미기: 320·390·768·1280px에서 가로 넘침 없이 실제 256px 이미지가 로드되고 WebGL 캔버스가 1개임을 확인했다. 합성 데이터로 소유하지 않은 의상의 저장 차단, 180위스 구매, 투명 썸네일 저장을 검증했다. 운영 구매·저장은 수행하지 않았다.
- 교사 설정·가격표: 320·390·768·1280·1366px에서 실제 이미지 로드와 가로 넘침 없음, 390·768·1280px의 전체 사이드바·설정·꾸미기 조합을 확인했다. 유형·착용 대상 필터, 빈 가격 오류, 명시적 저장, 저장 중 잠금, 재조회 실패 복구, 가격표 충돌 시 초안 보존을 합성 데이터로 검증했다. 1280px에서 주 사이드바의 오른쪽 경계와 설정 탐색의 왼쪽 경계가 모두 232px로 맞았다.
- Functions 전체 검사 통과. 가격표 추가를 반영한 아래 함수 12개 인스턴스의 선택 배포 성공 및 `ACTIVE` 확인.
- 최종 `npm run build` 통과. 재생성된 153개 미리보기는 1,307,544바이트이며 모델·렌더러·생성기 지문, 품목별 이미지 해시, 용량 제한 검사까지 통과했다. 기존 대형 번들 경고는 유지되며 빌드 오류는 없었다.

배포 함수: `getStudentAvatar`, `purchaseStudentAvatarItem`, `saveStudentAvatar`, `getAvatarStudioState`, `getTeacherMyPage`, `saveTeacherAvatar`, `getAvatarCatalogPricing`, `updateAvatarCatalogPricing`, `getWisRankingPreview`, `getWisEconomyState`의 미국·서울 리전, `getWisEconomyStateFast`. 배포 소스 해시는 `f71f83931a3cc2175385af02d3d59a1c0732cf67`이다. Functions 외의 rules·사용자 데이터·가격 설정은 변경하지 않았다.

재현 명령은 `node scripts/verify-avatar-garments.mjs`, `node scripts/verify-avatar-hair-renderer.mjs`, `node scripts/verify-avatar-hair-async.mjs`, `node scripts/verify-avatar-hair-lifecycle.mjs`, `node scripts/verify-avatar-settings-browser.mjs --require-previews`, `node scripts/verify-avatar-ui.mjs --serve`와 `node scripts/verify-avatar-catalog-browser.mjs`, `npm run build`다. 브라우저 QA는 로컬 합성 데이터만 사용한다.

프론트엔드 릴리스는 main 배포의 Ready, 운영 승격, `www.westory.kr`의 실제 관리자 화면 확인까지를 완료 기준으로 삼는다. 배포 전후 커밋과 도메인은 운영 배포 절차에 따라 대조한다.
