# 로그인 중 일시 오류 자동 복구 (2026-11-11)

## 확인 범위와 원인

기준 HEAD와 운영 도메인의 source SHA는 `2985822c68baeaee426d0cbc44834c64c077a378`로 같았다. 작업 폴더의 평가 분석·수업자료·사전 변경은 제외하고 로그인 공통 모듈과 전용 검사만 수정한다.

실제 `AuthStartupController`에 합성 계정을 넣어, 이미 `ready`인 학생·교사의 토큰 조회 `auth/network-request-failed`와 프로필 구독 `unavailable`이 즉시 사용자 정보를 지우고 `error`로 전환하는 것을 재현했다. 기존 `locked` 상태는 연결 회복 후 정상 SDK 콜백으로도 풀리지 않았다. 따라서 수업·작업 화면이 사라지고 수동 재확인이 필요했다.

`SESSION_AUTHORITY_CONFIG_INVALID`도 `SESSION_` 접두사 때문에 서버 장애인데 재로그인 오류로 분류되고 기존 세션 증명이 폐기되고 있었다. 세션 앞단의 `maintenance-config-read-failed`, `maintenance-profile-read-failed`도 실제 서버의 일시 조회 실패 사유로 확인했다.

운영 `openApplicationSession`의 최근 7일 POST 4,121건은 200 응답 4,051건, 401 응답 24건, 403 응답 46건이었다. 처리 시간은 중앙값 0.859초, 95백분위 1.480초, 최대 5.535초로, 45초 이상 지연은 없었다. 401/403의 상세 거부 사유는 요청 로그에 없어 특정하지 않았다. 운영 보관 소스·설정의 `OBSERVE_ONLY`를 확인했으며 유휴 1시간 경고는 세션 종료 원인이 아니다. 클라이언트 전체 오류 발생률을 측정한 결과는 아니다.

## 변경과 경계

- 명시적으로 분류한 일시 오류에 한해 1초·3초 간격으로 최대 두 번 자동 복구한다. 정상 성공 경로에는 추가 요청이 없다.
- 프로필 구독은 본인 `users/{uid}` 구독만 다시 연결한다. 이미 서버에서 확인한 동일 계정의 화면과 작성 중 상태를 유지하며 세션 개설·설정 조회를 반복하지 않는다.
- 최초 로그인은 세션과 서버 프로필 확인을 모두 마치기 전까지 포털을 열지 않는다. 캐시·미확정 로컬 쓰기는 권한 근거로 쓰지 않는다.
- 프로필 재연결도 최대 60초 안에 서버 확인을 받아야 한다. 반복 실패·권한 거부·계정 정지·세션 철회는 기존 차단을 유지한다. 영구적인 통신 단절을 정상 인증 완료로 간주하지 않는다.
- 계정·인증 시각 변경, 수동 재시도, 로그아웃과 unmount는 대기 중 복구를 취소한다. 이전 구독의 늦은 응답은 수락하지 않는다.
- 서버 설정 장애는 재로그인을 요구하는 인증 실패에서 제외한다. 기존 세션 증명은 클라이언트의 권한 허가가 아니며 모든 서버 명령의 실제 검사와 영수증을 유지한다.
- 실패한 답안 제출·점수 변경 등 일반 쓰기는 자동 재전송하지 않는다. 자동 재호출은 기존 멱등 세션 확인과 인증 조회에만 적용한다.

Firestore 구독은 오류 콜백 이후 추가 이벤트가 오지 않으므로 해당 구독의 재연결이 필요하다. [Firebase 공식 구독 문서](https://firebase.google.com/docs/firestore/query-data/listen)의 오류 처리 계약을 참고했다.

## 비용·권한·적용 범위

정상 로그인은 기존 세션 개설 한 번과 본인 프로필 구독 한 개를 유지한다. 토큰만 일시 실패하면 프로필·설정·세션을 다시 조회하지 않는다. 프로필 오류 한 번은 본인 프로필 구독 한 번을 추가하며 세션 호출 증가는 없다. 세션 확인 일시 실패에는 실패한 호출 외 최대 두 번의 확인만 추가된다. 폴링이나 모든 사용자 조회는 없다.

공통 메모리 상태는 현재 SDK 사용자 객체·인증 세대에 한정되며 디스크에 프로필/권한 캐시를 추가하지 않는다. 학기 경로, 기존 보관·legacy 경로, 공개 차단 구독, 역할·승인·본인 자료 권한, 30일 비활동 정책은 그대로다. Functions와 rules 배포는 필요하지 않다. 기존 서비스의 인증 오류 처리 유지보수로, 이용자·개인정보 항목·외부 서비스·저장 위치·접근 권한을 확대하지 않는다. AI 호출·에이전트 실행·학생 자료 외부 전송 기능을 추가하지 않는다. 기관 보안성 검토 승인이나 면제를 새로 판정한 문서가 아니다.
