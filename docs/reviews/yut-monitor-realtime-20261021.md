# 윷놀이 모니터링 실시간 반영

회사 PC의 `main`을 `9d1a0ff4`에서 운영·원격 기준 `4d405f80`으로 동기화했다. 기존 미커밋 상태는 `codex company PC pre-sync backup 2026-10-21 9d1a0ff4` stash에 보존했다. 앱 변경은 원격에 이미 포함되어 있었고, 로컬 전용 검증 스크립트 캐시 처리와 `output/` 자료는 배포에 섞지 않았다.

모니터링 목록의 15초 폴링을 학기별 `yut_management/current` 변경 신호 구독으로 교체했다. 방 생성·진행·퇴장·종료·만료 삭제와 설정/이름 갱신을 기존 transaction에서 함께 알린다. 신호는 무작위 변경 ID와 시각만 담고, 학생 정보는 기존 권한 검사를 거친 `getYutManagement` 응답에서만 읽는다. 방 목록 직접 읽기와 학생의 신호 읽기는 허용하지 않는다.

열린 모니터링 목록에서만 구독한다. 150ms 안의 신호를 묶고 한 번에 하나의 조회만 수행하며, 조회 중 받은 신호는 후속 조회로 반영한다. 관전·닫기·숨김·계정/권한/학기 변경은 구독과 표시 자료를 해제한다. 서버가 확인하지 않은 캐시와 이전 연결의 늦은 응답은 표시하지 않는다. 오류에는 다시 연결을 제공하고 설정 초안은 유지한다.

네트워크 지연과 무관한 연속 만료 타이머로 오래된 방의 재등장을 막는다. 차례 제한 시각 이후 1분 이상 진행이 없는 방은 기본 목록에서 접어 두며 `최근 진행 없음`으로 구분한다. 이는 접속 여부 판정이나 게임 종료가 아니다. 펼쳐서 관전·닫기가 가능하고 진행이 재개되면 자동으로 기본 목록에 복귀한다.

기존 모달·방 카드·버튼·상태 텍스트·InfoHelp를 재사용하며 새 디자인 토큰은 추가하지 않았다. 390/768/1280px와 1366px에서 기존 한 열/두 열 목록과 단일 스크롤, 키보드 포커스를 확인한다.

검증: 앱 빌드·변경 TypeScript Prettier·Functions 전체 check, demo Firestore 통합 및 대기방 만료 검사, 교사 모니터링 브라우저 검사와 학생 공개 제어 회귀 검사. 추가 회귀는 burst 묶음, 조회 중 후속 신호, 숨김/재연결/닫기, 느린 응답 중 만료, 첫 만료 조회가 보류된 동안 두 번째 방의 만료를 포함한다. 운영 검증에는 Chrome `방재석` 프로필을 사용하며 테스트 방이나 학생 데이터를 만들지 않는다.

배포 대상: `commandYutRoom`, `getYutLobby`, `saveYutSettings`, `cleanupWaitingYutRooms`, Firestore rules 및 Vercel 프론트엔드. 배포 전 운영 rules가 기준 HEAD와 같고 경기 코어·세션 가드·설정 저장 로직이 운영 소스와 같음을 확인했다. Firebase CLI의 rules test 요청이 503으로 실패하여, 같은 공식 Rules API의 test 및 ruleset 생성으로 서버 검증을 통과한 뒤 release를 갱신하고 운영 소스를 대조했다.
