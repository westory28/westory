# 공부의 神문고 공개 준비와 검증

사용자 요청: 2026-11-10, 기존 관리자 초안을 학생에게 공개하고 기존 상단 알림에 연결한다. 정식 이름은 `공부의 神문고`이며 알림장은 핵심포인트 다음, 소개는 새 운영 일지의 이미지 본문으로 게시한다. 삽화는 긴 교복 바지의 남학생·안경 쓴 남자 선생님을 사용한다.

## 변경 경계

- 기존 Firebase·Vercel·학생/교사 계정을 사용한다. 런타임 AI 호출, 새 외부 서비스, 다른 학교·외부 이용자 공개는 추가하지 않는다. 새 데이터는 학습 질문·교사 답변·연결 자료 식별자·이용 안내 확인·질문 제한·알림이다.
- 질문은 현재 학기의 학생 본인과 교사만 callable로 조회한다. 공개 스토리는 교사의 별도 공개 문구와 비식별 자료 연결만 저장한다. 학생 계정 삭제 시 개인 질문·관련 스토리·확인·제한·영수증을 함께 정리한다.
- 기존 기관 검토 이력은 저장소에서 미확인이다. 이번 자동 검증은 기관 보안성 검토의 승인·면제를 뜻하지 않는다. 변경 자료 흐름은 기존 `security-review.md`의 내부 준비 목록에 추가할 근거이며 학생 질문은 외부 이미지 생성에 사용하지 않았다.
- 배포 대상은 서울 `getGongsinmoongo`, `manageGongsinmoongo`, `deleteStudentData`, Q&A 전용 Firestore 규칙·추가 색인과 프런트엔드다. 다른 함수는 함께 배포하지 않는다.
- `deleteStudentData` 운영 보관 소스를 받아 LF 정규화로 대조했다. 기존 삭제 본체와 세션·점검·학적 검사 및 의존성 잠금은 동일하며 현재 학기 삭제 수집기에 Q&A 자료만 추가한다. 이미 다른 배포에 존재하는 부가 함수 export 차이는 선택 배포 대상이 아니다.

## 이미지와 게시

- `public/notice-guides/20261110-gongsinmoongo/hero.webp`: 1200×675, 남학생이 신문고를 치는 대표 안내.
- `guide-01.webp`: 1024×1536, 개인 질문·기존 알림·선정 스토리. 선생님은 안경을 쓴 남자.
- `guide-02.webp`: 1024×1536, 구체적인 질문·평가 제출 후 질문·이용 약속.
- 내장 `image_gen.imagegen`으로 제작했으며 최종 프롬프트와 교정은 `scripts/content/gongsinmoongo-image-prompts.json`에 기록한다. `prepare-gongsinmoongo-launch-assets.mjs`는 승인된 원본의 규격·WebP·기존 공식 워터마크만 처리한다.
- `publish-gongsinmoongo-launch.mjs` 기본 실행은 읽기 전용이다. 게시 시 활성 학기·공개 설정·배포 이미지 SHA를 검사하고 핵심포인트 다음의 빈 순서에 새 알림장과 운영 일지를 원자적으로 생성한다. 같은 요청 재실행은 0회 쓰기이며 기존 편집 내용은 덮어쓰지 않는다.

## 검증 기록

- `npm run test:score-request-rules`: 통과. 본인 접근·다른 학생 차단·세션·점검·점수 요청 경계 회귀 확인.
- `node scripts/verify-student-profile-commands.mjs`: 통과. 기존 학생 삭제 어댑터의 세션·revision·복구 경계 확인.
- `npm --prefix functions run check`: 통과. Q&A 전용 에뮬레이터 통합 12개 시나리오와 색인 구조 검사도 통과했다. 본인/타인 자료, 시험 중 접수 차단, 공개 중단, 재시도, 삭제 수집기를 검사했다.
- 실제 세션·점검 조회를 포함한 합성 시나리오 계측: 질문 등록 21회 읽기·7회 쓰기·3회 쿼리(교사 수신자 2명), 같은 요청 재시도 11회 읽기·0회 쓰기, 답변 저장 10회 읽기·4회 쓰기, 변경 없는 답변 9회 읽기·0회 쓰기. 이는 해당 시나리오의 호출 계측이며 청구 건수 보장은 아니다.
- `scripts/verify-gongsinmoongo-browser.mjs`: 통과. 320/390/768/1280/1440px에서 문서 넘침·PC 내부 대화 스크롤·320px 질문 목록·1행 관리 도구·계정 전환·최초 안내·제한·저장 실패 재시도·기존 알림 진입을 확인했다. 초기 학생은 state 1회·questions 1회, 교사는 state 1회·questions 2회이며 쓰기는 없다. 받은 20개 안의 UI 페이지 4회 전환은 추가 조회·쓰기 0회다.
- 학습지 대안 답안·이미지 보호·평가 복습 팝업 회귀 3종 통과. 운영 학생 질문·답변·점수는 검증용으로 변경하지 않았다.
- 안내 글의 390/768/1280px 렌더에서 이미지와 대체 텍스트, 긴바지 남학생과 안경 쓴 남교사, 파란 `神`을 확인했다.
- 운영 색인은 기존 11개를 유지하고 필요한 6개만 추가했으며 모두 READY를 확인했다. 서버 첫 배포는 Firestore Rules API의 HTTP 503으로 중단되었으나 동일 대상 재배포가 성공했다. Q&A 함수 2개와 `deleteStudentData`의 ACTIVE, Firestore Rules 게시 완료를 확인했다.
- 다른 작업의 로딩 변경을 제외한 별도 checkout에서 최종 브라우저 검증도 통과했다(`output/gongsinmoongo-pure-browser-20261110/report.json`).
- 최종 분리 checkout의 `npm run build` 전체 사전 검사와 Vite 빌드 통과. 배포·공개 결과는 작업 완료 보고와 `output/gongsinmoongo-*` 실행 증거에 남긴다.
