## 핵심포인트

- 이미 포인트를 모두 찾은 상태에서 전체 진행 조회가 실패하면 수령 버튼으로 돌아갈 방법이 없었다. 기존 플로팅 위치의 `다시 확인`으로 복구하며, 명시적 재시도 중 동일 요청은 합친다.
- 지급되지 않은 응답은 수령 완료로 처리하지 않는다. 지급 성공·기존 지급 확인 뒤에는 불필요한 전체 진행 재조회를 하지 않으며, 늦게 도착한 미수령 조회가 이미 확인한 지급 상태를 되돌리지 않는다.
- 서버의 최신 자료 선택에서 숫자형 `updatedAt`을 조회 API와 동일한 밀리초로 해석한다. 날짜 문자열·Firestore Timestamp와 기존 공개·학급·학기 검사는 유지한다. 현재 지목된 운영 사례에는 숫자형 시각이 없으므로 이 회귀를 그 사례의 원인으로 단정하지 않는다.
- 보상은 현재 학기에 고정 source ID `lesson-core-points-all`로 한 번 지급하는 500위스를 유지한다. 원장·legacy 지급·완료 표시를 확인하며, 과거 일부 자료를 완주한 뒤 새 포인트가 추가되었다는 이유로 같은 학기 보상을 다시 지급하지 않는다.
- 사용자가 지목한 두 사례는 현재 70/70 완료이며, 11월 5일 당시 23/23 완료로 각각 500위스를 받은 원장이 있다. 원장의 전후 잔액 차이도 500이며 해당 지급의 역분개 문서는 없다. 학생 식별자·원장 원문은 저장소에 남기지 않는다.

## 이순신

- 키보드가 열린 가로 화면에서도 최소 경기 높이를 340px로 유지하던 조건을 제거한다. 실제 보이는 높이에 맞추고, 짧고 넓은 화면에서는 현재 단어와 입력칸을 좌우로 놓는다. 게임의 기존 테마와 44px 조작 영역을 유지한다.
- 단어 제출 시 현재 시각으로 만료 여부를 다시 검사한다. 사라진 일반·특수 키워드와 오답은 입력칸을 비우고 오답 피드백을 표시한다. 이 입력은 서버 명령·장전·포격·점수를 늘리지 않는다.
- 한글 조합 중 Enter, 실제 정답, 재전송, 교사 체험 미기록, 학생 공개 제어를 유지한다.
