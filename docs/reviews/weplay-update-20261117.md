# 위플레이 주간 보상과 게임 업데이트

기준 `c30f889740350cb683f6530a185c16b388c1a782`, 별도 checkout `C:\westory-weplay-update`에서 작업한다. 기존 `C:\westory`의 다른 미커밋 변경은 수정하지 않는다. 배포 전 운영 Vercel main도 같은 기준 커밋임을 API로 확인했다.

## 랭킹과 보상

- 학번·이름을 분리하고 순위·학번·이름·점수의 제목과 셀을 가운데 정렬한다. 실명을 가리지 않는다. 이전 가림 projection은 표시 대상 최대 50명의 지정 프로필 필드만 읽어 복원하며 서버의 60초 payload 캐시에서 공유한다. 새 윷·리듬 기록에는 전체 이름을 저장한다. 필드 선택은 전송량을 줄이며 문서 읽기 수 감소로 계산하지 않는다. 계정·세션·학기·공개·학급 검사는 캐시에서도 유지한다.
- 교사 게임 관리의 `주간 랭킹 보상`에서 게임·주차·랭킹 분류와 1~50위 이내 지급 구간을 설정한다. 구간은 이전 마지막 순위 다음부터 적용하며 0위스 구간을 허용한다. 기본은 미설정·무지급이다. 전체 랭킹 기준이며 기존 해전의 학급별 기간 보상·게임별 승리 보상과 별도로 표시/처리한다. 기존 약속된 보상은 변경하지 않는다.
- 사용자가 주 종료 후 자동 지급을 명시적으로 선택했다. 한국 시간 월요일 경계 뒤 10분의 완료 정산 유예를 두고, 15분 주기의 서버 작업이 기한이 지난 계획만 조회한다. 계획 4개씩 처리하고 나머지는 영속 큐에 남겨 다음 실행에서 계속 처리한다. 당첨자·주차를 임의로 누락하지 않는다.
- 주 종료 이후 설정 수정은 차단한다. 지급을 시작할 때 상위 순위와 보상 정책을 동결한다. 기존 canonical 위스 계좌·원장·투영과 지급 영수증을 같은 트랜잭션으로 기록한다. 동일 요청·동시 실행·부분 실패 후 재시도는 중복 지급하지 않는다. 삭제·승인 해제 계정은 제외 영수증을 남기고, 학기/계좌 오류는 보류하여 재시도한다. 한 계좌 오류가 다음 수상자의 지급을 막지 않는다.
- 설정 펼치기 전 조회 0회, 첫 펼치기·분류/주차 변경 각 1회, 초안 편집 0회다. 변경 없는 저장은 비활성이고 서버도 0쓰기다. 성공 설정은 세션 검사 3읽기 외 6읽기/3쓰기, 같은 요청 재시도는 6읽기/0쓰기다. 캐시·권한·오류 조건은 리듬 검토 문서에도 기록한다.

## 게임

윷 확률·속도·전체화면·통신 계측은 [윷 검토](weplay-yut-update-20261117.md), 리듬 연출·피버·반응형 검증은 [리듬 화면 검토](rhythm-update-20261117.md), 무료 횟수·유료 차감·서버 재판정은 [도전 서버 검토](rhythm-challenge-20261117.md)를 따른다. 리듬 도전은 기존 연습 랭킹과 별도 내부 분류를 사용하여 과거 연습 기록이 도전 보상에 들어가지 않게 한다. 과거 기록은 삭제하지 않는다. 주가 바뀐 뒤 종료한 도전에는 다른 곡의 다음 주 랭킹 점수를 기록하지 않는다.

새 외부 AI 호출·런타임 에이전트·외부 서비스·학생 정보의 외부 전송은 없다. 기존 서비스의 게임 유지보수이며 공개 설정은 교사의 기존 제어를 유지한다. 도전 출시 요청으로 기존 공개 게임 안의 도전 기능을 제공하되 비공개 게임 자체를 자동 공개하지 않는다.

## 검증과 배포

`npm run build`, `npm --prefix functions run check`, 관련 코드 포맷 확인, 윷·리듬·랭킹·보상 실제 Firestore 통합과 합성 브라우저 검증을 실행한다. 보상 검사는 권한·CAS·무변경·실패·재시도·동시 지급·탈퇴·기한·전체 큐 처리를 확인한다. 운영 학생의 위스·점수·도전 횟수나 교사 정책을 검증용으로 변경하지 않는다.

`scripts/prepare-weplay-update-release.mjs`는 함수별 운영 ZIP의 generation을 고정하고 원본 파일을 보존한다. 기존 `getWeplayRanking`, `startRhythmRankingGame`, `finishRhythmRankingGame`, `commandYutRoom`, `commandYutRoomFast`의 대상 모듈만 이식한다. start 함수는 원본 랭킹 출시 커밋 `45fe373c` 이후 재배포되지 않았음을 원본 비교로 확인했다. 나머지는 현행 기준과 일치하며 윷의 미배포 `getYutPublication` 분기를 이식하지 않는다.

신규 `getRhythmChallengeState`, `saveRhythmChallengeSettings`, `getWeplayWeeklyRewards`, `saveWeplayWeeklyRewards`, `settleWeplayWeeklyRewards`는 운영 랭킹 소스의 기존 보안·지갑 의존성을 보존한 독립 진입점에서 배포한다. rules·색인·공개 설정은 변경하지 않는다. 별도 준비본에서도 실제 통합 검사를 통과해야 한다. 선택 배포 후 `--verify`로 모든 배포 파일 해시·ACTIVE·기존 자원 설정을 대조한다. 동일 main의 Vercel 배포를 운영 도메인에 승격하고 `방재석` Chrome 프로필에서 실제 화면을 확인한다.

로컬 앱 빌드·Functions 기본 검사·변경 TS/TSX 포맷 확인을 통과했다. 랭킹 브라우저 26개, 리듬 11개, 교사 도전 설정 3개, 세 게임 보상 설정 9개와 공개/통신 9개를 통과했다. 도전과 보상의 실제 Firestore 검사는 로컬 및 운영 의존성을 보존한 준비본 모두 통과했다. 최종 순위 보상은 부분 계좌 실패 뒤에도 뒤 순위 지급, 동시 재시도, 정확한 지급 합계·원장 수를 검증했다.

검증 근거는 `output/weplay-update-20261117/` 및 각 게임 문서의 경로에 보관한다. 운영 성공 여부는 배포 후 소스 대조와 실제 화면으로 판단한다.
