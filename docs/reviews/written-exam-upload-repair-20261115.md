# 정기시험 파일 업로드 복구 (2026-11-15)

## 문제와 수정

- 실제 학급별 XLSX의 worksheet dimension이 `A1`인데 셀 데이터는 그 범위를 벗어나 있어 읽기 도구가 빈 시트로 판단했다. 기존 namespace 정규화 단계에서 실제 셀 범위와 모순되는 dimension만 메모리에서 제거한다. 원본 파일·셀 값·스타일은 수정하지 않는다.
- 명렬표의 첫 열이 비어 있고 `반/번호`가 B열에 있었다. 해당 헤더 위치로 학생 식별 열을 결정하며 기존 A열 양식도 유지한다.
- 운영 미리보기에서 9개 파일·284명 연결을 확인하는 과정에서 평가명이 파일명 `1`로 잡히는 후속 문제를 발견했다. 명렬표 상단의 NEIS 학년도·학기·학년·시험명·과목을 읽고 반 표기와 중복 학년을 제거하여 기존 점수표 제목 관례에 맞춘다. 다른 학기·시험·과목의 파일 혼합을 거부하며 기존 평가 한 개만 있다는 이유로 자동 연결하지 않는다. 최종 평가명은 교사가 미리보기에서 검토·수정한다.
- 같은 평가명·과목·학년이어도 서답형과 논술형은 별도 원장으로 저장한다. 기존 점수 화면은 원래의 학생별 합산 경로를 유지한다. 재업로드는 같은 유형의 기존 ID를 재사용하고 새 ID에만 유형을 포함한다. 다른 유형이나 혼합 원장을 덮어쓰지 않도록 저장 트랜잭션에서도 재확인하며 수행평가 ID 규칙은 바꾸지 않는다. 점수·분석·원안지 선택 목록에 유형을 덧붙여 같은 평가명을 구별한다.
- 문항정보표의 2단 난이도 헤더·원형 선택 표시·인쇄 꼬리말·선택형 이후 논술형 구역을 처리한다. 알 수 없는 행이나 중복 문항은 계속 오류로 알린다.
- 원안지의 안내문 번호와 실제 문항 번호를 구별하고 페이지 번호를 제외한다. 명시된 공통 지문 범위는 문항별 이미지 위에 합성하며 정답 선지 영역만 강조한다. 기존 크롭 스키마에 선택적 `contextRects`를 추가한다.
- 업로드 유형을 공통 밑줄 하위 탭으로 바꾸고 현재 유형의 기록만 표시한다. 자료 등록은 필수 선택 오류와 처리 단계를 표시하고 처리 중 중복 클릭·탭 이동·닫기를 차단한다. 자동 구분 성공 시 등록을 완료하며 영역 확인이 필요하거나 저장이 실패하면 준비 자료를 보존한다.
- PDF 업로드 뒤 manifest를 게시하는 같은 트랜잭션에서 연결 점수표의 존재·학기·유형·내용이 유지되는지 다시 확인한다. 변경·삭제 경합은 신규 자산을 정리하고 이전 revision을 유지한다. 원장 조회 중 계정 변경도 쓰기 전에 차단한다.

## 실제 파일 확인

사용자가 제공한 9개 학급 XLSX를 실제 브라우저용 읽기 라이브러리와 앱의 다중 파일 진입점으로 확인했다. 9학급·284명·선택형 21문항을 인식했으며 원본 SHA가 바뀌지 않았다. 문항정보표는 선택형 21문항·90점이며 원안지 4쪽에서 21개 크롭을 만들었다. 각 정답 강조가 하나이고 13~14번·18~19번의 공통 지문을 보존했다. 논술형 자료를 선택형으로 섞지 않는다.

학생 이름·개별 점수·원본 파일·실제 시험지 렌더는 저장소에 포함하지 않는다. 로컬 실제 파일 증거는 `C:/evidence/written-exam-actual-20261115`, 합성 화면 증거는 `C:/evidence/written-score-upload`에 둔다.

## 검증 범위

- 실제 XLSX reader 회귀를 `verify:written-exam-analysis`와 기본 빌드에 포함한다. 기존 다중 파일·논술형·NEIS 수행평가·원본 hair 테두리 회귀를 유지한다.
- 실제 컴포넌트의 합성 브라우저 검사로 320/390/768/1440px, 투명 페이지 제목, 하위 탭 키보드 이동·기록 필터, 처리 중 이동·닫기 차단, 여러 파일/시트 동시 인식과 일부 파일 오류의 전체 중단을 확인한다.
- 실제 Firestore/Storage 에뮬레이터에서 자료 저장·manifest 재조회·보호된 파일 바이트·원장 변경/삭제 경합·실패 정리·응답 유실·재시도·다른 학생 및 만료/해지 세션 차단을 확인한다. 합성 대규모 선택형 payload의 저장 검사는 실제 UI 저장 handler 실행과 구별한다.
- 최종 결과: 기본 빌드·전체 TypeScript 포맷·점수 요청 rules 통과, score source 45개 및 Firestore/Storage 48개 검사 통과. 284명×21문항 점수를 교사 권한 트랜잭션으로 저장하고 전체 상세를 재조회했으며 기존 논술 원장은 유지됐다. 브라우저에서는 CAS 오류 후 최신 등록 상태 조회·재시도와 정답 변경 시 기존 PDF 재처리·원본 바이트 보존도 확인했다.
- 후속 저장 경로는 `saveParsedScores` 전체 함수를 AST로 추출하여 합성 Firestore에서 실행했다. 같은 이름의 기존 논술 285명 원장·점수·서명을 그대로 보존하면서 선택형 284명×21문항 첫 등록은 원장 1건+학생 284건, 같은 파일 재등록은 같은 ID의 원장 1건·학생 0건 쓰기였다. 기존 선택형/구형 논술형 ID 재사용, 혼합 원장과 트랜잭션 중 유형 변경의 쓰기 0건, 수행평가 ID 유지도 확인한다. 이 검사를 기본 빌드에 포함하며 실제 Firestore 권한·용량 검증과 구분한다.
- 운영에서는 같은 배포 커밋과 교사 업로드 화면을 확인한다. 학생 점수·서명·이의 상태를 QA 목적으로 변경하지 않는다.

## 조회·권한·영향

원장 재확인은 등록 마지막 트랜잭션에 해당 학기·점수표 문서 한 건 읽기를 추가한다. 비교는 메모리에서 수행하며 학생 자료를 로그에 남기지 않는다. 탭의 기록 필터·키보드 이동은 서버 쓰기를 만들지 않는다. 미사용 자료 탭을 조회하지 않는 기존 지연 로딩을 유지한다. 공통 XLSX reader는 수행평가와 정기시험 가져오기에도 적용되므로 기존 양식·테두리 회귀를 함께 실행한다.

Functions·Firestore/Storage rules·학생 화면·AI 호출·외부 서비스는 변경하지 않는다. 기존 기관 내부 평가 관리의 입력 호환성·오류 복구 유지보수이며 새로운 개인정보 항목·전송 대상·학생 공개 범위를 추가하지 않는다. 프론트엔드의 Vercel main 배포만 운영 반영한다.
