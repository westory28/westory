# 2D 아바타 의상·포즈 정합성 보완

요청: 자연스러운 2D 체형에 맞게 의상을 전부 다시 만들고 포즈 변경 및 헤어 이탈을 수정한다.

기준 checkout은 `C:\westory`, 시작 HEAD는 `fd44c09cf261e956681a916ced2be1dbd1599e5b`였다. 병행 시험 진입 패치 `4c2e0858b29c5f4f9168d87500a94d2598286cad`와 분석 도움말 패치 `85263bba6c9782bfcfe8569fba5d468331fec3fa`를 보존하고 아바타 변경만 별도로 검증·커밋한다. 기존 `output/`, `tmp/`와 다른 작업의 파일을 커밋에 포함하지 않는다.

## 변경

- 연결된 Higgsfield에서 새 원화 7장을 제작했다. 모델·작업 ID·프롬프트 명세는 [원화 기록](../../assets/avatar-source/v3/README.md)에 있다. 상의 15종, 하의 12종, 신발 5종의 모든 기존 ID에 새 원화를 연결한다.
- 상의는 어깨·소매·팔꿈치·손을 잘라 회전시키지 않고 기본·인사·응원·생각·하트마다 이어진 전체 원화를 사용한다. 고개 기울이기는 기본 의상과 머리 그룹 회전을 조합한다.
- 선택 항목의 포즈별 레이어와 숨김 규칙을 지원한다. 가려진 하의의 숨김 규칙이 계속 다리를 지우던 문제도 수정했다. 관복·치마·한복 바지에서 발목이 신발 안쪽을 채운다.
- 긴 머리는 얼굴 아래에서 앞·뒤로 나누며 경계를 조금 겹쳐 반투명 선을 방지한다. 모자 가림은 머리카락과 두상에 적용하고 머리 기울이기와 함께 이동한다.
- 의상 재색칠과 피부색 변경은 같은 원본 피부 마스크를 공유한다. 관복은 포즈별 목·손 윤곽을 명시하여 흉배·금속 장식·깃을 피부색으로 칠하지 않는다.
- 원본 PNG는 개발 자료로만 보관한다. 런타임은 최대 640px 의상 WebP와 무손실 피부 마스크를 선택적으로 읽고 앞·뒤 헤어는 같은 이미지 자원을 공유한다.

## 유지 범위

카탈로그 ID·가격·보유·구매·저장·학기·권한과 서버 조회·쓰기 계약은 변경하지 않는다. 기존 저장 프로필 이미지는 보존하며 사용자가 아바타 저장을 누르면 새 원화로 갱신된다. 학생·교사 화면 배치는 유지하고 공통 2D 합성에만 적용한다. Functions·rules 배포는 필요하지 않다.

생성 도구에는 위스토리 자체 공개 원화와 신규 생성 의상만 참조로 전달했다. 학생·교사 사진, 개인 기록, 자격 증명은 전달하지 않았다. 앱 런타임 AI 호출·외부 전송·공개 범위·수집 항목 추가가 없는 기존 기능 유지보수다.

## 검증

- `verify-avatar-2d-renderer.mjs`: 포즈별 교체, 숨긴 하의의 다리 가림 무효화, 모자 가림/기울이기/해제, 잘못된 경로·포즈·clip 거부, 로딩 실패 시 기존 프레임 보존, 빠른 선택 취소, 자원 정리, 투명 전신 캡처, WebGL 미사용.
- `verify-avatar-skin-mask.mjs`: source cell 좌표의 피부 영역·윤곽, crop 후 좌표 보존, 피부색과 같은 옷/금색의 분리, 정규화·염색·의상 재색칠의 공통 마스크, 재빌드 해시.
- `verify-avatar-studio-service.mjs`: 한 번의 조회, 교사 접근, 가격 확인 구매, 중복 요청, 세션 경계 회귀.
- `verify-avatar-outfit-fit.mjs`: 상의×6포즈 180개, 헤어×모자×얼굴형×기본/기울이기 198개, 하의 108개, 신발 20개 등 총 506조합. 원화·프레임·큰 분리 조각·신발 입구의 투명 구멍을 검사하고 실제 접촉시트를 시각 검토한다. 발견한 한복 바지 36조합은 보정 뒤 `--match=baji`로 재검증한다.
- 학생·교사 각각 390/768/1280px에서 화면 넘침, 캔버스와 저장 버튼을 검사한다. 실제 계정 쓰기는 하지 않는다.
- 최종 조합 검증은 기존 470개 성공과 보정 후 한복 바지 36개 성공을 정확한 조합 키로 합쳐 506개를 확인했다(`combined-report.json`).
- 실제 꾸미기 카탈로그 브라우저 검증은 캐릭터별 151개 선택, 각각 6포즈, 학생 320/390/768/1280px·교사 390/768/1280px를 통과했다. 로컬 합성 구매 1회·투명 저장 2회, 브라우저 오류 0건·구형 3D 요청 0건이다. 최종 153개 미리보기와 19개 캡처를 `catalog/report.json`에 기록했다.
- 원화·등록표·compiler·배포 레이어 해시 및 모든 선택 항목 미리보기 지문을 검사하고 `npm run build`를 통과해야 한다.
- 최종 `npm run build` 전체 사전 검사·TypeScript·Vite 빌드가 통과했다. 기존 SSR `useLayoutEffect`와 큰 청크 경고는 남아 있으나 빌드 오류는 없다.

자동 이미지 검사는 패션 취향을 판정하지 않는다. 목·허리·발목, 어깨/소매/손 연결, 모자와 헤어 겹침, 피부 마스크는 실제 합성 이미지와 원본 마스크를 별도로 확인한다. 검증 증거는 `output/avatar-fit-20261110` 및 선택 재검증 폴더에 남긴다.

## 운영 반영

프론트엔드만 main에 푸시하여 검증 커밋의 Vercel 배포 성공 후 운영 도메인으로 승격한다. 도메인의 배포 ID·커밋과 원화 manifest/대표 이미지 지문을 대조하고 방재석 Chrome 프로필에서 실제 꾸미기·포즈 전환을 확인한다. 운영의 아바타 저장·위스 구매는 검증 목적으로 실행하지 않는다.
