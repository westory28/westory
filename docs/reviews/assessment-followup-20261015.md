# 평가 후속 개선

## 사용자 기준

- 본문·문항·선택지·보기·힌트·팝업은 가능한 한 어절 단위로 줄바꿈한다. 목차는 예외로 항상 한 줄이며, 넓이를 확보하고 남는 긴 제목은 말줄임과 전체 제목으로 제공한다.
- 확신도 선택을 없애고 풀이 시간·첫/최종 응답 시간·수정·재방문·실제 점수와 분포를 사용한다. 시간만으로 찍기·능력·숙달을 단정하지 않는다.
- 교사는 내부 서식 표기 대신 시각 편집기로 지문을 편집한다. 기존 문항 저장 형식과 학생 렌더링 의미를 보존한다.
- 학생 마이페이지는 본인의 실제 평가 결과를 보여준다. 기록 없음, 실제 0점, 답안 원문 미보관, 관측 기록 없음을 구분하고 가짜 보정 값·중복 기록·근거 없는 성과 문구를 제거한다.
- 서술형 및 AI API 연동은 이번에도 범위에 포함하지 않는다.

## 변경 전 확인

기준 작업 공간은 기존 평가 작업의 격리 checkout이며 HEAD는 `3c4ae88`이다. `C:\westory`에 진행 중인 지도 작업은 수정하지 않는다.

마이페이지에는 실제 응시 기록 조회가 있지만 canonical/legacy 중복, 누락 점수의 0점 처리, 남은 학습 수의 최소 1 보정, 고정 점수 기준 칭찬·향상 문구가 있었다. 모의고사의 `mockExam` 이름은 예시 데이터가 아니므로 유지한다. 과거 canonical 기록의 학습 분류 스냅샷은 당시 문항 원문을 포함하지 않아 현재 문제은행 원문을 과거 원문으로 단정하면 안 된다.

운영 Functions 소스는 인증된 읽기 전용 API로 확인했다. `executeCommand` generation `1792064037131628`의 gateway 55개 파일은 HEAD와 LF 기준 동일했다. `getAssessmentState` generation `1792063319477055`, `saveAssessmentProgress` generation `1792063319668887`은 `historyClassroomExemptions.js`만 차이가 있으며, 현재 HEAD의 `7f43f3f` 면제권 성능 개선 이전 배포였다. 나머지 54개 파일은 같았다. 배포 시 이 최신 개선도 보존한다.

## 구현

- 공통 본문은 `keep-all`과 긴 단어의 비상 줄바꿈을 사용한다. 코드 표시는 제외한다. 문제 목차는 데스크톱 320px·태블릿 288px이며 한 줄 말줄임과 전체 제목을 유지한다.
- 확신도 UI·수집·추천 의존을 제거했다. 관찰되지 않은 문항과 시간은 0으로 만들지 않는다. 첫·최종 응답, 답 변경, 재방문, 힌트 사용을 정오답과 함께 표시하며 속도로 학습 능력을 단정하지 않는다.
- 교사의 지문 편집은 밑줄·네모·빈칸·글머리표를 시각적으로 적용한다. 기존 토큰 저장 형식, 인접 네모·빈칸의 구분, 한글 조합, 실행 취소·다시 실행을 보존한다. 붙여넣은 HTML은 지원 서식과 텍스트만 읽어 다시 만든다.
- 마이페이지는 실제 응시의 횟수·최근 점수·평균·분포·답안 확인을 연결한다. UID/학기·명시적 응시 참조로 범위를 검사하고 중복을 제거한다. 원문·정답·학생 답안·점수·관찰 기록의 누락을 각각 구분한다.
- 새 응시는 당시 문항을 비공개 응시 기록에 보관하고 풀이 화면에는 정답·해설·연결 정답 쌍을 제외한 문항만 전달한다. 제출 후 불변 결과에서 원문을 조회한다. 단일 문항 32KiB·전체 128KiB와 문서 여유 예산을 넘으면 문항 전체를 명시적으로 제외하며 원문을 잘라 저장하지 않는다. 과거 원문이 없거나 용량 때문에 빠진 문항을 현재 문제은행으로 복원하지 않는다.

## 검증 기록

- `npm run build`, `npm run format:check`, `npm --prefix functions run check` 통과. 빌드에는 수행평가 XLSX `hair` 점선 회귀가 포함된다.
- 평가 공개/응시 안전성, 학습 근거 18개 시나리오, 로컬 시간 계측, 문항 서식 26개 회귀, 기존 타입 계약 회귀 통과. 기존 타입 검사의 지도 빈칸 추출 helper 의존 누락을 보완했으며 제품의 지도 코드는 수정하지 않았다.
- 서버 회귀는 응시 시작 → 저장 → 문제은행 발문·정답 변경 → 재개 → 제출 → 응답 재조회에서 당시 원문·채점 유지, 6개 유형의 풀이 자료, 정답의 제출 전 제외, 용량 초과 명시 누락과 기존 응시 호환을 확인했다.
- 교사 시각 편집은 브라우저 DOM/붙여넣기 검사 14개와 실제 은행 수정 → 저장 → 재열기를 통과했다. 인접 네모·빈칸, 이미지·보기·힌트·해설·분류 연결을 보존했다. 390/768/1440px에서 긴 지문과 가로 넘침을 확인했다.
- 교사 목차는 390/768/1280px에서 한 줄·말줄임·전체 제목과 화면 폭을 확인했다. 학생 검증은 생산 화면을 로컬 합성 데이터로 실행하며 운영 학생 기록을 만들거나 삭제하지 않는다.

## 운영 반영

배포 직전 원격 main에 `cccf8a3` 지도 개선과 `7165482` 역사교실 저장 복구가 추가된 것을 확인했다. 운영 `executeCommand` generation `1792065952797495`는 기존 기준과 `assessmentLifecycle.js`만 다르므로 최신 변경을 병합하고 재검증한 뒤 이번 세 함수만 배포한다. 프런트엔드는 최신 main의 Vercel 배포를 운영으로 승격하고 `www.westory.kr`에서 확인한다. 최종 커밋과 실제 배포 결과는 작업 완료 응답에 기록한다.
