# 평가 제출·오답노트 연결 점검 (2026-11-08)

## 확인하고 수정한 문제

- 이미 다른 탭에서 제출한 응시를 다시 제출하면 서버의 점수·정오답과 현재 탭의 임시 답안이 섞일 수 있었다. 최초 제출과 재요청 모두 서버에 확정된 답안을 반환하고 제출 완료 화면도 이 답안을 사용한다.
- 응시 당시 머리말은 attempt에만 저장되어 마이페이지에서 사라졌다. 새 결과에 동결 머리말을 보존하고 기존 결과는 소유권·학기·결과 연결이 일치하는 해당 attempt 한 건에서 복원한다.
- 마이페이지의 문항 변환에서 공통 지문과 〈보기〉가 빠졌다. 제출 당시 스냅샷을 시험지·상세·복습에 그대로 전달한다.
- 기존 복습 답안과 선택 이유는 화면을 닫으면 사라졌다. 사용자 요청에 따라 연습 답안·이유·자유 노트를 별도 저장하고 마이페이지에서 다시 읽는다. 순서·연결형의 부분 답안은 미채점 상태로 보존한다.
- 구형 링크를 새 key로 변환할 때 저장 대상 key와 재조회 캐시가 어긋날 수 있었다. 실제 응답 key를 보존하고 같은 결과를 가리키는 캐시를 함께 갱신한다.

## 저장 범위와 불변 조건

노트는 인증 UID·학기·응시 결과 key별로 분리하며, 본인의 제출된 오답과 보관된 원문만 허용한다. 현재 활성 학기에서만 수정하고 과거 기록은 읽는다. 명시적 저장, revision 충돌 검사, 같은 저장 ID 재시도를 사용한다. 오류나 충돌 시 작성 중인 내용을 유지하며 최신 노트를 확인한 뒤 다시 저장한다. 원래 점수·답안·응시 횟수·보상은 변경하지 않는다.

노트 상세 조회는 선택한 응시의 노트 문서 한 건을 추가한다. 기존 결과의 머리말이 빠진 경우에만 해당 응시 한 건을 추가 읽는다. 전체 학년이나 문제은행을 다시 조회하지 않는다. 학생 삭제의 기존 대상 학기·학생 범위에 노트를 포함하고 삭제 진행 중 저장은 거부한다. 외부 AI 호출·외부 데이터 전송은 없다.

## 검증

| 검사 | 결과 |
| --- | --- |
| 실제 React 제출 → 마이페이지 → 노트 저장 → 새로고침·재조회 | 모의·진단·형성 × 390/768/1280px, 9조합 통과 |
| 저장 실패·응답 재시도·동시 수정·부분 답안·입력 보존 | 전용 브라우저 검사 통과, 320~1280px 가로 넘침 없음 |
| 문항·답안 동일성 | 18개 흐름과 이미 제출된 응시의 다른 탭 재요청 통과 |
| 실제 callable·Firestore 에뮬레이터 | 평가 3종 제출·조회·노트 저장·충돌·재시도·타인 차단·학기 경계 통과 |
| Firestore 직접 접근 | 학생·교사·비로그인의 노트 직접 읽기·생성·수정 차단 확인 |
| 기존 공통 세션·점수 요청 권한 | `npm run test:score-request-rules` 통과 |
| 기본 검증 | `npm run build`, `npm run format:check`, Functions 전체 check 통과 |

검증은 합성 계정과 로컬 fixture·에뮬레이터를 사용했다. 실제 학생의 응시·답안·점수·노트·계정은 시험 목적으로 변경하지 않았다. 모바일·태블릿 검증은 브라우저 크기·터치 모사이며 실물 기기 검증을 뜻하지 않는다.

배포 대상과 운영 소스 차이 확인은 [운영 배포 절차](../runbooks/production-release.md)의 ‘제출 답안 복원과 오답노트’를 따른다. 자동 재현 스크립트는 `verify-student-quiz-review-flow.mjs`, `verify-quiz-review-notes-browser.mjs`, `verify-quiz-history-identity.mjs`, `verify-quiz-release-integration.cjs`다.
