# 역사 지도 문체 정비 및 시간 변화 기능 조사

조사일: 2026-10-15. 대상: 한국사·세계사·지구본의 설명과 한국사의 시대별 영역 지도. 이 문서는 자료 조사와 구현 제안이며, 새 역사 경계 폴리곤을 앱에 추가하지 않았다.

## 판단

검증된 사건의 연도와 도시·수도 이동을 연결하는 기능은 현재 데이터로 시작할 수 있다. 조선의 행정구역 변천을 담은 학술 GIS도 존재하지만, 공개 파일이라는 이유만으로 전체를 앱에서 재서비스할 수 있는 것은 아니다. 자료마다 복원 범위와 시간 조회 방식이 다르다. 삼국의 영토를 매년 정확한 경계로 제공하는, 재사용 조건까지 확인된 공식·학술 벡터 데이터는 이번 조사에서 찾지 못했다.

따라서 우선순위는 **사건·도시 변화 → 허가와 검수를 거친 조선의 특정 시점 → 검증된 영역 변화**로 둔다. 자료를 찾지 못했다는 조사 결과가 해당 자료의 부재를 입증하는 것은 아니다.

### 조선 행정구역 DB의 중요한 조건

제작자는 김현종·김종혁 등이며, 변경 이력에 근거와 공간 식별자를 연결한다. 2026년 1월 공개 SHP의 기준 자료 시점은 1454·1530·1765·1789·1864·1910년이다. 작성자는 도형의 `begin`·`end`만으로 정확한 시간 조회가 되지 않으며 이력 테이블과 연결해야 한다고 명시한다. 초기에는 중심지의 원으로 영역을 대신한 경우도 있다. `영역복원안됨`·`임시복원` 메모를 가진 도형을 확정 경계로 표시하면 안 된다. 별도 경계선·월경지 자료는 1864년 기준만 구축되었다는 설명도 있다. 이는 모든 폴리곤이 1864년 것이라는 뜻은 아니다. [제작자 설명과 설계](https://www.hisgeo.info/wiki/index.php?title=조선_행정구역_DB&oldid=7133)

같은 페이지는 비영리 논문·연구서에서의 인용 사용을 허용하면서 영리 프로젝트의 사전 협의와 전체 자료의 외부 서비스 제한을 명시한다. 페이지 하단의 [CC BY-NC-SA 4.0](https://creativecommons.org/licenses/by-nc-sa/4.0/) 표시만으로 첨부 데이터의 개별 조건을 무시하지 않는다. 교육용 앱에 사용할 범위·가공·공개 방식은 제작자와 확인해야 한다. 이번 작업에서 문의를 발송하거나 사용 승인을 받은 것은 아니다.

### 근현대 자료와 고지도 좌표의 차이

국사편찬위원회의 근현대 경계는 측량 지도와 행정구역 변경 문서를 토대로 복원한다. 그러나 1914년 개편처럼 여러 해에 걸친 변화를 기준일에 묶은 경우가 있어, 날짜 필드가 항상 그날의 물리적 경계를 뜻하지는 않는다. [복원 방법과 시간 처리 기준](https://hgis.history.go.kr/pro_g1/intro/intro01.do)

국사편찬위원회가 별도로 공개한 근대 지명 포인트 SHP는 EPSG:5179이며, [배경지도 API](https://hgis.history.go.kr/api/intro.do)는 인증키를 받는 1919년·1970년대 WMTS 서비스이다. 포인트 파일이나 배경 타일을 삼국 영토 폴리곤으로 오인하지 않는다. [근대지리정보 자료와 좌표계](https://hgis.history.go.kr/mod_g1/main.do?INFO=ON)

대동여지도 DB는 `Oldmap ICS Joseon Ri`라는 고지도 방안 좌표계를 설명한다. 일부 미완성 경계는 추정해 연결했으며, 하천 국경을 도형상 선으로 만들더라도 표현할 때는 하천 영역으로 다룰 것을 권고한다. 이 자료의 좌표를 WGS84로 이름만 바꾸거나 단순 배율로 맞춰서는 안 된다. 실제 활용에는 기준점·변환 모델·잔차 검토가 필요하다. [좌표계와 경계 제작 원칙](https://www.hisgeo.info/wiki/조선_대동여지도_DB)

삼국·가야의 군사적 경계나 문화권은 점유 거점과 문헌·고고학 자료를 해석해 복원하는 연구 대상이다. 예를 들어 가야 영역 연구는 경계와 시기의 불확실성을 명시한다. 이 연구를 임의의 연도별 좌표 목록으로 변환할 수는 없다. [남재우, 「기록으로 본 가야문화의 성격」, 2015](https://www.kci.go.kr/kciportal/landing/article.kci?arti_id=ART001965984)

이번 조사는 제공 기관·제작자의 설명, 공개 목록, 학술 자료를 확인한 단계이다. SHP 전체를 내려받아 좌표계·자기교차·누락·도형별 복원 등급을 검수한 단계는 아니다. 따라서 어떤 후보도 바로 배포 가능한 정밀 역사 경계로 승인하지 않는다.

## 현재 데이터로 가능한 첫 구현

### 사건과 도시를 시간순으로 탐색

현재 `AtlasHistoricalStory`에는 `startYear`, `endYear`, `period`, `placeIds`, `sources`가 있다. 사건 이전·다음 버튼과 연도 선택으로 해당 이야기와 지도점을 함께 선택하는 기능을 구성할 수 있다. 한국사·세계사 과목 범위와 지구본의 통합 범위는 유지한다.

427년 이야기의 원본 `placeIds`에는 국내성(`kr-3a00fcea8b71`)과 평양(`pyongyang`)이 있으나, 이번 감사 시점의 선별 데이터에는 평양만 남아 있다. 국내성은 역사 의미가 확인되어도 좌표가 `null`이므로 지도·목록·연표에서 제외한다. 두 도시를 잇는 기능은 국내성의 위치 근거를 확보해 좌표를 검증하고 선별 목록에 복구한 뒤에만 가능하다. 이 조건이 충족되기 전에는 국내성의 점이나 연결선을 만들지 않는다.

905년 천도와 911년 개칭을 하나의 사건으로 합치지 않는다. 국호가 바뀌었다는 기록만으로 영토가 바뀌었다고 표시하지 않는다. 위 사건은 기존 데이터의 활용 예시이며 이번 조사에서 새 이야기를 앱에 추가한 것은 아니다.

### 시간과 이동의 의미를 명시

- `period`가 ‘8세기 중엽’처럼 대략적인 시기이면 정렬용 `startYear: 750`을 ‘750년에 확정적으로 일어난 사건’으로 표시하지 않는다. 화면에는 검증된 원래 시기 표현을 유지하고, 정확한 연도·연도 범위·세기 추정의 정밀도를 구분한다.
- 단일 사건과 일정 기간 지속된 상태를 구별한다. `endYear`가 없다는 이유로 그 사건이 현재까지 계속된다고 처리하지 않는다. 이야기의 기간도 곧 국가의 존속 기간이나 영토 유효 기간은 아니다.
- 천도 연결선에는 검증한 출발 도시와 도착 도시를 별도로 지정한다. 같은 이야기의 `placeIds` 전체를 순서대로 연결하지 않는다. 해당 배열에는 국가·도시·유적이 함께 있을 수 있다.
- 두 도시를 잇는 선은 천도의 관계를 나타낸다. 실제 이동로를 복원한 선으로 표시하지 않는다. 경로 사료가 확보되면 별도의 경로 자료로 구분한다.
- 좌표 미확정 장소는 지도·목록·연표에서 모두 제외한다. 임의의 중심점이나 도형을 만들지 않는다. 검증 근거가 확보되면 위치와 역사 설명을 함께 재검토한 뒤 선별 데이터에 복구한다.

첫 화면은 현재 지도 안에서 연도별 사건을 선택하고 장소 팝업을 여는 구조를 유지한다. 재생은 사용자가 시작하며, 정지·이전·다음과 키보드 조작을 제공한다. 연도 선택만으로 지도를 계속 이동시키기보다 선택한 사건의 장소로 이동할 때 맥락을 보여 준다. 이는 구현 제안이며 이번 패치에 재생 기능을 넣지 않았다.

### 영역 기능의 다음 단계

조선 영역 지도를 진행한다면 먼저 특정 기준 자료 시점 하나를 선정한다. 제작자 사용 조건을 확인한 뒤 근거가 있는 도형만 검수하고, 출처·기준 시점·복원 상태를 함께 저장한다. 검수 전에는 ‘조선 8도’라는 하나의 외곽선을 조선 전체 기간에 반복 적용하지 않는다.

영역 데이터는 최소한 `source`, `sourceVersion`, `license`, `validFrom`, `validTo`, `datePrecision`, `geometryType`, `crs`, `reconstructionStatus`를 가진다. 불확실한 경계는 표시 방식으로도 구별해야 한다. 이력과 공간 식별자를 결합한 결과를 검수한 후에만 시간 필터에 연결한다. 점 사이를 채운 임의 폴리곤이나 현재 행정구역을 과거 왕조 경계로 대체하는 방식은 적용하지 않는다.

데이터 8개 파일과 공통 팝업 1개 파일을 수정했다. `historyAtlasPlaceProfiles.ts`와 `historyAtlasProfiles.ts` 등 이미 평서형인 파일은 불필요하게 바꾸지 않았다. ‘아닙니다 → 아니다’, ‘다릅니다 → 다르다’, ‘필요합니다 → 필요하다’처럼 형용사 어미를 구별했다. 후속 검토에서 동사 부정형 1,667곳을 ‘뜻하지 않는다’, ‘표시하지 않는다’처럼 교정했으며, 상태를 나타내는 ‘알려져 있지 않다’는 보존했다. ‘트리니다드 토바고’의 고유명사와 평서형 ‘아니다’는 ‘니다’ 검색에 걸려도 수정 대상이 아니다.

문체 변환 직후 데이터 8개 파일을 TypeScript AST로 비교하여 허용된 설명 문자열 외 구문·ID·숫자·좌표·제목·출처 URL이 동일함을 확인했다. 인용부호 안 텍스트도 보존했다. 설명 문자열의 존댓말 어미 잔여는 0개이다. 공통 팝업의 출처 캡션 정리는 새 ‘등장한다’와 기존 ‘등장합니다’를 모두 인식하도록 수정했다.

검증 기록은 로컬 임시 폴더 `.codex-tmp/prose-style-validation.json`에 두었다. `tsc --noEmit`, 대상 파일 Prettier, `git diff --check`를 통과했다. 역사 데이터 검증은 동시 작업의 dataset export 변경과 통합한 뒤 주 작업에서 다시 수행한다. 문체 정비는 사용자에게 답하는 존댓말 원칙을 변경하지 않는다.
