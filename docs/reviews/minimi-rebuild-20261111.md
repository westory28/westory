## 실행 순서와 완료 조건

1. **범위 확정**: 저장·보유·공개 복제·순위·이미지 실패 fallback·Storage 경로를 모두 찾는다. 사용자 자료를 출력하거나 실계정으로 구매·저장 QA를 하지 않는다.
2. **새 규격**: 단일 정수 픽셀 격자, 두상/목/어깨/허리/발 기준점을 고정한다. 새 catalogVersion 2와 `minimi-` ID 및 `mm-` 선택값을 사용한다. 구버전 선택을 부분 변환하거나 소유품으로 복구하지 않는다.
3. **동일 작화 체계**: 피부·눈매·헤어·의복을 같은 좌표에서 그린다. 헤어 뒷부분→몸/의복→얼굴→앞머리/장식 순서를 명시한다. 팔·손·소매는 같은 포즈 관절로 그려 연결한다. 정지·인사·응원 3포즈만 먼저 완성한다.
4. **학교복 우선**: 흰색/네이비 하복 상의와 반바지, 회색 동복 후드 집업/반집업과 긴바지, 민트 세 줄과 학교 마크를 반영한다. 학교복 6종은 무료로 유지한다. 일반 니트·맨투맨·청바지·치마는 기존 판매 정책에 맞춘다. 모든 품목 미리보기·저장 이미지·실제 착용이 같은 렌더링 함수를 사용한다.
5. **연결 정리**: 구 renderer·실행 자산·구형 기본 이미지 fallback을 제거한다. 새 버전만 저장·표시하고 구형 캐시 응답도 거른다. 학생의 구 선택/보유/썸네일·공개 복제를 제거하고 Storage v1 이미지를 정리한다. 구매 영수증과 위스 거래 원장·감사는 보존하여 결제 재실행과 원장 손상을 막는다. 교사 공통 아바타도 구형 표시가 남지 않게 같은 버전 경계를 적용한다.
6. **검증과 출시**: 실제 합성 시트에서 모든 헤어×의복×포즈의 정렬과 관통을 확인한다. 학생/교사 390·768·1280px 및 작은 휴대전화에서 선택·미리보기·저장·오류·재시도를 확인한다. 빌드, Functions 검사, 아바타 에뮬레이터 검사를 통과한다. 삭제 dry-run의 정확한 대상과 범위를 검사한 뒤 운영 정리하고 재검사한다. 필요한 Functions만 운영 원본과 대조해 선택 배포하고 검증한 프론트엔드 커밋을 운영 도메인에 반영한다.

## 기술·운영 경계

- 화면 구성은 기존 `education-web-design-system`, `DESIGN.md`, `UI_RULES.md`를 따른다. 제목·탭에 흰색 컨테이너를 추가하지 않는다.
- 네트워크에서 따로 받은 머리와 의상을 임의 확대/이동하여 맞추지 않는다. runtime AI 호출·학생 자료 외부 전송·새 개인정보 수집은 없다.
- 표시 renderer는 사용자 선택 또는 크기 변경 때만 그리며 무한 프레임 루프·폴링·아이템별 서버 조회를 추가하지 않는다. 확대는 nearest-neighbor로 한다.
- 조회는 기존 계정·세션·학기 범위를 유지한다. 정리 도구는 필요한 아바타 필드만 projection하고 cursor로 끝까지 처리한다. projection은 문서 읽기 수 감소로 보고하지 않는다.
- 운영 삭제는 구버전만 대상으로 하며 transaction/세대 조건으로 동시에 새로 저장한 선택을 덮어쓰지 않는다. 재실행하면 변경이 없는 대상은 쓰지 않는다.
- 거래 원장·감사·구매 영수증은 아바타 선택 데이터와 구분한다. 이번 사용자 요청으로 원장 금액을 변경하거나 환불을 임의 생성하지 않는다.
- 기존 `three` 의존성은 윷놀이가 사용하므로 제거하지 않는다.
