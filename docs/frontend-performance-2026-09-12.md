# 교사 화면·로딩 개선

학생 접속은 사용자의 별도 개방 요청 전까지 중지 상태를 유지합니다. 이 패치는 학생 접속 정책, 실제 학적, 잔액, 평가 기록을 변경하지 않습니다.

## 사용 흐름

- 교사 첫 화면 제목은 현재 운영 학기입니다.
- 학습운영·일정·공휴일 동기화·출석·공지소통의 독립 메뉴와 라우트를 제거했습니다. 공지 게시판은 두 포털에서 제거했습니다.
- 학사 일정은 교사 첫 화면 달력에서 날짜 또는 기존 일정을 더블클릭하여 팝업으로 추가·수정합니다. 기존 일정의 시각·복수 학급·개별 대상은 변경하지 않는 한 보존합니다.
- 학급·학적 관리에서 학기와 할 일을 선택합니다. 이전 명부는 학생 선택 → 대상 학급 확인 → 서버 확인 → 최종 확인 후 등록합니다. JSON·UID·해시를 입력하지 않습니다.
- 학기 전환은 기본 정보 → 학기 준비 → 준비 점검 → 운영 학기 전환 순서입니다. 현재 학기와 보관 학기는 구분하며, 전환 시 학생 접속 중지를 유지합니다.

## 성능 변경

- 관리자 학생 명단: 개인별 프로필을 321회 읽은 뒤 같은 프로필을 다시 받던 경로를 제거했습니다. 신뢰된 서버의 최대 100명 단위 응답을 재사용하며 최대 4개 요청을 동시에 실행합니다.
- 수업 자료: 처음에 최근 본문 10개를 읽던 조회를 1개로 줄였습니다. 현재 학기에서 방금 받은 문서는 다시 읽지 않습니다. 삭제된 자료 탐색과 legacy fallback의 현재 학기 우선순위는 유지합니다.
- 위스: 방문한 탭의 projection만 읽습니다. 전당은 학습 등으로 실제 적립한 순위 점수가 양수인 학생만 표시하고, 동점이 많아도 각 목록은 최대 20명입니다. 초기 500위스만 받은 학생은 순위에 넣지 않습니다.
- 같은 계정·학기·세션의 진행 중인 읽기를 합칩니다. 명시적 학기 조회 일부는 메모리에서 15초만 재사용합니다. 계정·세션 변경 및 쓰기 전후에는 지웁니다. 전환 준비도·CURRENT 포인터는 방문 간 캐시하지 않습니다.
- 메뉴 hover/focus는 권한이 있는 목적지 코드만 준비합니다. 자료 조회와 쓰기를 미리 실행하지 않습니다.
- 일반 페이지 조회는 공통 중앙 spinner를 사용하며 빠른 응답은 표시를 생략합니다. 저장·PDF 처리의 차단 상태와 내부 세부 조회 표시는 구분합니다.

## 검증과 한계

명령 경계 검증은 기존 호출의 이동과 새 실제 학기 명령 5개만 검토하여 갱신했습니다. 조회 중 쓰기, 자동 학기 전환, 승인 생략, 학생 개방은 허용하지 않습니다.

실제 컴포넌트를 사용하는 네트워크 차단 합성 화면에서 달력 추가·수정과 원본 대상 보존, 명부 확인·등록 1회 반영, 새 학기 날짜 기본값·등록, 미준비 전환 차단과 모바일 가로 넘침을 확인했습니다. 운영 학생 자료를 수정하는 시험은 하지 않습니다.

표시를 빠르게 하는 변경만으로 모든 서버 응답을 즉시 완료할 수는 없습니다. 배포 후 실제 로그인 세션에서 확인하며, 이 문서의 요청 수 절감은 코드 경로 기준이고 초 단위 실측 개선율을 뜻하지 않습니다.

향후 새 학기의 자료 복사·위스 개설·백업 승인 작업은 아직 모두 웹에서 실행할 수 있는 상태가 아닙니다. 이번 화면은 실제 서버가 지원하는 기본 정보·명부·점검·전환을 연결하고, 남은 준비가 있으면 차단합니다. 준비하지 않은 학기를 완료된 것처럼 표시하지 않습니다.
