# 새로고침과 초기 화면 로딩 개선

기준 소스는 실제 `www.westory.kr`에 연결된 `c3a56b5ada5401786c5cd9f2717023f7a76ff483`이다. 기존 작업 폴더의 변경은 보존하고 별도 worktree에서 수정했다.

## 줄인 대기

- 요청한 경로의 화면 코드를 인증 확인과 함께 준비한다. 모든 페이지를 선로딩하지 않으며, 컴포넌트 mount와 자료 조회는 기존 점검·세션·역할·학기 gate 뒤에서만 시작한다. 선로딩 실패는 화면을 새로고침하지 않고 실제 진입에서 재시도한다.
- 클라이언트 점검 확인과 서버 세션 확인을 동시에 시작한다. 세션 callable 자체의 서버 점검 검사는 그대로 적용된다. 양쪽 확인에 통과해야 설정과 메뉴를 읽으며 최종 사용자 문서의 서버 확인도 유지한다. 점검 차단, 인증 실패, 타임아웃 뒤 늦게 도착한 세션 응답은 로컬 권한 증명을 복구할 수 없다.
- 교사 수업자료의 목차와 최근 자료 첫 페이지를 병렬 조회한다. 최근 자료 snapshot을 본문에 재사용하며 서버 확인 전 자료를 보여주지 않는다. 저장 결과 미확정과 복구 경로에서는 기존 순서를 지킨다. PDF 페이지가 있는 자료에만 편집 코드 준비를 앞당긴다.
- 학생 첫 화면은 일정 조회 때문에 위스 순위 등 독립 영역까지 기다리지 않는다. 일정 코드도 조회와 동시에 준비하며, 일정 실패와 재시도는 해당 영역에 표시한다. 계정·학기·반 변경 이전의 결과를 재사용하지 않는다.

## 확인 방법과 한계

`verify-initial-route-preload.mjs`, `verify-lesson-initial-load.mjs`, `verify-student-dashboard-loading.mjs --browser`, `verify-reauth-maintenance-integration.mjs`에서 실제 구현에 지연·실패를 주입해 요청 시작 순서, 실패 복구, 보호화면 차단, 계정·학기 변경을 확인한다. 빌드·타입·포맷·권한·세션·쓰기 경계 검증과 해당 커밋의 CI를 배포 전에 확인한다.

성능 진단은 기존 `?westoryPerfLogin=1`에서만 켜지며, 브라우저 console에 단계별 시간과 소요 시간을 출력한다. `westory-main-layout-ready`는 설정과 학생 공개 확인까지 끝난 시점으로 수정했다. 이전 버전의 같은 표시는 설정 준비 전 찍혔으므로 직접 비교하면 안 된다.

변경 전 교사 세션 복원 관찰에서 app-load → config-ready는 첫 방문 2,590ms, 뒤이은 새로고침 1,730ms였다. 단일 브라우저의 관찰값이며 신규 Google 로그인 시간이나 통제된 성능 비교는 아니다. 배포 후 관찰 및 파일 대조 기록은 `.vercel/initial-load-release/`에 별도로 보관한다.

서버의 보안 검사, Firestore rules, 데이터 구조, 유료 상시 대기 설정은 변경하지 않는다. 서버가 유휴 상태에서 시작하는 시간과 실제 네트워크 지연은 이번 최적화 후에도 발생할 수 있다.
