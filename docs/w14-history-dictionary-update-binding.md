# 교사 학생 단어 수정의 대상 연결 검증

후속 변경: 아래 이중 출처 ID 이동 제한은 [PATCH15 요청 출처 분리](w15-history-dictionary-request-origin.md)로 보완했습니다. PATCH14 당시의 근거와 한계는 이 문서에 보존합니다.

기존 수정 함수는 학생·단어 경로에 저장된 내용을 읽은 뒤, 명시된 학생·학기나 연결된 요청이 다른 자료를 가리키는지 확인하지 않고 뜻풀이와 이름을 바꿨습니다. 잘못된 연결 정보가 그대로 남고 교사 검토 완료로 기록될 수 있었습니다.

## 처리 기준

- 문서 경로 생성 전에 원래 UID와 단어 ID를 검사합니다. 저장된 요청 ID도 경로로 사용하기 전에 검사합니다.
- 하나의 Firestore transaction에서 원본 단어, 변경할 위치, 프로필, 연결된 요청을 읽습니다. 저장된 UID·단어 ID·단어 표현·학기의 모순을 확인한 후에만 수정합니다.
- 새 이름은 원래 이름과 달라도 됩니다. 요청 연결은 화면에서 보낸 새 이름이 아니라 서버에서 읽은 원본 단어로 검증합니다.
- 이미 이름이 바뀐 단어는 교사 검토 기록과 원래 단어 ID로 기존 요청을 확인합니다. 여러 번 이름을 바꿔도 요청 ID와 원래 보상 ID를 보존합니다. 기존 목적지 단어가 있으면 덮어쓰지 않고 충돌을 반환합니다.
- 연결된 요청이 없거나 반려됐거나 다른 학생·단어·학기에 속하면 수정 전에 거절합니다. 수정 함수는 사라진 요청을 새로 만들지 않습니다.
- 수정은 원본과 목적지 단어에만 반영합니다. 요청·보상 원장·잔액·알림에는 쓰지 않습니다.

## 기존 자료와의 호환

공식 풀이 저장과 과거 승인 자료에는 UID나 학기가 없을 수 있습니다. 명시된 정보가 서로 맞고 기존 요청으로 연결을 확인할 수 있는 자료는 허용합니다. 요청·학기·보상 메타데이터가 없는 공식 저장 자료도 편집할 수 있으며, 학기와 보상 출처는 빈 값으로 유지합니다. 호출자가 고른 학기를 근거 없이 부여해 이후 삭제가 그 학기의 원장을 찾게 하지 않습니다. 학기와 요청은 없는데 보상 메타데이터가 남은 자료는 호출자의 학기를 보상 출처로 간주하지 않도록 거절합니다.

요청 ID가 없는 직접 저장 자료와 현재 `requested` 또는 `saved` 상태를 지원합니다. 과거 역할 변경을 이유로 기존 자료 편집을 새로 제한하지 않으며, 프로필 존재와 명시 UID 일치를 확인합니다. `rewardTransactionId`는 기존 writer에 따라 원래 보상 ID와 달라질 수 있어 단독 검증 근거로 쓰지 않습니다.

이전에 이름을 바꾼 단어를 학생이 다시 요청하면 요청의 원래 단어와 보상의 원래 단어가 달라질 수 있습니다. 두 출처가 다른 자료는 같은 ID의 뜻풀이 수정은 허용하되, 요청 연결을 잃게 만드는 추가 이름 변경은 저장 전에 거절합니다. 요청 출처와 보상 출처를 별도로 보존하는 migration 전까지의 제한입니다.

## 검증과 배포

`functions/historyDictionaryUpdate.js`의 순수 검증과 실제 Auth/Functions/Firestore 에뮬레이터 검사를 함께 수행합니다. 거절 사례에서는 전체 업무 데이터가 바뀌지 않는지 확인하며, 정상 수정에서는 이름 이동과 요청·보상 메타데이터 보존을 확인합니다. 정확한 실행 결과·소스·전용 Staging 배포 및 합성 계정 HTTPS 검증은 외부 PATCH14 기록에 남깁니다.

프런트·Rules·의존성은 변경하지 않습니다. 검증을 통과한 `updateStudentHistoryDictionaryWordByTeacher`와 아래 호환성 보완이 포함된 `deleteStudentHistoryDictionaryWordByTeacher`를 전용 Staging에 배포합니다.

오래된 ID의 뜻풀이만 수정해도 현재 저장 로직은 canonical ID로 이동시킵니다. 이후 이름이 같다는 이유로 원래 요청 연결 검증을 건너뛰면 다음 수정·삭제가 막힙니다. 이름을 바꿨다가 원래 이름으로 되돌린 경우도 같습니다. 두 검증 helper에서 원래 ID 참조가 남은 경우 교사 검토 기록과 원래 보상 ID를 함께 확인하도록 보완했습니다. 모순된 참조를 무조건 허용하지 않습니다.

## 남은 한계

- 현재 ID가 같은 두 편집의 선후관계를 구분하는 서버 revision/CAS와 Gateway 결과 복구는 후속 작업입니다.
- 기존 요청·단어가 실제로 연결되지 않은 자료를 자동 복구하는 기능은 포함하지 않습니다.
- 모든 writer의 원래 보상 학기·ID·revision 출처 migration은 별도로 필요합니다. 현재 단어의 학기가 과거 보상의 학기를 증명하지 않습니다.
- 실제 Google 계정의 전체 앱 수용과 운영 사이트 배포는 별도입니다.
