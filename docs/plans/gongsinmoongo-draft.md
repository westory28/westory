학생은 자기 질문과 답변만 확인합니다. 교사는 함께 보면 도움이 될 질문을 골라, 이름과 개인 상황을 덜어 낸 별도 질문·답변을 스토리로 공개합니다. 학습자료를 보거나 평가를 복습하던 자리에서 질문하고, 답변에서 해당 자료로 돌아가는 흐름을 목표로 합니다.

## 이번 초안의 범위

- 교사 메인 사이드바의 역사 사전 바로 아래 독립 `공神문고` 메뉴(`/teacher/gongsinmoongo`)로 들어갑니다. 관리자 설정의 기존 항목은 제거합니다. 메뉴와 직접 경로 모두 `isDeveloperUser(currentUser.email)`로 관리자만 허용하며, 일반 교사·staff·학생에게 열지 않습니다. `isAdminUser`는 일반 교사 역할도 포함하므로 이 제한에 사용하지 않습니다.
- 질문 작성, 개인 대화(DM), 답변, 스토리 선정과 알림은 합성 예시를 메모리에서 조작합니다. 새로고침이나 계정·학기 변경 시 초기화되며 실제 학생 자료를 조회하거나 저장하지 않습니다.
- 실제 학생 플로팅 버튼은 위로 펼쳐지는 메뉴로 바꾸되, 현재는 역사 사전만 제공합니다. 공神문고 항목은 관리자 미리보기에서 체험합니다.
- 학생 공개는 꺼진 상태로 유지합니다. 초안 조작으로 운영 공개를 켤 수 없습니다.
- 첫 사용 안내와 학생별 질문 제한도 예시로 제공합니다. 제한은 1시간·3시간·1일·3일·7일 중 골라 적용하거나 해제하며, 실제 학생 계정에는 영향을 주지 않습니다.
- 공神문고 서버 API·저장 경로·권한 규칙·실제 접수·공개·알림 발송은 **아직 구현하지 않았습니다**. 아래 저장 경로·서버 권한·호출량은 다음 구현을 위한 제안입니다.
- 공神문고 초안은 외부 AI·외부 API를 호출하지 않습니다. 기존 앱의 로그인·공통 설정 조회까지 없어지는 것은 아닙니다.

학생 화면은 공개 게시판을 두지 않습니다. 개인 DM에는 본인이 보낸 질문과 교사의 개별 답변만 나타나며, 다른 학생의 이름·질문 목록·질문 건수는 제공하지 않습니다. 선정 스토리는 인스타그램 질문 스토리처럼 질문 카드와 답변을 한 장씩 보여 줍니다. 자동 넘김이나 24시간 자동 삭제는 적용하지 않고, 이전·다음 버튼과 진행 표시를 제공합니다.

교사 질문 목록은 기존 `PortalSubNavigation`의 세로 대상 탐색으로 제공합니다. 필터와 목록을 그 안에 두고 본문에는 선택한 질문만 열어 행이 계속 늘어나지 않게 합니다. 제목·탭·필터만을 위한 카드는 추가하지 않습니다. 모바일은 기존 접이식 목록을 사용하며 키보드·터치·긴 한글·확대 상태에서도 주요 행동을 유지합니다. 안내가 필요한 항목은 기존 동그라미 `i` 도움말을 사용합니다.

PC에서는 계정 헤더와 푸터를 포함해 한 화면에 맞춥니다. 질문 목록은 화면 높이에 맞춘 페이지로 나누고, 개인 답변과 공개용 편집은 같은 자리를 전환합니다. 학생 미리보기는 외곽 카드 없이 가용 가로 폭을 쓰며 대화 목록만 내부 스크롤합니다. 학습 도구 버튼은 작성란 오른쪽 별도 영역으로 옮깁니다. 모바일에서는 자연스러운 세로 배치와 접이식 질문 목록을 유지합니다.

운영 설정을 `site_settings`에 둘 수 있는지와 별개로, 질문·개인 답변·공개 전 편집본은 그 아래 저장하지 않습니다. 기존 규칙상 승인 로그인 사용자도 `site_settings`를 읽을 수 있습니다.

## 권한과 운영 제어

현재의 관리자 미리보기는 관리자 이메일 판정을 재사용합니다. 실제 운영에서는 서버가 검증한 관리자에게만 전체 운영과 공개 설정 변경을 허용하고, 일반 교사와 보조 권한 사용자의 질문 열람 범위는 담당 학기·학급을 명시적으로 배정한 뒤 적용합니다. 기존 `lesson_read`나 `quiz_read`만으로 학생 개인 질문을 읽게 하지 않습니다.

- 학생 목록 조회는 서버에서 현재 학기와 `ownerUid == request.auth.uid`로 제한합니다. 다른 학생의 ID를 알아도 상세 조회·목록·추측 조회를 차단합니다.
- 쓰기는 서버 명령으로 처리하고, 클라이언트가 보낸 작성자 UID·교사 역할·학기·상태·공개 여부를 신뢰하지 않습니다. 질문 수정·삭제 허용 범위도 서버에서 검사합니다.
- 공개 스토리는 운영·스토리 공개 설정, 공개 상태, 대상 학급을 모두 검사합니다. URL 직접 진입과 실시간 구독도 같은 조건을 따릅니다.
- `enabled=false`는 전체 비상 차단입니다. `acceptingQuestions=false`는 새 접수만 중단하고, `storiesPublished=false`는 공개 스토리만 닫습니다. 전체 운영이 꺼져 있으면 나머지 값과 관계없이 학생 화면·읽기·쓰기 모두 닫습니다. 교사의 비공개 관리와 학생 공개는 구분합니다.
- 공개 철회는 이미 열린 화면에서도 반영합니다. 서버 확인된 설정 구독에서 변경을 받으면 화면의 본문·링크·캐시를 비우고 관련 구독을 종료합니다. 설정 확인 실패도 열림 상태를 유지하지 않습니다. 서버 규칙과 명령 검사를 UI 숨김으로 대신하지 않습니다.
- 공개 스토리 게시는 관리자가 운영을 연 범위 안에서 지정 교사가 마지막 미리보기를 확인한 뒤 명시적으로 실행합니다. 답변 저장이나 선정만으로 공개되지 않습니다. 비공개 전환도 별도 행동으로 제공합니다.

학기 경로는 `getSemesterCollectionPath` / `getSemesterDocPath`로 만듭니다. 신규 공神문고는 전역 legacy 경로를 만들지 않습니다. 계정·학기·담당 권한이 바뀌면 목록, 상세, 작성 중 문맥, 페이지 커서와 요청 결과를 폐기하고 새 범위에서 확인합니다. 비동기 응답도 시작 당시 범위와 현재 범위가 같을 때만 반영합니다. 민감한 초안을 공용 localStorage에 저장하지 않습니다.

## 학습자료·평가 연결

질문에는 `source: { kind, year, semester, unitId, lessonId?, category?, round?, questionId?, pageIndex?, anchorId? }` 형태의 최소 참조를 붙입니다. 점수·답안·문항 정답은 복사하지 않습니다. 페이지 번호는 표시용 값과 내부 인덱스를 구분합니다. 사용자가 제목이나 URL만 바꿔 타인의 자료를 읽게 할 수 없도록 서버에서 실제 대상과 접근 권한을 다시 확인합니다.

| 맥락 | 현재 연결 근거 | 적용 방향 |
| --- | --- | --- |
| 수업자료 | `/student/lesson/note?id={unitId}&title={title}` | 자료를 읽던 단원과 실제 lesson ID를 연결. 자료를 열 때 공개 여부를 재확인. 페이지·각주 직접 이동은 추가 구현 전까지 지원 완료로 표시하지 않음 |
| 진단평가 | `/student/quiz/run?unitId={unitId}&category=diagnostic` | 제출 완료한 본인 복습 화면에서 문항 ID를 붙여 질문. 응시 중 정답 도움 요청 경로는 열지 않음 |
| 형성평가 | `/student/quiz/run?unitId={unitId}&category=formative` | 제출 완료한 본인 복습 화면에서 연결. 문항 ID와 시험지 표시 순서인 `paperOrder`를 구분 |
| 모의고사 | `category=exam_prep`, `unitId=exam_prep`, `round=round_N` | 일반 질문의 자료 선택 목록에서 제외. 제출 완료한 본인 오답 노트의 해당 문항에서만 질문을 시작하고 회차·문항 ID를 보존 |
| 결과 복습 | `/student/mypage?menu=wrong_note&attemptId={resultId}` | 본인 결과의 복습 화면으로 이동. 기존 `reviewLessonId` 연결을 이용해 관련 수업자료로 돌아감 |
| 역사 사전 | `/student/lesson/history-dictionary` | 공개 용어 안내와 사전 진입을 연결. `termId`·검색어 직접 이동은 현재 미지원. 개인 단어장 기록을 공개본으로 복사하지 않음 |

평가 링크를 누르는 것만으로 새 응시를 시작하지 않습니다. 현재 `QuizIndex.startQuiz`는 `state.startAssessment=true`를 보내므로 관련 자료 이동에 그대로 쓰지 않습니다. 공개된 평가 목록·내 결과·복습으로 먼저 연결하고, 응시 시작은 학생의 별도 행동으로 둡니다. 현재 특정 `questionId`나 PDF 페이지로 바로 이동하는 링크는 지원하지 않으므로, 초안에서 특정 문항·페이지에 도착했다고 표시하지 않습니다. 이후 별도 구현·검증한 뒤 제공합니다.

초안은 모의고사를 일반 선택지에서 빼고, 합성 오답 노트의 `이 문항 질문하기`에서만 `origin: "wrong-note"`를 붙입니다. 부모 입력 처리도 모의고사에 이 출처가 없으면 거부합니다. 이 값은 초안 흐름을 구분하는 표시이며 실제 보안 증명이 아닙니다. 실제 구현에서는 서버가 로그인 UID·학기·본인 제출 완료 기록·회차·문항 포함 여부를 확인해야 합니다. URL이나 요청 본문의 `origin`을 바꿔도 임의 모의고사 질문을 접수할 수 없어야 합니다.

수업자료에는 학기 자료와 전역 legacy fallback이 남아 있습니다. 연결 시 기존 자료 조회·공개 검증을 재사용하며, 공神문고가 원문을 복사해 기존 비공개를 우회하지 않습니다. 평가 목록은 `assessmentConfig.active`와 `visibleClassIds`, 실제 응시는 서버 `assessmentLifecycle.js`의 세션·학기·본인 응시·활성 학적·학급/학생 배정·공개·선행 회차 검사를 따릅니다. 응시용 presentation은 `answer`·`explanation`·`matchingPairs`를 제외하며, 원본 `quiz_questions`를 학생이 직접 읽지 못하는 경계도 유지합니다.

현재 결과 복습은 본인의 `SUBMITTED` 기록을 확인하는 별도 분기이며, 결과 공개를 위한 독립 플래그는 확인되지 않았습니다. 공神문고도 이 본인·제출 완료 검사를 재사용합니다. 다른 학생도 읽는 스토리에 문항·해설을 내보내는 조건은 별도로 구현해야 합니다. 본인이 복습할 수 있다는 이유만으로 해당 정답을 전체 공개하지 않으며, 필요하다면 평가 진행 기간과 대상별 스토리 노출 제한을 추가합니다. 공개 스토리와 연결 자료의 공개 범위가 다르면 자료 링크를 제공하지 않고, 답변 본문 자체에 미공개 문항·정답이 드러나지 않는지 게시 전에 검토합니다.

## 질문·답변 알림

초안에서 학생이 질문하면 `question_created` 교사 알림이 생기고, 교사가 개별 답변을 저장하면 `question_replied` 학생 알림이 생깁니다. 교사 알림은 해당 질문, 학생 알림은 본인의 해당 대화로 이동합니다. 미리보기 알림함에서만 읽음 상태를 바꾸며 기존 헤더 알림·서버 알림함·외부 푸시에 연결하지 않습니다. 공개 스토리 편집만으로 개인 답변 알림을 만들지 않고, 내용이 같은 답변을 다시 저장해 중복 알림을 만들지 않습니다.

실제 알림 연결은 후속 서버 작업입니다. 질문 생성·답변 변경과 outbox 이벤트를 원자적으로 기록하고, 별도 전달 작업이 수신자별 inbox를 갱신하도록 합니다. 새 질문은 그 학기·학급의 지정 담당 교사에게만, 답변은 질문 작성 학생에게만 보냅니다. 모든 교사·전체 학생을 조회하거나 broadcast로 보내지 않습니다. 수신자는 클라이언트 입력이 아니라 서버 권한·담당 배정에서 결정합니다.

이벤트 ID는 질문·답변 버전과 명령 영수증에 연결하고, inbox 문서 ID도 이벤트 ID와 수신자 UID로 결정하여 재시도에 같은 문서를 사용합니다. 동일 명령·중복 트리거에서 이벤트·알림이 늘어나지 않아야 합니다. 발송 실패는 outbox에 남겨 재시도하고 본문 저장 성공과 알림 전달 상태를 구분합니다. 권한 회수·학기 전환·운영 중지 후에는 알림을 눌러도 옛 본문을 노출하지 않습니다. 알림 미리보기·로그에는 질문 원문·개인 답안·점수를 복사하지 않습니다.

## 첫 사용 안내와 질문 제한

학생이 처음 질문 기능을 사용할 때 학습 관련 질문만 보내기, 사담·욕설·반복 전송 금지, 반복 시 일정 기간 질문 제한을 안내합니다. 명시적으로 확인하기 전에는 전송할 수 없습니다. 팝업을 닫거나 Escape를 눌렀다고 확인 처리하지 않습니다. 초안에서는 확인 상태를 화면 메모리에만 두며 새로고침·계정·학기 변경 시 초기화합니다.

교사는 질문 상세에서 학생을 확인하고 기간과 사유를 정해 질문 작성을 제한합니다. 제한은 질문 한 건이 아닌 해당 학생에게 적용하며, 같은 학생의 다른 질문에서도 동일하게 표시합니다. 제한 중에도 기존 질문·교사 답변·선정 스토리와 수업자료는 읽을 수 있습니다. 학생에게는 본인의 사유와 해제 시각을 표시하고, 다른 학생의 제한 여부나 사유를 공개하지 않습니다. 미전송 글은 보존하고, 기간 만료 또는 교사의 명시적 해제 후 다시 보낼 수 있습니다. 별도의 자동 탐지나 AI 제재는 도입하지 않습니다.

실제 운영에서는 서버가 현재 시각·제한 버전·안내 확인 버전을 매 질문 명령에서 검사해야 합니다. 브라우저 시간을 바꾸거나 화면의 버튼을 조작해 제한을 우회할 수 없어야 합니다. 제한 설정·연장·해제는 배정된 담당자 또는 관리자만 명시적으로 수행하며 대상 학생·기간·사유·실행자·변경 전후 버전을 최소 감사 기록으로 남깁니다. 학생 동시 전송과 제한 적용이 겹치면 같은 서버 트랜잭션에서 현재 상태를 판정합니다. 기존 요청 영수증 재조회는 새 질문 생성과 구분합니다.

실제 안내 확인은 현재 안내 버전과 서버 시각을 저장하고 새 안내가 필요한 경우 버전을 갱신합니다. 제한 만료는 서버 시각을 기준으로 판단하며 잦은 폴링이나 매분 쓰기를 만들지 않습니다. 학생 화면은 제한 변경을 권한 있는 상태 구독으로 반영하고, 새 전송도 항상 서버에서 확인합니다. 안내 확인·제한 문서의 보유 기간과 삭제 범위는 아래 운영 조건과 함께 확정합니다.

## 조회·저장과 복구

초안의 공神문고 전용 서버 조회와 쓰기는 0회입니다. 실제 구현의 초기 요청 예산은 아래와 같이 정하고, 에뮬레이터와 서버 계측으로 성공·오류·재시도별 횟수를 확인합니다. 표의 숫자는 사업자 청구 건수의 확정값이 아닙니다. 권한 검사의 종속 문서 읽기, 인덱스·집계 과금, 트랜잭션 재실행 등은 별도로 기록합니다.

| 작업 | 제안 요청·문서 작업 | 확인 조건 |
| --- | --- | --- |
| 접힌 플로팅 메뉴 | 기존 설정 상태 재사용 또는 운영 설정 구독 1개; 질문·스토리 목록 조회 0 | 메뉴 렌더링마다 조회하지 않음. 운영 차단을 캐시만으로 판단하지 않음 |
| 내 질문 목록 | 현재 학기·본인 필터, 정렬, 커서, 페이지 크기 20의 목록 요청 1회 | 반환 문서 0~20개. 다음 페이지가 있음을 표시하고 임의 limit로 전체 건수를 추정하지 않음 |
| 공개 스토리 | 현재 학기·대상·공개 상태 필터, 커서로 10개씩 요청 | 비활성 탭은 조회하지 않음. 공개 목록에 개인 필드가 애초에 없음 |
| 질문 상세 | 선택 문서 1개 조회 | 목록 projection에 없는 본문만 필요할 때 조회. 본인·담당자 검사 유지 |
| 교사 건수 | 현재 필터의 서버 count 집계 요청 1회 | 조회 성공 후에만 건수 표시. 전체 문서를 내려받아 세지 않음 |
| 새 질문 | 단일 명령; 질문 1개, 영수증 1개, 필수 감사 1개, outbox 1개 쓰기 목표 | 인증·운영·범위·영수증 읽기는 별도 계측. 중복 재시도는 새 질문·감사·이벤트 생성 0회 |
| 답변 저장 | 변경된 개인 질문 1개와 필수 영수증·감사·outbox 쓰기 | 변경 없는 저장은 명령 0회. 실패 시 입력을 보존하고 명시적 재시도 |
| 알림 전달 | 해당 이벤트 1개와 지정 수신자 확인, 수신자별 inbox 1개 및 전달 상태 갱신 | 전체 사용자 조회 0회. 재시도 시 같은 알림 ID 사용. 실제 읽기·쓰기 수는 담당 배정 저장 구조에 맞춰 계측 |
| 스토리 게시·회수 | 편집본·공개본·영수증·감사를 하나의 명령으로 원자적으로 반영 | 학생 식별 필드 0개. 동일 명령 재실행으로 게시·알림 중복 생성 0회 |

필드 projection은 전송량을 줄일 뿐 Firestore 문서 읽기 건수를 줄이는 것으로 보고하지 않습니다. 개수는 집계, 상세는 지정 ID, 목록은 필터·커서를 사용합니다. 전체 분석이 필요한 경우 모든 페이지를 완전하게 집계하고 임의 limit로 누락시키지 않습니다. 실제 호출량과 읽기·쓰기량을 구분해 기록합니다.

질문 전송 전에 클라이언트가 요청 ID를 한 번 만들고 재시도에도 같은 ID를 사용합니다. 서버는 UID·학기·요청 ID를 묶은 영수증과 입력 해시를 트랜잭션으로 확인합니다. 같은 요청이면 기존 결과를 돌려주고, 같은 ID에 다른 본문이면 충돌로 거부합니다. 응답 유실 뒤 재시도에서도 질문·알림·감사를 중복 생성하지 않습니다. 전송 중 버튼은 잠그되 오류 시 질문은 지우지 않습니다. 계정·학기가 바뀐 뒤 이전 초안을 자동 제출하지 않습니다.

실제 읽기 캐시를 추가한다면 키에 UID·학기·권한 버전·조회 조건·커서를 포함하고, 저장·공개 변경·권한 변경·로그아웃·오류 때 무효화합니다. 숨긴 탭의 폴링과 중복 요청은 없애되, 공개 철회 확인과 필수 영수증·감사 기록은 유지합니다.

## 실제 접수 전에 완료할 검증

1. 학생 A의 질문 상세 ID·목록·변조 UID·다른 학기 조회를 학생 B가 모두 읽거나 수정할 수 없어야 합니다. 담당 범위 밖 교사와 단순 열람 권한 사용자의 접근도 거부합니다.
2. 학생은 자신의 질문·답변과 게시된 익명 스토리만 읽습니다. 공개 문서·네트워크 응답·URL·로그에 원문 ID, 작성자 정보, 개인 점수·답안이 없어야 합니다.
3. 미설정, 공개 꺼짐, 접수만 중단, 스토리만 비공개, 설정 오류, 직접 URL 진입과 열린 화면의 공개 철회를 각각 검사합니다. 관리자만 운영을 변경할 수 있어야 합니다.
4. 질문 전송·답변 저장·게시·알림 전달의 성공, 오류, 응답 유실 후 재시도를 검사하고 실제 조회·쓰기·알림 횟수를 기록합니다. 두 번 클릭하거나 트리거가 재실행되어도 질문·게시·알림이 중복되지 않아야 합니다. 알림 수신자·클릭 대상·읽음 처리도 본인 또는 지정 담당자 범위로 제한합니다.
5. 자료 비공개·삭제·학기 전환, 타인 평가 결과·미제출 결과·응시 중 질문 진입을 차단합니다. 일반 선택지에 모의고사가 없고, 위조한 `origin`·회차·문항 ID로 우회할 수 없어야 합니다. 새로 도입할 공개 스토리의 문항·해설 노출 조건도 따로 검사합니다. 링크 이동이 응시를 자동 시작하거나 답안을 변경하지 않아야 합니다.
6. 390px·768px·1280px 화면과 키보드·터치에서 플로팅 메뉴, 스토리 넘김, 질문·답변 입력, 긴 문구, 빈 화면·오류·재시도를 확인합니다. 초안의 버튼은 운영 쓰기를 일으키지 않아야 합니다.
7. 실제 서버 구현 후 `npm run build`, 관련 Functions 검사, 공神문고 전용 rules 에뮬레이터 검사를 통과해야 합니다. 공통 권한·세션·rules 영향이 있으면 `npm run test:score-request-rules`도 유지합니다.
8. 안내 확인 전·취소 후 전송, 다른 학생의 안내 확인 대입, 제한 중 전송·위조 시각·기간 만료·명시적 해제·제한과 전송의 동시 요청을 검사합니다. 제한 중 기존 대화와 학습자료 읽기는 유지하고 다른 학생에게 제재가 번지지 않아야 합니다. 화면 입력 보존과 서버 거부 시 복구도 확인합니다.

## 아직 정하지 않은 운영 조건

개인 질문·개인 답변·공개 스토리·영수증·감사의 보유 기간, 학생 삭제 요청과 공개본 회수의 관계, 전학·탈퇴·학기 보관 시 삭제 범위, 백업에서의 파기 절차는 확정하지 않았습니다. 이를 정한 뒤 기존 삭제·학기 보관 작업에 공神문고 경로를 포함해야 합니다. 공개 철회는 즉시 읽기를 차단하고 실제 삭제·백업 만료와 구분합니다.

실제 학생 질문 수집은 개인정보 항목과 공개 범위를 추가하므로 기존 고지·처리 근거와 승인 범위를 확인해야 합니다. [보안성 검토 준비 문서](../runbooks/security-review.md)에 따라 담당부서의 대상·재검토 판단과 필요한 조건을 확인한 뒤 실제 접수를 엽니다. 현재 상태를 승인·면제·위법으로 단정하지 않습니다. 이번 초안은 실제 학생 정보를 수집하지 않으며 기관 제출이나 공문 발송을 포함하지 않습니다.

답변은 교사가 직접 작성합니다. 향후 AI 답변을 도입한다면 이번 초안과 별도 변경으로 취급하고 [AI·에이전트 기준](../runbooks/responsible-ai.md)을 먼저 적용합니다.
