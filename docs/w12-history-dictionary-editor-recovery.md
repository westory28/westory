# 역사사전 편집 초안과 계정 경계 보호

교사가 역사사전의 단어·학생 요청·학생 등록 단어를 편집하는 동안 목록을 다시 받으면 편집란을 다시 채워 입력을 잃을 수 있었습니다. 선택 요청이 닫히거나 목록에서 사라질 때 다른 학생의 요청을 자동으로 선택하는 경로도 있었습니다. 이번 작업은 서버의 DIC01 Gateway 이전과 분리한 화면 복구 보완입니다.

## 편집 기준

- 같은 항목의 동일한 목록 갱신은 입력을 초기화하지 않습니다. 단어·풀이·관련 단원·태그·아직 추가하지 않은 태그 입력을 함께 관리합니다.
- 편집하지 않은 항목은 최신 내용을 반영합니다. 편집 중 원본 내용이 바뀌면 초안을 보존하고 변경 작업을 잠급니다. 최신 내용을 다시 불러오는 명시적 행동에서 입력을 버릴지 확인합니다.
- 선택 항목을 목록에서 확인할 수 없으면 다른 항목을 자동으로 선택하지 않습니다. 조회 실패나 목록 제한도 있을 수 있으므로 이를 확정 삭제로 단정하지 않습니다.
- 계정·학기·읽기/쓰기 권한이 바뀌면 화면 상태를 분리합니다. 이전 계정의 자료나 입력을 새 계정에 남기지 않고, 이전 조회·저장 응답이 새 화면을 초기화하지 않게 합니다.
- 명시적 항목·탭 전환과 자동 목록 갱신을 구분합니다. 저장 중 중복 실행과 편집 대상 변경을 막으며 결과는 해당 화면의 요청에만 표시합니다.
- 저장·삭제 응답이 늦게 도착한 동안 같은 ID의 학생 단어나 요청 연결이 바뀌면 최신 목록을 덮거나 숨기지 않습니다. 초안과 최신 내용 재조회 경로를 남깁니다. 학생 단어 수정 직후 화면 반영과 실제 서버 재조회도 구분합니다.

학생 등록 단어의 기존 서버 수정 범위는 단어와 풀이입니다. 관련 단원·태그·아직 추가하지 않은 태그 입력은 미저장 입력으로 보존하며 서버에 저장했다고 표시하지 않습니다.

## 저장 요청의 계정과 내용

교사 전용 단건 저장·승인·학생 단어 수정·삭제 helper는 호출한 계정을 검사하고 `getHttpsCallable`의 `expectedUid`에 고정합니다. 인증·세션 준비 중 계정이 바뀌면 전송을 거절합니다. 학기와 입력 payload는 비동기 준비 전에 복사하며 태그 배열도 별도로 복사합니다. 학생용 저장 helper나 서버 API의 입력 계약은 바꾸지 않습니다.

## 검증과 한계

`scripts/verify-history-dictionary-editor-identity.mjs`는 실제 helper와 실제 callable factory를 실행하고 SDK·세션·재인증 I/O를 제어해 계정 변경 시 전송 거절과 원래 입력 보존을 확인합니다. `scripts/verify-history-dictionary-editor-recovery.mjs`는 실제 교사 화면과 합성 데이터 I/O를 사용하는 로컬 브라우저 검증입니다. 고정 이전 소스로 입력 유실을 재현하고 수정 후 화면의 갱신·선택·저장·계정 경계를 확인합니다. 정확한 검사 결과와 배포 소스는 외부 인수인계에 기록합니다.

목록에서 확인한 변경을 막는 것은 서버 CAS 보장이 아닙니다. 아직 도착하지 않은 원격 수정과 저장이 경합할 수 있습니다. DIC01 Gateway·receipt·revision/CAS, 전역 단어/학생 단어장/알림의 분리 transaction, 서버 알림 실패 복구, 교사 삭제의 요청 결합 보안은 별도 후속 작업입니다. 브라우저를 닫거나 새로고침한 뒤 초안을 복구하는 영구 저장도 이번 범위가 아닙니다.

교사 수업 제시 화면·판서 제거, 왼쪽 메뉴, 학생 빈칸·저장·효과·핵심포인트·보상·각주·링크는 유지합니다. 보안 규칙·Functions·의존성은 변경하지 않고, 검증된 프런트만 전용 Staging에 반영합니다.
