# 알림장 팝업 운영 반영 기록

- 운영 기준: `dfa0ca5` 및 이후 main 변경을 병합한 별도 작업 브랜치.
- 복원 근거: `d360227` (2026-09-15, Unify school banner management in a compact dialog).
- 원인: 최신 배너 UI가 phase6 분기에 남아 있고 운영은 `TeacherNoticeBoard → NoticeModal`을 사용했다.
- 적용: 운영 알림장에 목록 3개씩 보기, 등록·수정·삭제·순서 편집, 크게 미리보기를 단일 팝업으로 통합했다. 분류·대상을 선택 상자로 정리하고 날짜와 이미지 편집을 컴팩트하게 배치했다.
- 보존: 기존 Firestore/Storage 저장 경로, 학생 표시 데이터, 개발자 일지 연결, 이미지 압축, 최근 헤더·달력 변경. phase6 전용 callable 및 전체 Dashboard는 이식하지 않았다.

## 검증

- `npm run build`, 변경한 TSX의 Prettier 검사 및 `git diff --check` 통과.
- 전체 TypeScript 검사: 기존 HEAD 64건, 변경 후 64건으로 신규 오류 0건. 전체 타입 검사가 통과한 상태는 아니다.
- 실제 브라우저의 격리된 React 컴포넌트 검증: 390×844, 768×1024, 1280×960. 저장은 mock으로 확인해 운영 데이터를 생성하지 않았다.
- 확인: 분류·반 선택, 편집 값의 미리보기 왕복 보존, 기존 content/이미지/연동 게시물 및 학급 대상 저장, 저장 중 입력·닫기 잠금, 실패 후 입력 보존, 이미지 없는 등록 차단, 순서 저장, 저장 중/후 키보드 포커스와 역방향 Tab.
- 개발용 검증 파일은 `tmp/notice-qa`에만 두고 배포 커밋에 포함하지 않는다.

## 후속 병합 시 주의

- 회사/집의 오래된 작업 폴더를 그대로 운영에 덮어쓰지 않고 최신 `origin/main`을 기준으로 별도 브랜치에서 변경 파일을 비교한다.
- `3b56b7e` 등 학기 분기의 `assertTeacherSemesterWritable()` 또는 새로 도입되는 보기 전용 보호는 제거하지 않는다. 이번 변경은 해당 권한·학기 모듈을 수정하지 않는다.
- 다른 패치 배포가 먼저 완료되면 다시 fetch/merge 후 검증하고 fast-forward push만 수행한다. 강제 push는 사용하지 않는다.
