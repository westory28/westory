# 개인 패치 메모의 오래된 목록 조회

2026-09-11. 기존 최신 100건의 클라이언트 필터만으로는 오래된 미처리 메모에 접근할 수 없었다. 이번 변경은 본인 메모를 100건씩 조회하고 최신 목록·이전 쪽·오래된 메모로 이동하도록 한다.

- 기존 `updatedAt DESC`와 문서 이름의 동일 정렬, `limit(100)`을 유지한다. 원본 QueryDocumentSnapshot을 커서로 사용하여 같은 시각의 메모도 이어서 조회한다. 화면의 상태별 재정렬 결과는 커서로 사용하지 않는다.
- 커서는 소유자와 컬렉션 경로를 확인한다. 계정 변경 시 패널과 커서·초안은 함께 분리된다. Firestore Rules, 인덱스, Functions, 의존성은 변경하지 않는다.
- 페이지 이동과 조회 실패에도 편집 초안과 저장 기준 리비전을 유지한다. 이전 구독의 늦은 결과는 폐기하고, 로딩 중 중복 이동을 차단한다. 오류 후 같은 쪽을 다시 불러오거나 이전·최신 목록으로 돌아갈 수 있다.
- 건수와 미처리·전체·완료 필터는 현재 쪽 기준이라고 표시한다. 전체 미처리 건수로 오인하지 않는다. 정확히 100건인 마지막 쪽에서는 다음 쪽이 비어 있을 수 있으며 이전·최신 목록으로 돌아갈 수 있다.
- 실시간 수정으로 메모가 최신 정렬 위치로 이동할 수 있다. 여러 쪽을 하나의 원자적 시점으로 고정하는 조회는 아니다. 최신 목록으로 돌아가 최근 변경을 확인할 수 있다.

검증은 기존 `verify-teacher-patch-memo-recovery.mjs`와 `verify-teacher-patch-notes-rules.mjs`에 추가했다. 패키지 스크립트와 잠금 파일은 유지한다.

- 실제 컴포넌트 격리 브라우저: 98개 통과. 390·768·1280·1440px, 페이지 오류 0, 가로 넘침 0. 페이지 이동 중 초안, 늦은 구독 응답, 실패·재시도, 이전·최신 이동 포함. 확인 대화상자 처리를 기다리도록 검증의 비동기 타이밍도 명확히 했다.
- 양쪽 Rules와 실제 클라이언트 helper: 207개 메모를 3쪽으로 조회하여 가장 오래된 미처리 메모 확인. 시각 동률·삭제된 커서·소유자 불일치·100건 초과 제한을 검사했다.
- 전용 Staging에는 개인 메모 합성 데이터 205건으로 같은 쿼리를 검증한다. 실제 Google 관리자 메모는 검증 목적으로 수정하지 않는다. 최종 결과와 배포 정보는 외부 야간 인수인계에 기록한다.

초안의 새로고침·탭 종료 복구, 상태별 전체 건수 집계, 실제 관리자 화면 조작 확인은 이번 조회 개선의 완료 범위에 포함하지 않는다. 기존 서버 Gateway·CAS·receipt와 학생·교사 기능은 유지한다.
