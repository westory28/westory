# 역사사전 Excel 일괄 등록의 Gateway 이전

Excel에서 확인한 단어 목록을 저장한 뒤 응답이 끊기면, 종전에는 이미 등록된 단어라는 오류가 나면서 원래 등록 결과를 확인할 수 없었습니다. 일괄 등록 DIC02를 명령 ID와 receipt를 사용하는 Gateway로 이전합니다. 단건 등록·수정 DIC01과 학생 요청 승인·알림은 이번 범위에 포함하지 않습니다.

## 저장 계약

- 최대 200행을 하나의 transaction으로 처리합니다. 입력 오류나 기존 단어가 하나라도 있으면 단어·receipt·audit 전체 쓰기를 취소합니다. 내부에서 여러 요청으로 나누거나 일부 행만 저장하지 않습니다.
- 기존 전역 `history_dictionary_terms/term_{SHA1(normalizedWord)}` 경로, 공백·소문자 정규화, 학생 공개 필드와 생성자·수정자·시각을 유지합니다. 이미 존재하는 단어는 덮어쓰지 않습니다.
- payload의 year/semester는 요청 문맥으로 고정합니다. 기존 일괄 등록은 전역 사전을 쓰므로 새 활성 학기·수강·반 조건을 추가하지 않습니다. 학기별 학생 요청·단어장·포인트 fanout도 추가하지 않습니다.
- 교사와 최고 관리자만 일반 애플리케이션 세션으로 등록합니다. 학생·직원·권한 없는 사용자는 서버에서 거절합니다. 클라이언트의 낮은 위험 분류와 서버 GENERAL 설정을 함께 적용합니다.
- 허용된 payload 필드와 정규화 후 길이·중복을 검사합니다. 기존처럼 초과 내용을 서버에서 잘라 저장하지 않고 전체 거절합니다. 전역 Gateway의 750,000바이트 상한은 유지하며 클라이언트에서도 큰 요청을 전송 전에 안내합니다. 200행 이내라도 한글 설명과 태그가 길면 상한에 걸릴 수 있습니다.
- 같은 사용자·명령·ID의 receipt를 먼저 확인하고 동일 payload이면 결과만 재생합니다. 다른 ID의 겹치는 목록은 전체 거절합니다. 성공 뒤 다른 교사가 해당 단어를 편집해도 원래 등록의 재시도로 다시 덮어쓰지 않습니다.
- 기존 직접 callable `saveHistoryDictionaryTermsBulk`는 `LEGACY_DICTIONARY_IMPORT_RETIRED`로 쓰기를 거절합니다. 이전 테스트 번들 사용자는 최신 테스트 주소를 새로 열어야 합니다. Firestore의 직접 쓰기 거절 규칙은 유지합니다.

## 교사 화면

일괄 등록의 파일·행·사용자·학기를 현재 업로드 세션에 고정합니다. 결과가 불명확하면 미리보기를 유지하고 `등록 결과 다시 확인`을 제공합니다. 이때 파일 교체와 미리보기 비우기는 잠깁니다. 새 목록에서 같은 단어가 나타나도 원래 결과 재확인을 차단하지 않습니다. 성공과 서버가 확정한 충돌만 pending 작업을 해제합니다. 세션·권한 거절은 이전 요청의 실패를 확정하지 않습니다.

충돌이나 검증 실패를 일부 저장이라고 안내하지 않습니다. 성공 후 목록 조회만 실패했다면 등록 완료와 조회 실패를 구분합니다. 파일 분석·등록·후속 조회 중 사용자·학기·권한이 바뀌면 이전 결과와 알림을 현재 업로드 화면에 적용하지 않습니다.

새로고침·화면 종료 뒤에는 같은 계정·학기에서 원본 Excel을 다시 올리면 기존 Gateway의 프로젝트·사용자·명령·payload hash가 일치하는 미확정 요청을 찾아 결과 재확인을 제공합니다. 다른 내용이나 다른 계정·학기의 일반 중복 검사는 유지합니다. 파일·업로드 원문은 새 브라우저 저장소에 남기지 않으며 미리보기를 자동 복원하지 않습니다. 기존 명령 메타데이터를 지운 경우에는 이 재확인 경로를 사용할 수 없습니다.

## 검증

- 서버 adapter와 실제 Gateway core의 합성 transaction 검사, 이전 endpoint 쓰기 차단 검사.
- 실제 helper·Gateway와 Auth/Firestore/Functions 에뮬레이터를 연결한 동시 transaction, 응답 유실·ID 재시도, 200행·바이트 제한, 권한·session·직접 쓰기 차단. 모듈 재생성과 원래 ID 유지도 확인합니다.
- 실제 관리 컴포넌트와 합성 workbook/parser·전송 응답으로 여러 화면 폭의 미리보기 유지, 결과 재확인, 실시간 중복, 충돌 후 복구, 계정·학기·권한 변경, 늦은 파일 분석·목록 조회를 확인합니다. 이는 실제 XLSX 디코더 검증을 대신하지 않습니다.
- 실행 건수, 실패 수정 기록, 정확한 소스와 Staging 배포·실제 서버 검증은 외부 인수인계에 남깁니다. 사용자 Google 로그인과 전체 앱 수용을 완료했다고 확대하지 않습니다.

Production은 접근하거나 변경하지 않습니다. DIC01의 revision/CAS와 학생 요청 배포·알림 멱등성, 다른 미이전 callable, 공식 성적 XLSX 정책 및 기존 운영 출시 조건은 남아 있습니다.
